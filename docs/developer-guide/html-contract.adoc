= HTML出力の仕様

この文書では、生成HTMLの構造、出力規則および安全性を保証する範囲を定義します。CLIの操作方法は
xref:../user-guide/command-line.adoc[コマンドライン]、参照先やresourceの解決結果を渡す方法は
xref:server-execution.adoc#render-inputs[変換入力]を参照してください。

HTML出力はパッケージバージョンの一部であり、独立した仕様バージョンを持ちません。異なるパッケージバージョン間で
DOM構造、属性順、空白またはbyte列が同一であることは保証しません。

== 文書モード

``Fragment``は本文要素だけを出力する既定のモードです。``Complete``は文書型、言語未確定の``html``、
UTF-8 encodingと非空タイトルを持つ``head``および``body``を常に出力します。Stylesheetは同じ``head``へ
追加します。

[source,html]
----
<!doctype html>
<html lang="">
<head>
<meta charset="utf-8">
<title>AdocWeave document</title>
</head>
<body>
...
</body>
</html>
----

== スタイルシート

``RenderPolicy.stylesheets``は利用側アプリまたはCLIが明示的に渡す設定であり、文書入力からCSSへ到達する
経路はありません。埋め込みCSSと外部stylesheet URLを``Complete``の``head``へ指定順に出力し、同じ内容は
最初の一件だけを採用します。``Fragment``では出力せず、診断を返します。

埋め込みCSSでは、``style``要素を終了できる文字列、HTML comment開始文字列および不正な制御文字を拒否します。
外部URLは``ActiveUrlPolicy``で検査してから属性値としてescapeします。件数とバイト数には``StylesheetPolicy``を適用し、
拒否した値をHTMLや診断messageへ出力しません。

文書入力に由来する任意の``style``、classまたはraw HTMLは、stylesheet設定の有無にかかわらず拒否します。
この分担を採用した理由はxref:adr/0007-host-supplied-stylesheets.adoc[ADR 0007]に記録しています。

== 許可するHTML

生成する要素は次に限定します。

* 文書構造：`html`、`head`、`meta`、`title`、`body`、`style`、`link`、`figure`、`figcaption`
* 見出しと本文：``h1``から``h5``、`p`、`div`、`br`、`hr`
* インライン：`a`、`strong`、`em`、`code`、`mark`、`span`、`sub`、`sup`、`kbd`
* ブロック：`pre`、`blockquote`、`cite`、`details`、`summary`
* list：`ul`、`ol`、`li`、`dl`、`dt`、`dd`
* table：`table`、`caption`、`thead`、`tbody`、`tfoot`、`tr`、`th`、`td`
* media：`img`、`audio`、`video`

属性は``lang``、`charset`、`id`、`class`、`href`、`src`、`alt`、`width`、`height`、`title`、`controls`、`open`、
`poster`、`target`、`rel`、``colspan``、``rowspan``、``data-language``、``data-line-numbers``および
``data-line-start``、``data-math-language``および``data-math-display``に限定します。
classには実装が列挙する固定値、source blockの``language-*``、およびhostの``RolePolicy``が許可したblock roleを表す
``role-*``だけを使用します。文書に書いたroleは、hostが名前を列挙した場合に限り``role-<name>``として出力し、
それ以外は出力しません（xref:adr/0020-host-allowed-role-classes.adoc[ADR 0020]）。
入力由来の任意属性、event handler、`script`、SVGおよびraw HTMLは生成しません。

この一覧は通常のHTML変換に適用します。利用側アプリが選択した本文領域を描画する入口では、
<<selected-body-regions>>に記載する固定の段階表示属性も使用できます。スライドの脚注一覧では、
``li.value``にscope内の表示番号を整数で書き込みます。

``target``と``rel``は外部HTTP(S) linkの固定表示と外部stylesheetだけに使用します。入力に書かれた同名属性を
そのまま通過させません。

完全HTML文書には``doctype``、`html`、`head`、UTF-8の``meta``、非空の``title``および``body``を常に出力します。
文書タイトルがある場合は構造モデルのタイトル文字列をinline記法として再解釈せず、escapeして``title``へ
使用します。タイトルがない場合は固定の代替タイトルを使用します。言語を推測せず、``html``の``lang``には
未知を表す空文字列を出力します。

Tableの``width``は1から100までの値を百分率として正規化し、``%``付きで出力します。Captionは安全な
literal textとしてescapeし、inline書式や属性参照を再解析しません。

順序付きlistの``start``、``reversed``および番号形式は型付きpresentationへ保持しますが、公開属性allowlistに
含まれない``start``、``reversed``、``type``および``style``へ変換しません。HTMLでは通常の``ol``として出力します。

利用側アプリが渡す参考文献一覧も同じ制限に従います。項目に番号を渡した場合は``ol``、渡さない場合は``ul``で
出力し、番号の値はHTMLへ書き込みません。表示する番号は``ol``が振るものだけです。そのため利用側が渡す番号は、
出力対象として残った項目の並び順で1から始まる連番でなければならず、満たさない場合は一覧を出力しません。
詳しくはxref:server-execution.adoc#render-inputs[変換入力]を参照してください。

== URLとリソース

URLは由来を示すcontextとともに``RenderPolicy.active_urls``の``ActiveUrlPolicy``で検査します。
文書に記述されたlink、
解決済みxrefおよび解決済みresourceを区別し、利用側アプリが返したURLも信頼済みとして扱いません。

制御文字、空白、不正なscheme、絶対filesystemのpath、backslash、ネットワーク-path referenceおよびpath traversalを
拒否します。許可するscheme、root-relative URL、外部画像およびdata URIはpolicyで明示します。
root-relative URLの許可は解決済みの値だけに適用し、文書へ直接記述した値へは適用しません。

``javascript``と``vbscript``は、利用側アプリが許可schemeへ加えても出力しません。これらはbrowserが
codeとして実行するURLであり、許可する設定を受け付けること自体が誤りだからです。この保証はstylesheetの
検査と同じ考え方です。``data``はこの一覧に含めません。data URIは実行されない内容を運び、独自の設定項目を
持つためです。

解決できない参照、拒否したURLおよび利用できないresourceはactive要素へ変換せず、表示文字列や代替文字列を
escapeした非activeな内容として出力します。解決済み表示文字列はプレーンテキストとして扱い、AsciiDocや
HTMLとして再解析しません。詳しいfallback規則はxref:server-execution.adoc#render-inputs[変換入力]を
基準とします。

画像、音声および動画は、解決済みURL、macro種別と一致するMIME typeおよび対応する
``ResourceCapabilities``がある場合だけactive要素として出力します。MIME typeはASCIIの大文字と小文字を
区別せず、parameterを除いたtypeとsubtypeを検査します。拡張子からMIME typeを推測しません。

画像とアイコンには``image/*``、音声には``audio/*``、動画には``video/*``を要求します。画像はalt、寸法、title、
アイコンはaltとtitle、音声はtitle、動画は寸法、poster、titleを出力できます。寸法には10進整数だけを使用します。
``controls``は音声と動画へ常に付与し、入力から無効化しません。動画のposterは独立した``image/*`` resourceとして
URLとMIME typeを検査します。posterだけを利用できない場合は診断を返してposterを省略し、安全な動画本体は
維持します。Mediaのlink化、アイコンset固有の要素・classおよびその他の再生属性には対応しません。

== HTML5標準適合性検査

生成HTMLの標準適合性は``cargo make verify``で検査します。検査対象は
``fixtures/html/validation.json``で一意に管理し、断片出力は同ディレクトリの固定テンプレートで完全HTML文書へ
変換します。完全文書出力とCLIで生成した公開用・発表者用の研究スライドは包まず、そのまま検査します。
研究スライドの入力は数式・引用・表・脚注・日本語を含み、SVGも同じ検査へ渡します。
生成物は``target/html5/``だけへ書き込みます。

Validatorには``flake.lock``で固定したNixpkgsのNu Html Checkerを使用し、manifestにバージョンと実行optionを
記録します。errorとwarningをいずれも失敗として扱い、言語推定だけを無効にします。既知違反のallowlistは
設けません。不正な入れ子、標準外属性および不完全な文書のnegative fixtureがvalidatorで拒否されることも
同じtaskで確認します。

この検査はHTML5標準への適合性だけを担当します。Golden fixtureのbyte比較、要素・属性allowlist、
URL policy、安全性検査およびnativeとWASMの一致検査は引き続き独立して実行します。

== 区切り付きblockとrole

example、sidebarおよびopen blockは、種類を表す固定class（`example`、`sidebar`、`open`）を持つ``div``で囲み、
block titleがある場合はadmonitionと同じく先頭に``div.title``を出力します。``%collapsible`` optionを持つ
example blockは``details``で囲み、block title（ない場合は``Details``）を``summary``へ出力します。
``%open``を併用した場合は``open``属性を付けます。admonition styleを持つexample blockは引き続きadmonitionです。
quote styleのない``____``はこれまでどおり要素を生成せず、内容だけを出力します。

文書に書いたblock role（`[.name]`または``role=``）は、``RenderPolicy.roles``で許可した名前だけを
``role-<name>`` classとして、段落、ラッパー、表、list、見出しなどblock要素の``class``へ出力します。
許可一覧の既定は空であり、未許可のroleは出力しません。``unknown``を``Diagnostic``にすると未許可のroleを
``role-not-allowed``として報告します。名前はASCIIの英数字、``-``および``_``に限り、それ以外は許可一覧に
含めても出力しません。``lead`` roleだけは従来どおり固定class``lead``を持ちます。

[#selected-body-regions]
== 選択した本文領域

Rustの``output::html::render_regions``は、同じ``semantic::Document``から選択したblockを本文HTMLへ変換します。
利用側アプリは``Document::index()``でblockの識別子``BlockId``と元範囲を対応付け、``Document::block()``で
内容を参照できます。``BlockId``は、その解析結果内だけで有効です。ソースの再解析や意味情報の複製は必要ありません。
脚注定義のinline treeは``Document::footnote_body()``で借用し、``semantic::walk_inlines``で走査できます。
各nodeは定義内の元範囲を保持し、``stem``の記法はその位置の属性値で確定しています。

``HtmlRegionSelection.blocks``は描画するblockの順序を指定します。複数領域を通じて同じblockを選択した場合、
または選択したblockが別の選択blockを含む場合は``HtmlRegionError::InvalidSelection``を返します。
``omitted_blocks``に指定したblockは、選択blockの内部にある場合も内容ごと除外します。

段階表示は、``stepped_blocks``に指定した通常の箇条書き・番号付きlistの各項目、または通常のopen block全体へ
適用します。値は最初の表示段階を表す番号です。固定class``fragment``と整数の``data-fragment-index``だけを
追加し、任意のclass、属性またはHTMLは受け付けません。``container_headings``に指定した見出しでは、見出し要素へ
``id``を出力しません。この場合、利用側アプリが周囲の要素へ同じIDを付けます。段階表示と見出しの指定は、
その領域で実際に描画されるblockだけに適用できます。

全領域は一つの``RenderInputs``を共有し、参照先とresourceの使用状態をまとめて検査します。別の領域で使用する
結果を未使用として報告しません。利用側アプリが除外blockだけで使用する結果を渡した場合は、通常の未使用結果の
診断を返します。診断は元の文書内の範囲を保持し、include展開元との対応も維持します。

この入口は本文だけを返し、``head``、目次、脚注一覧および生成参考文献一覧を追加しません。文書モードと
stylesheet指定も本文へ反映しません。escapeとURL検査には通常の本文writerを使用し、全領域のHTMLの合計に
``OutputLimits.max_output_bytes``を適用します。通常のHTML変換に段階表示を付加したり、roleの扱いを変更したりしません。

=== スライドの番号と参照先

``render_slide_regions``は、本文とノートを表す``HtmlSlideScope``と、実スライドごとに領域をまとめた
``HtmlSlideSelections``を受け取ります。列を別領域へ描画する場合も、同じスライドの領域としてまとめます。
返却する``HtmlSlideRegions.regions``は領域順の本文、``footnotes``はスライドごとの脚注一覧です。
利用側アプリは各スライドの本文・列の後へ対応する脚注一覧を一度だけ追加します。

図表、exampleおよびlistingのcaptionと脚注は、選択された内容だけを対象に、本文とノートでそれぞれ1から
番号を付けます。caption語と番号を無効にする指定は元のblock位置の値を維持します。空labelのxrefは掲載先の
表示番号を使い、著者が記述したlabelは維持します。意味情報のcaption、脚注、識別子および通常HTML・端末・
editor向けの番号は変更しません。

見出しの表示を省略して周囲のスライドにIDを残す場合は、本文領域の``container_headings``へその見出しを
指定します。この入口では指定された見出しが``blocks``の外にあっても、実際に掲載する参照先として認めます。
衝突検査用の予約IDだけでは、掲載していない見出しへの参照を許可しません。

装飾済み引用の横には、固定の``a.citation-link``を一つ付けます。単一の文献を引用した場合はその項目へ、
複数の文献をまとめて引用した場合はscopeの参考文献一覧の先頭へ移動します。操作名は固定の``aria-label``と
``title``へ付け、引用内の外部linkとは並べて出力します。通常HTMLの引用表示にはこのリンクを追加しません。

名前付き脚注を複数スライドで参照した場合は、各スライドの一覧へ同じ内容を掲載し、参照点と掲載先のIDを
scope・スライドごとに分けます。逆参照はそのスライドの実参照点だけを対象にします。本文はノート専用の
脚注定義やlocal参照先を使用できません。ノートは本文で定義した脚注と参照先を使用できます。
脚注本文の数式と引用へ渡す描画結果は、scope内の最初の参照位置における本文内の順序で処理したものを使います。
同じscopeでは定義の元範囲に一つの結果を対応付け、各掲載先で再利用します。数式のSVG内のIDと
fragment参照は検証済みのXML treeから書き直し、同じ脚注内の参照は現在の配置、それ以外は最初の配置へ向けます。
書誌の逆参照には、脚注が実際に掲載されるすべての配置の引用IDを含めます。
脚注本文内のanchorと書誌定義は診断し、IDを出力しません。通常HTMLの脚注本文の扱いは変えません。

生成参考文献は``bibliography``へ一つのHTML断片として返し、逆参照は描画するscopeの実際の引用だけを
対象にします。利用側アプリは本文の一覧を末尾の一つの参考文献スライドへ、ノートの一覧を最後の実スライドの
ノートへ一度だけ追加します。同じ文献が両方で引用されている場合は両一覧へ残します。本文の一覧を囲むスライドには
``HtmlSlideScope::Body.bibliography_id()``の固定IDを付けます。ノートの一覧は断片内に固定のIDを持ちます。

著者のID、利用側アプリが予約したスライドID、検証済み数式のID、および脚注・書誌が生成するIDの衝突を拒否します。
生成IDは``generated_ids``にも返し、後から描画するscopeの予約IDへ追加できます。領域本文、脚注および書誌の
合計に出力バイト上限を適用します。公開用の利用側アプリはノート選択を空にして本文だけを描画します。

== 図表とcaption

1行だけの``image::target[]``は画像blockであり、``figure.image-block``で囲んで``img``を出力します。block titleが
ある場合は``figcaption``へ、表はtitleを``caption``へ、example blockはtitleを``div.title``へ出力し、いずれも
先頭へ番号付きのcaption語（``Figure 1. ``、``Table 1. ``、``Example 1. ``）を付けます。caption語は
``figure-caption``、``table-caption``、``example-caption``属性をblockの位置で解決した値であり、未定義なら
言語既定の語、``:figure-caption!:``のように解除した場合は番号も語も付けずtitleだけを出力します。番号は
語を持つblockだけを種類ごとに読み順で数えます。見出し以外のblockへの空label参照は、anchorの表示テキスト、
番号付きcaption（`Figure 1`）、block title、識別子の順で表示文字列を決め、blockのsourceを表示しません。

== ソースと数式

Source blockの言語classは``SourceLanguagePolicy``で許可した言語だけに付けます。未知の言語ではclassを
省略して診断を返します。

Block titleまたは``linenums``を持つsource blockは``figure.source-block``で囲み、titleを``figcaption``へ
inline装飾を除いた解決済みplain textとして安全に出力します。構造情報のtitleも同じplain textです。
文書が``listing-caption``属性を設定している場合は、titleを持つsource blockとlisting block（``----``）へ
読み順の番号付きcaption語（``Listing 1. ``）を付け、xrefの空label表示にも使います。figureやtableと違い、
属性が未定義なら番号を付けません。titleを持つlisting blockは``figure.listing-block``、literal block（``....``）は
``figure.literal-block``で囲み、titleを同じ形の``figcaption``へ出力します。
``pre``の``data-language``、``data-line-numbers="true"``および``data-line-start``は
構造情報と同じ言語、行番号指定および開始行を表します。行番号要素、構文強調、themeおよび操作buttonは
生成しません。Titleも行番号指定もない従来のsource blockは既存の``pre > code.language-*``構造を維持します。

数式engineは内蔵しません。許可した数式言語だけに固定class、``data-math-language``および
``data-math-display``を付け、内容は常にescapeします。LaTeXは``latexmath``、表示形式は``inline``または
``block``です。Inline数式は``code``、block数式は``pre``内の``code``として出力します。利用側は要素名や
親子関係を推測せず、この二つの属性とescape済みのtext contentを数式描画adapterへ渡せます。
JSON/WASM protocolでは既存の言語enum値``latex``を維持し、``latexmath``はAsciiDoc構文とHTML属性の名前に
限定します。

利用側が検証済みの数式結果を``RenderInputs``へ指定した場合は、その数式だけを静的SVGで
表示します。原TeXは解析結果の値をescapeして保持し、数式を囲む要素の``aria-label``にも設定します。
外部のXMLは要素、属性、名前空間、数値CSS、IDと
参照先を有限の許可集合で検査し、XMLの木から再構成します。DOCTYPE、独自entity、処理命令、script、event属性、
外部URL、HTML要素および未知の名前空間は受理しません。バイト数、要素数および深さを検査してから描画へ渡します。
入力位置に一致しない結果と同じ位置への重複結果は、既存の参照解決と同じように診断します。

引用と生成書誌の外部装飾は、text、強調、上付き・下付き、小型大文字、通常書体への復帰、下線および
資格情報を含まないHTTP(S) linkだけから組み立てます。文字列をHTMLとして解釈する入口はありません。
linkは描画時にも``ActiveUrlPolicy``で検査し、拒否した場合はplain textとして表示します。
通常文書の書誌は引用keyをanchor IDに使います。スライド本文とノートでは固定の別名前空間を使い、
同じ文献を引用しても生成anchorが重複しません。

== 決定性

同じパッケージバージョン、解析結果、``RenderPolicy``および``RenderInputs``からは同じHTMLを生成します。
属性順、改行、空白および末尾改行はテスト用の期待出力で固定し、変更時は意図した差分であることを
確認します。

== 公開適合性fixture

利用側はlink:../../crates/adocweave-core/conformance/cases.json[適合性manifest]から``publicContract``を持つcaseを
選び、入力AsciiDoc、解析結果、HTML、解析診断および描画診断の対応を検査できます。caseに記録した解析条件と
描画条件を適用し、``publicContract``のJSON pointer、HTML断片および診断codeを比較します。

公開fixtureは次の構文を分離して扱います。

* 文書タイトル、TOCおよび節番号
* block title、source language option、linenumsおよび開始行を記述したsource block
* 未対応source optionの診断と安全なlisting回復
* inline数式およびblock数式
* table、quoteおよびlist
* 安全でないURLの解析診断、描画診断および非active HTML fallback

公開仕様は``publicContract``に列挙した意味上の値とHTML構造だけです。公開caseの入力はmanifestへ直接記録し、
実行結果を意味上のassertionと比較します。JSONのkey順と空白、HTMLの属性順、字下げ、空白、末尾改行および
未選択の構造情報fieldは利用側の安定APIではありません。利用側はこれらのbyte列を固定せず、必要な項目だけを
選択して検査します。

Source blockではtitle、language、option、linenums、開始行およびsource本文と、対応する安全なHTML構造を
保証します。数式では構造情報のlanguage ``latex``、表示形式``inline``または``block``、source本文と、
HTMLの``data-math-language="latexmath"``および``data-math-display``を保証します。Tableのcell構造、
quoteの追加presentationおよびlist itemを表す未選択の構造情報fieldは現行の公開仕様に含めず、tableとlistの
HTML断片、およびquoteの既存``blockPresentations``だけを保証します。

== golden fixtureの保守

``expected*File``を持つ内部caseの期待出力fileは手で書き換えず、現在の実装から書き出します。単一manifestに
登録した内部caseはWASM adapter側の一つのcommandで書き出し、同じtestでfileが書き出し結果と一致することを
検査します。

[source,console]
----
cargo test -p adocweave-wasm --test conformance regenerate_shared_fixture_products -- --ignored
----

書き出すコマンドはgateに含めません。内部caseのgolden fileは実装変更の影響を見えるようにするためのもので、
読まずに上書きするとその目的が失われます。コマンドを実行した後は差分を1件ずつ読み、意図した変更だけで
あることを確かめてコミットします。公開仕様を変える場合は、manifest内の入力と``publicContract``の差分を
確認します。

一致を検査するtestはgateに含めます。これにより、ファイルの整形が書き手ごとに揺れることも、複数のcaseが
参照するfileの更新漏れも、コミット前に分かります。
