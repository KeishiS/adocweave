= 利用側アプリの実行仕様

この文書は、CLI、Language Server、WebAssemblyその他の利用側アプリに共通する実行順序と失敗時保証の正本です。
各コンポーネントの責務と依存方向はxref:architecture.adoc#component-boundaries[アーキテクチャ]を参照してください。
内部型、フィールドおよび状態遷移はRust APIと試験を基準とします。

[#analysis-execution]
== 解析

利用側アプリは次の順序で処理します。

. 入力本文、設定、処理上限および外部リソースの同じ時点のスナップショットを取得します。
. includeを有効にした場合は、不足するリソースを許可された取得元から読み、同じ前処理を途中から再開します。
. 前処理済み本文を一度解析し、不変な``Analysis``を得ます。
. 必要な外部参照やmediaを解決し、型付きの変換入力として渡します。
. 入力の版と設定が現在値に一致する場合だけ結果を公開します。

解析結果は入力本文、設定および外部リソースと同じ版に属します。利用側アプリは解析中の値を公開せず、
採用後の``Analysis``を書き換えません。同じ解析結果を診断、整形、問い合わせおよび出力で共有します。

includeを無効にした場合はdirectiveを展開せず、外部リソースを暗黙に取得しません。WASMでも、取得済みのリソースを
要求へ明示した場合だけ前処理します。

[#asynchronous-execution]
== 非同期実行

非同期の利用側アプリは、処理を開始した時点の文書、設定、外部リソースおよび取消し状態を一つの処理単位として
保持します。外部I/Oの完了後、前処理の再開前および結果の公開前に現在値と照合し、古い処理を破棄します。

CPU解析はプロトコルやUIのevent loopから分離し、同時実行数と待機数を制限します。取消しはコアへ伝えますが、
すでに完了した処理でも古い結果は公開しません。共有状態のロックはスナップショットの取得と採用判定に限定し、
CPU処理、外部I/O、実行枠の待機およびクライアントとの通信中には保持しません。

キャッシュを使う場合は、入力本文だけでなく意味へ影響する設定と外部リソースもキーへ含めます。処理途中の値、
取消済みの値、上限を超えた値および失敗した値はキャッシュへ採用しません。

[#execution-observability]
== 観測

通常のログ、メトリクスおよびトレースには、結果分類、処理時間、入出力のバイト数および診断数だけを記録します。
入力本文、展開後の属性値、リンク先、xrefの参照先および生成HTMLは記録しません。本文を必要とするデバッグ機能には、
明示的な有効化とアクセス制御が必要です。

[#resource-execution]
== 外部リソース

コアはリソースの取得を行いません。利用側アプリは論理的なソースIDを保ったまま、ファイルシステム、ネットワークまたは
データベースから取得し、安全性を確認した本文だけを渡します。一回の処理中は、同じIDが指す内容を変更しません。

前処理は不足するリソースを要求した位置で停止し、対応する応答だけを受理して再開します。別の要求への応答や、
一度使った継続の再利用は拒否します。取得失敗時は処理を終了し、途中まで作った解析結果を公開しません。
利用側アプリが診断を残して処理を継続する場合は、失敗したリソースの代替内容を明示的に渡します。

ネイティブ環境のローカルファイルは``adocweave-project``が、要求に保持した読込権限を使って読みます。
許可したルートディレクトリの外側、シンボリックリンクによる許可範囲外への移動、不正なUTF-8および上限超過を
通常の不在と区別します。
検査後に未確認のパスから開き直さず、取得した内容と使用量を一回の要求に固定します。Language Serverは処理結果を公開する前に
文書と参照先が変わっていないことを確認し、変更済みの場合は結果を破棄して新しい要求を開始します。

ファイルシステムの競合に対する保証とOSごとの差は
xref:adr/0046-project-owned-local-filesystem.adoc[ADR 0046]を参照してください。プロジェクト設定から決まる
ルートディレクトリおよび上限の現在の動作はxref:../user-guide/project-configuration.adoc[プロジェクト設定]を
基準とします。Language Serverが解析する文書とファイル監視は
xref:language-server.adoc#lsp-workspace[Language Serverの実行仕様]を基準とします。

ファイル件数、ファイルごとの読込量、合計読込量および結果に保持する量は、一回のプロジェクト処理ごとに制限します。
具体的な設定項目と既定値は、Rust型から生成する
link:../../config/adocweave.schema.json[プロジェクト設定スキーマ]を基準とします。

[#source-map]
== ソースマップ

include展開後のbyte範囲は、ソースマップによって元の``SourceId``と範囲へ対応付けます。診断、修正候補、参照、
リソースおよび文書シンボルは元の位置へ対応付けます。複数の元範囲または変換された範囲にまたがる修正候補は
適用不可とします。

canonical pathは安全性の検査、キャッシュおよび来歴の記録に限定します。診断とソースマップには、利用側アプリが
割り当てた論理的な``SourceId``を使用します。同じファイルを指す別名も、論理IDとして自動的に統合しません。

[#render-inputs]
== 変換入力

``RenderInputs``は、同じ``Analysis``から得た参照、リソースおよび``cite:``に対する解決結果をまとめる、
出力形式に依存しないスナップショットです。変換処理はこの値を読むだけであり、ファイルシステム、ネットワーク、データベース
またはresolverを呼び出しません。渡さなかった種類は、解決結果がない状態として扱います。

参照とリソースの結果は、解析結果が返した問い合わせのUTF-8 byte範囲で照合します。文字列のtargetでは照合しません。
一つの問い合わせへ複数の結果を渡した場合は``duplicate-render-input``、対応する問い合わせがない場合は
``unused-render-input``として報告します。

成功結果のURL、メディア型および表示文字列も非信頼入力です。URLとメディア型を出力直前に再検査し、不適合な値から
有効なリンクやメディア要素を生成しません。解決できない場合は、明示したlabel、元のtargetまたは代替文字列を
escapeした有効でない内容へ戻します。内部障害、権限または非公開の情報を代替表示へ含めません。

[#citation-inputs]
=== 引用と参考文献

AdocWeaveは書誌ライブラリを読みません。利用側アプリは引用の表示文字列と、必要であれば文書内アンカーへのリンクを
渡します。文字列はプレーンテキストとしてescapeし、AsciiDocやHTMLとして再解析しません。存在しないアンカーは
リンクにせず、診断を返します。

外部の書誌項目を表示する場合は``GeneratedBibliography``として渡します。変換処理は解析済みの引用から利用箇所を
決定し、引用から項目へのリンクと項目から引用位置への逆参照を生成します。文書自身が同じIDを定義する場合は
文書内の定義を優先します。不正なキー、重複、競合および未使用項目は安定した診断コードで報告します。

番号付きの一覧では、除外後の項目が表示順に1から連続する必要があります。条件を満たさない場合は
``invalid-generated-bibliography-numbering``を返し、誤った対応関係を持つ一覧を出力しません。

WASMは同じ構造をJSONで受け取り、範囲、項目数および合計バイト数を検査します。native環境とWASMは同じ入力から
同じHTML、診断、通知および構造情報を生成します。

[#diagnostic-integration]
== 診断の統合

構文、意味および標準Lintの診断は``Analysis``の構築時に一度だけ統合します。外部文書、データベース、権限または
アプリ固有IDに関する診断は、``Analysis``を書き換えず別の結果として生成します。表示時はソース位置とコードによる
安定した順序へ統合します。

診断コードは機械判定に使用する安定した識別子です。メッセージを判定条件にしません。修正候補は重複しない
``TextEdit``だけを持ち、安全に適用できる変更と利用者の判断を要する変更を区別します。

[#web-worker-execution]
== Web Workerでの実行

ブラウザーでは公開ブラウザークライアントを使用し、Workerの内部メッセージやWASM補助ファイルを直接利用しません。公開入口は
``analyze(request, { signal })``が返すPromiseです。クライアントは同時に一つの要求を実行し、取消し時またはWASMの
trap時はWorkerを終了して、そのインスタンスを次の要求へ再利用しません。

debounce、文書の版、古い結果の判定、認証、ネットワーク、CSPおよび表示サンドボックスは利用側アプリが所有します。
生成HTMLを信頼済みDOMとして扱いません。配備方法は
xref:../user-guide/release-installation.adoc#wasm-library-deployment[WebAssemblyライブラリの配備]を参照してください。
