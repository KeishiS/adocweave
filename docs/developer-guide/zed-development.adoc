= Zed拡張の開発

この文書では、``editors/zed``にあるZed拡張を検証し、公式Zed拡張レジストリへ提出する手順を説明します。
利用者向けの導入方法は
xref:../user-guide/release-installation.adoc#zed-installation[Zedへの導入]を参照してください。

AdocWeave拡張はLanguage Serverとの接続だけを提供します。AsciiDoc言語の登録と構文強調には、Zed公式レジストリの
``AsciiDoc``拡張を使用します。
``extension.toml``の``language_servers.adocweave.languages = ["AsciiDoc"]``は、その拡張が登録する
``AsciiDoc``言語へAdocWeave Language Serverを関連付けます。これにより、同じ言語定義とTree-sitter grammarを
二つの拡張で管理しません。

[#zed-development-prerequisites]
== 前提条件

次の環境を使用します。

* Zedと``zed``または``zeditor`` CLI
* 公式レジストリの``AsciiDoc``拡張
* ``cargo``、``rustc``および``rustfmt``
* ``rustup``で導入した``wasm32-wasip2`` target

targetがない場合は、Zedが使用するRustツールチェーンで次を実行します。

[source,console]
----
rustup target add wasm32-wasip2
----

[#zed-development-build]
== 構築と自動検査

リポジトリrootで次を実行します。

[source,console]
----
cargo build -p adocweave-cli
cargo test --manifest-path editors/zed/Cargo.toml
cargo build --manifest-path editors/zed/Cargo.toml --target wasm32-wasip2
node tools/zed-registry-contract.mjs
----

Rustのテストは実行ファイルの選択と``adocweave lsp``の起動引数を検査します。レジストリ用の検査は
manifest、README、license、icon、バージョン管理および提出例を確認します。

[#zed-development-install]
== 開発用拡張の導入

. ZedのExtensions画面から``AsciiDoc``拡張を導入します。
. コマンドパレットで``zed: install dev extension``を実行します。
. リポジトリrootではなく``editors/zed``を選択します。
. ``fixtures/zed/manual.adoc``を開きます。

手元で構築したLanguage Serverを使用する場合は、``adocweave``の絶対パスをZedの設定へ指定します。

[source,json]
----
{
  "lsp": {
    "adocweave": {
      "binary": {
        "path": "/absolute/path/to/adocweave"
      }
    }
  }
}
----

指定しない場合、拡張はZedが引き継いだ``PATH``を調べます。そこにもない場合は、AdocWeaveの最新安定版
GitHub Releaseから現在のOSとCPUに合うnative実行ファイルを取得します。

[#zed-development-verification]
== 動作確認

``fixtures/zed/manual.adoc``で次を確認します。

* ``AsciiDoc``拡張による言語認識と基本的な構文強調
* AdocWeaveによる診断、Outline、hover、補完、定義参照、参照検索および文書整形
* 編集後の診断更新と、同じ文書を再び整形したときに差分が生じないこと

起動に失敗した場合は``zed: open log``でZedのログを開きます。明示した実行ファイルについては
``adocweave lsp --help``を実行できることを確認します。言語認識や構文強調だけが動作しない場合は、
``AsciiDoc``拡張が導入されているか確認します。

[#zed-registry-submission]
== 公式レジストリへの提出

拡張のバージョンは``editors/zed/extension.toml``の``version``だけで管理します。Cargo packageの
``version = "0.0.0"``は構築用の固定値であり、拡張のバージョンではありません。利用者に見える変更では、
``extension.toml``と``editors/zed/CHANGELOG.md``を同じcommitで更新します。専用tagとGitHub Releaseは
作成しません。

提出するcommitについて、この文書の検査と開発用拡張の確認を完了し、公開branchに含まれることを確認します。
Zed公式の``zed-industries/extensions``リポジトリでは、HTTPSのsubmoduleを
``extensions/adocweave``へ追加し、``extensions.toml``へ次の項目を追加します。

[source,toml]
----
[adocweave]
submodule = "extensions/adocweave"
path = "editors/zed"
version = "<extension.tomlのversion>"
----

``version``のplaceholderは、提出commitの``editors/zed/extension.toml``と同じ値へ置き換えます。
``pnpm sort-extensions``を実行し、一つの拡張だけを扱うPull Requestとして提出します。説明には、既存の
``AsciiDoc``拡張が言語と構文強調を担当し、AdocWeave拡張はLanguage Server機能を追加することを記載します。

更新時はsubmoduleを新しい公開branch上のcommitへ進め、``extensions.toml``の版も同時に更新します。
AdocWeaveリポジトリのworkflowから外部リポジトリへの投稿は行いません。
