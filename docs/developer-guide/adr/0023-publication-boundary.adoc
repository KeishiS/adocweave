= ADR 0023: 公開先と配布方法
:status: accepted in part; amended by ADR 0043

== 文脈

公開先、製品の単位、検査および書込み権限が複数のADRへ分散し、一つの変更で複数の決定を更新する必要がありました。
個人開発では、この調整自体が継続的な負担になります。

== 決定

公開先と権限の分離方法をこのADRで定めます。配布物ごとの版と公開単位は
xref:0043-independent-distribution-units.adoc[ADR 0043]、エディタとLanguage Serverの導入方法の分担は
xref:0028-editor-language-server-boundary.adoc[ADR 0028]、一つのtagとcommitから同じrunで公開する手順は
xref:0032-same-run-release-publication.adoc[ADR 0032]を基準とします。現在の成果物と公開先は
xref:../release-distribution.adoc[配布仕様]を基準とし、このADRへ一覧を複製しません。

GitHub Releaseを全製品の一次公開先とし、registryへも同じbyte列を送る判断は
xref:0043-independent-distribution-units.adoc[ADR 0043]で置き換えました。現在は配布物ごとに標準的な公開先へ
直接公開し、GitHub Releaseはネイティブ実行ファイルだけが使います。registryへの公開に必要なcredentialを
対象の専用jobだけが参照する判断は維持します。

製品別の配布manifestと配布計画を正本とする決定は
xref:0040-unified-release-and-native-executable.adoc[ADR 0040]で置き換えました。現在の配布情報は
xref:../release-distribution.adoc[配布仕様]、task名と操作手順は
xref:../../../CONTRIBUTING.adoc[コントリビューションガイド]を基準とします。

=== 公開権限

計画、構築、検査およびcandidate集約はread-onlyで実行します。GitHub Releaseへの書込みと、attestationへ
署名するためのOIDCは、保護した``github-release`` Environmentを使う公開jobだけへ与えます。外部actionは
完全なcommit SHAへ固定します。各Environmentのdeployment branch policyは、その配布物の公開workflowを起動する
``main``またはstable tagのpatternだけを許可します。

Release workflowは``main``から手動実行します。書込み権限を持つ``host``より前にnative Releaseの検査を一度実行し、
指定したstable tagとworkspace版が一致することを検査します。後続の
Cachix公開jobは検査済みのtagとcommitを使い、``main``との関係を重ねて検査しません。

ネイティブ版のCachix公開jobは``release.yml``へ直接置き、GitHub Releaseの公開後に動かします。このjob自身へ
``cachix-publish`` Environmentを設定し、Environment Secretの``CACHIX_AUTH_TOKEN``をこのjobだけで参照します。
再利用workflowへSecretを渡す構成や``secrets: inherit``は使用しません。送信後の取得確認jobはEnvironmentも
書込みtokenも使用しません。

独立したregistryへ公開するjobは、配布物ごとのstable tagから専用workflowとして動きます。repositoryへの書込みは持たず、
公開先ごとに必要な資格情報だけを使用します。tokenによる認証しかない公開先ではそのtokenだけを、公開元を
OIDCで確認できる公開先ではtokenを持たず``id-token``の書込みだけを与えます。後者ではCIに長期の資格情報が
残らないため、公開先が対応している場合はこちらを選びます。

tagを作成できる主体を公開jobだけに限るtag rulesetは使用しません。個人所有リポジトリでは組込みの
GitHub Actions appをbypass対象にできず、bypassなしでは公開workflow自身もtagを作成できないためです。
専用GitHub Appと鍵を維持する費用も個人開発の範囲に見合いません。代わりに書込み権限を公開jobだけへ与え、
Environmentのbranch制限と公開前検査で作成経路を限定します。organizationへ移す場合は、Actions appを
bypass対象とするrulesetを再評価します。

== 帰結

公開先と書込み権限の判断は一か所になります。成果物の内容、製品の単位、検査手順およびmetadataの変更は、
それぞれの正本だけを更新します。

ADR 0006、0013、0017および0021は本ADRへの到達性を保つstubとして残します。
