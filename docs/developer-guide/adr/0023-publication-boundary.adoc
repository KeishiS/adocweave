= ADR 0023: 公開と配布の境界
:status: accepted; amended by ADR 0027, 0028, 0030, 0031, 0032, 0033, and 0036

== 文脈

公開先、製品の単位、検査および書込み権限が複数のADRへ分散し、一つの変更で複数の決定を更新する必要がありました。
個人開発では、この調整自体が継続的な負担になります。

== 決定

公開先と権限境界をこのADRで定めます。製品ごとのversionと公開単位は
xref:0027-product-release-trains.adoc[ADR 0027]、エディターとLanguage Serverの導入境界は
xref:0028-editor-language-server-boundary.adoc[ADR 0028]、同じrunの成果物を公開する手順は
xref:0032-same-run-release-publication.adoc[ADR 0032]を基準とします。現在の成果物と公開先は
xref:../release-distribution.adoc[配布仕様]を基準とし、このADRへ一覧を複製しません。

GitHub Releaseを全製品の一次公開先とします。registryへも公開する製品では、GitHub Releaseで検証した同じbyte列を
使用し、registry向けに構築し直しません。registryへの公開に必要なcredentialは、対象の専用jobだけが参照します。

配布manifestの形式はlink:../../../release/adocweave-dist-manifest.schema.json[JSON Schema]、製品と成果物は
link:../../../release/distribution-plan.json[配布計画]を正本とします。task名と操作手順は
xref:../../../CONTRIBUTING.adoc[コントリビューションガイド]を基準とします。

[#publication-authority]
=== 公開権限

計画、構築、検査およびcandidate集約はread-onlyで実行します。GitHub Releaseへの書込みとOIDCは、保護した
``github-release`` Environmentを使う公開jobだけへ与えます。外部actionは完全なcommit SHAへ固定します。

tagを作成できる主体を公開jobだけに限るtag rulesetは使用しません。個人所有リポジトリでは組込みの
GitHub Actions appをbypass対象にできず、bypassなしでは公開workflow自身もtagを作成できないためです。
専用GitHub Appと鍵を維持する費用も個人開発の範囲に見合いません。代わりに書込み権限を公開jobだけへ与え、
Environmentのbranch制限と公開前検査で作成経路を限定します。organizationへ移す場合は、Actions appを
bypass対象とするrulesetを再評価します。

== 帰結

公開先と書込み権限の判断は一か所になります。成果物の内容、製品の単位、検査手順およびmetadataの変更は、
それぞれの正本だけを更新します。

ADR 0006、0013、0017および0021は本ADRへの到達性を保つstubとして残します。
