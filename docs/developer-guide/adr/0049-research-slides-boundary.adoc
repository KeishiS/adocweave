= ADR 0049: 研究スライドの構成と数式・引用処理の分担
:status: 採用

== 状態

{status}

== 文脈

研究スライドでは、AsciiDocの本文に加えて、スライドの区切り、数式、引用および発表者ノートを扱います。
通常HTMLと別の解析器や文書モデルを持つと、構文の修正、原文位置との対応および参照の解決を二重に保守する
必要があります。一方、MathJaxと、引用・参考文献の書式を定めるCSL（Citation Style Language）の処理系は
Node.jsで利用でき、Rustの解析コアへその実行環境を持ち込む必要はありません。

個人開発で保守する範囲を抑えながら、原稿の解析、外部計算、出力の配置およびファイル操作を分担します。
発表者ノートは公開版へ含めない内容であり、本文と混ぜた後にHTMLだけを取り除く方法では、数式の番号、引用の
順序および取得した資産へ影響が残ります。

== 決定

[#existing-analysis]
=== 既存の解析とCLIへの統合

同じリポジトリの``adocweave``内に``slides``を置き、既存の``Analysis``を参照する``Deck``で表示する範囲と
配置を決めます。スライド専用のRust crate、別リポジトリのCLIおよびParserへのplug-in ABIは設けません。
``Deck``は既存のblockとinlineを参照し、別のAsciiDoc解析器や公開文書モデルを定義しません。

コアは構文、意味情報、原文範囲、参照およびHTMLのescapeとURL検査を所有します。``slides``はスライドの
区切り、縦方向のグループ、配置、段階表示および発表者ノートの掲載を所有します。CLIは生成、preview、
補助プロセスの起動および配信を調停し、ローカルファイルの権限と管理出力は既存の``adocweave-project``へ委ねます。

[#bounded-helper]
=== 数式・引用処理とRustの検証

MathJaxとCSL処理系は、独立したNode補助パッケージへ置きます。一回の生成で一つのプロセスへ、件数とサイズに
上限を設けたJSONを渡し、一つの応答を受け取ります。必要な数式と引用がない生成では起動しません。
補助はAsciiDocを解析せず、原稿位置、原稿ファイルの取得、配信および変更監視を所有しません。

Rustは原文位置と対応``key``を保持し、補助へ計算に必要な値だけを渡します。戻り値のSVG、読み上げ用MathML、
有限の引用要素および通知の本文を検査してから、出力用の型へ渡します。未検証のXMLや任意HTMLをコアの出力へ
混ぜません。失敗は対応``key``から原文位置へ戻し、ブラウザーへ未検証の応答を渡さず生成を中止します。

ブラウザーは静的な数式と引用を表示し、MathJaxやCSL処理系を起動しません。これにより、表示時の外部取得と
再計算を避け、保存した出力とpreviewで同じ計算結果を使います。JSONの細目は補助パッケージとRust側の型を、
配布単位の版と互換性はxref:0043-independent-distribution-units.adoc[ADR 0043]を正本とします。

[#two-scopes]
=== 本文と発表者ノートの二つの範囲

数式、脚注、引用および参照の掲載範囲は、本文と全発表者ノートの二つに固定します。本文とノートはそれぞれ
文書順に処理し、番号と引用状態を独立させます。スライドごとやノートごとの任意の範囲は追加しません。
ノート内の数式や引用を編集しても、本文の番号と引用結果は変わりません。

公開出力では、ノートを外した``Deck``から必要な数式、引用および資産を集めます。公開範囲を決めてから
補助処理とファイル取得を行うため、ノートだけの情報を生成物へ持ち込みません。発表者出力は二つの範囲を
保持し、ノートの書誌は最後の実スライドのノートへ一度掲載します。通常HTMLでは``notes``を普通のroleとして扱います。

[#browser-assets]
=== 固定ブラウザー資産と管理出力

reveal.jsのブラウザー資産はCLIに固定して同梱します。通常のCargo構築はnpmからの取得を必要としません。
スライド用Node補助と固定ブラウザー資産は、配布時に使う依存物として監査します。通知とlicenseの扱いは
xref:0034-standard-runtime-dependency-audit.adoc[ADR 0034]を基準とし、版や依存一覧を本ADRへ複製しません。

生成物は専用ディレクトリへ保存し、manifestを管理ファイルの更新、不要ファイルの削除および配信用の検査へ
共用します。未知のファイルや手修正がある出力は更新しません。全OSでのディレクトリの原子的な置換を前提にせず、
処理中に失敗した場合は成功と扱いません。この管理は新しい保存基盤へ分離せず、既存のプロジェクト処理へ置きます。

== 検討した代替案

スライド機能を別のRust crateやリポジトリへ切り出すと、非公開の配置モデルにも互換性と公開工程が必要です。
独立した利用者がいない段階では内部moduleとし、実装を共有する範囲と利用者が導入する配布単位を分けます。

ブラウザーで数式と引用を計算する方法は、表示時の起動、取得、失敗と計算状態をpreviewと保存済み出力の両方で
扱う必要があります。静的出力を採用し、外部処理の失敗を生成時に集めます。

各スライドに独立した引用や番号の範囲を持たせる方法は、前方参照と引用状態を断片ごとに解決する規則を増やします。
本文とノートの二つに固定することで、原稿順を保ちつつ公開範囲を分離できます。

== 帰結

構文や原文位置の修正は既存の解析へ集まり、スライドの配置とNode処理は別々に変更できます。補助の変更では
Rust側の検証と代表的な数式・引用の連携試験を通し、公開出力と発表者出力の両方で境界を確認します。
モジュールの独立性のために、専用crate、常駐プロセス、任意の実行計画および追加の状態管理は導入しません。
