= ADR 0049: 研究スライドの構成と数式・引用処理の分担
:status: 採用

== 状態

{status}

== 文脈

研究スライドでは、AsciiDocの本文に加えて、スライドの区切り、数式、引用および発表者ノートを扱います。
通常HTMLと別の解析器や文書モデルを持つと、構文の修正、原文位置との対応および参照の解決を二重に保守する
必要があります。一方、MathJaxと、引用・参考文献の書式を定めるCSL（Citation Style Language）の処理系は
Node.jsで利用でき、Rustの解析コアへその実行環境を持ち込む必要はありません。

個人開発で保守する範囲を抑えながら、原稿の解析、外部計算、出力の配置およびファイル操作を分担します。
発表者ノートは公開版へ含めない内容であり、本文と混ぜた後にHTMLだけを取り除く方法では、数式の番号、引用の
順序および取得した資産へ影響が残ります。

== 決定

[#existing-analysis]
=== 既存の解析とCLIへの統合

同じリポジトリの``adocweave``内に``slides``を置き、既存の``Analysis``を参照する``Deck``で表示する範囲と
配置を決めます。スライド専用のRust crate、別リポジトリのCLIおよび解析器へ任意コードを注入する
拡張インターフェイスは設けません。
``Deck``は既存のblockとinlineを参照し、別のAsciiDoc解析器や公開文書モデルを定義しません。

コアは構文、意味情報、原文範囲、参照およびHTMLのエスケープとURL検査を所有します。``slides``はスライドの
区切り、縦方向のグループ、配置、段階表示および発表者ノートの掲載を所有します。CLIは生成、preview、
補助プロセスの起動および配信を調停し、ローカルファイルの権限と管理出力は既存の``adocweave-project``へ委ねます。

選択した領域を描画する``render_regions``と``render_slide_regions``はコアへ置きます。CLIが描画範囲を指定し、
コアの既存HTML描画処理がcaption、脚注、引用、参照先および番号をまとめて処理します。これらをCLIで描画すると、
HTMLの安全な生成と文書内の状態を二重に実装する必要があるためです。別の文書モデルや利用側のファイル操作を
コアへ追加せず、既存の解析結果から領域を選ぶ入口だけを公開します。

[#bounded-helper]
=== 数式・引用処理とRustの検証

MathJaxとCSL処理系は、独立したNode補助パッケージへ置きます。一回の生成で一つのプロセスへ、件数とサイズに
上限を設けたJSONを渡し、一つの応答を受け取ります。必要な数式と引用がない生成では起動しません。
補助はAsciiDocを解析せず、原稿位置、原稿ファイルの取得、配信および変更監視を所有しません。

CSLスタイルとロケールの既定値はCLIへ内包します。指定がある項目だけローカルファイルから読み込み、補助には
選択済みのXML全文を渡します。省略時の規則を補助とCLIへ分散させず、外部取得なしで既定の引用書式を再現します。
CSSもCLIの組込みテーマを使い、利用者が指定したCSSをその後に適用します。

Rustは原文位置と対応``key``を保持し、補助へ計算に必要な値だけを渡します。戻り値のSVG、
許可した装飾だけを持つ引用要素および通知の本文を検査してから、出力用の型へ渡します。未検証のXMLや任意HTMLをコアの出力へ
混ぜません。失敗は対応``key``から原文位置へ戻し、ブラウザーへ未検証の応答を渡さず生成を中止します。

ブラウザーは静的な数式と引用を表示し、MathJaxやCSL処理系を起動しません。これにより、表示時の外部取得と
再計算を避け、保存した出力とpreviewで同じ計算結果を使います。要求に使う選択済みコンテンツは一度作り、
入力ファイルの取得判断と補助要求の生成へ渡します。補助応答は全成功または診断群とし、使われない部分成功の
成果物は返しません。複数の診断収集と、後続引用に応じた書式の更新は補助内部で行います。
JSONの細目は補助パッケージとRust側の型を、
配布単位の版と互換性はxref:0043-independent-distribution-units.adoc[ADR 0043]を正本とします。

数式の表示は静的SVGと原TeXの保持を優先し、読み上げ用のMathML出力は扱いません。原TeXを``aria-label``へ
設定して基本的な補助情報を提供しますが、自然言語による数式の読み上げは保証しません。利用者が求める表示に
範囲を絞り、追加の出力型、検証およびブラウザー間の挙動を保守する負担を抑えます。

[#two-scopes]
=== 本文と発表者ノートの二つの範囲

数式、脚注、引用および参照の掲載範囲は、本文と全発表者ノートの二つに固定します。本文とノートはそれぞれ
文書順に処理し、番号と引用状態を独立させます。スライドごとやノートごとの任意の範囲は追加しません。
ノート内の数式や引用を編集しても、本文の番号と引用結果は変わりません。

脚注定義も本文とノートで分け、範囲をまたぐ再利用は認めません。脚注内の数式は番号なしinline式に限定します。
式の定義と参照先をスライドごとの複製へ対応付ける負担を避け、番号付き数式は本文またはノート本文へ置きます。
共有脚注のSVGは検証時に記録したID属性の位置だけを使って複製し、配置のたびにXMLを解析し直しません。
共通HTML描画の結果はスライドごとに領域と脚注を保持し、複数の配列の消費順で配置を復元しません。

手書き書誌とCSLの二方式は同じ生成の表示対象で併用しません。CSLは有限の装飾へ変換できる範囲に限定し、
参考文献の任意の段落配置は扱いません。元のHTMLを許可する方式を追加せず、表示する書式の範囲を明確にします。

公開出力では、ノートを外した``Deck``から必要な数式、引用および資産を集めます。公開範囲を決めてから
補助処理とファイル取得を行うため、ノートだけの情報を生成物へ持ち込みません。発表者出力は二つの範囲を
保持し、ノートの書誌は最後の実スライドのノートへ一度掲載します。通常HTMLでは``notes``を普通のroleとして扱います。

[#browser-assets]
=== 固定ブラウザー資産と管理出力

reveal.jsのブラウザー資産はCLIに固定して同梱します。通常のCargo構築はnpmからの取得を必要としません。
スライド用Node補助と固定ブラウザー資産は、配布時に使う依存物として監査します。通知とlicenseの扱いは
xref:0034-standard-runtime-dependency-audit.adoc[ADR 0034]を基準とし、版や依存一覧を本ADRへ複製しません。

CLIは、スライドを表示する利用側アプリとして固定themeとsystem fontsを選びます。
xref:0007-host-supplied-stylesheets.adoc[ADR 0007]がthemeを同梱しないと定めた対象は汎用HTMLコアです。
スライド用CSSと、本文・発表者画面へ共通に渡す有限の数式・引用CSSはCLIが供給し、汎用HTMLのfragmentや
原稿由来の任意styleを許可する仕組みへ混ぜません。

生成物は専用ディレクトリへ保存し、manifestを管理ファイルの更新、不要ファイルの削除および配信用の検査へ
共用します。未知のファイルや手修正がある出力は更新しません。全OSでのディレクトリの原子的な置換を前提にせず、
処理中に失敗した場合は成功と扱いません。この管理は新しい保存基盤へ分離せず、既存のプロジェクト処理へ置きます。

生成物には本文だけか発表者向けかを表すメタデータを保存し、資産のファイル名から用途を推測しません。
previewは成果物と生成の成功・失敗を区別し、失敗時に前回成功の成果物を保持する判断を一か所で行います。
HTML配信時の世代をページへ渡し、世代と診断を同じ通知で取得することで初回表示と更新の競合を避けます。

画面比率は未指定時の自動取得と原稿による明示指定を維持します。配布する資料には比率を指定でき、
代表的な比率で実内容の収まりを検査します。PDFは最終表示状態で1スライド1ページを既定とし、
段階ごとの複製によるページ数の増加を避けます。

== 検討した代替案

別のRust crateへ切り出すと、CLI内で使う配置モデルをcrate間のインターフェイスとして維持する必要があります。
別リポジトリでは変更の同期と検査も分かれます。独立した利用側がない段階では内部moduleとし、
実装を共有する範囲と利用者が導入する配布単位を分けます。

RustのCSL処理にはhttps://github.com/typst/hayagriva[Hayagriva]などの選択肢があります。採用する場合は、
CSL JSONからの入力変換、装飾結果の受渡しと、locator、同名著者の区別および参考文献順の連携を別途検証する
必要があります。MathJaxのためのNode補助は引き続き必要なため、今回は同じ補助でciteprocを使い、外部計算の
入口を一つにまとめ、今回保守する連携の数を抑えます。

作成ツール全体をNode.jsに置く方法では、既存のRustによるAsciiDoc解析、原文位置と診断の対応、権限付きの
ローカルファイル取得を移植するか、大きなプロセス間インターフェイスを保守する必要があります。既存CLIを
利用し、数式と引用の計算だけを補助へ渡す方が責務を限定できます。

補助のMathJax依存には``speech-rule-engine``も含まれますが、自然言語の読み上げ文字列を出力へ追加する方法は
言語と読み方の選択、式との対応および実際の読み上げ結果の検証を必要とします。依存を同梱していることだけを
読み上げ機能の採用理由とせず、初期の出力はSVGと原TeXに限定します。

ブラウザーで数式と引用を計算する方法は、表示時の起動、取得、失敗と計算状態をpreviewと保存済み出力の両方で
扱う必要があります。静的出力を採用し、外部処理の失敗を生成時に集めます。

各スライドに独立した引用や番号の範囲を持たせる方法は、前方参照と引用状態を断片ごとに解決する規則を増やします。
本文とノートの二つに固定することで、原稿順を保ちつつ公開範囲を分離できます。

== 帰結

構文や原文位置の修正は既存の解析へ集まり、スライドの配置とNode処理は別々に変更できます。補助の変更では
Rust側の検証と代表的な数式・引用の連携試験を通し、公開出力と発表者出力の両方で境界を確認します。
モジュールの独立性のために、専用crate、常駐プロセス、任意の実行計画および追加の状態管理は導入しません。
