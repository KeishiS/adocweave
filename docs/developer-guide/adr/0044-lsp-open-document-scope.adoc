= ADR 0044: Language Serverの解析対象を開いた文書へ限定

:status: accepted

== 文脈

Language Serverは起動時に各workspace folderを再帰的に走査し、見つけた``.adoc``を解析の起点としていました。
この方式は、エディタで利用していない文書にも読込時間とメモリを使い、除外pattern、走査上限、部分結果、再走査および
回復処理を必要とします。CLIの一括処理とは異なり、Language Serverがフォルダ内の全ての独立文書を先に知る必要は
ありません。

一方、開いた文書のincludeとローカル参照を正しく扱うには、参照先を必要になった時点で読み込み、変更を監視する
必要があります。workspace folderは解析対象の一覧ではなく、設定探索とファイル読込を許可する範囲として必要です。

== 決定

Language Serverの解析の起点は、``didOpen``で開かれている文書だけとします。開いた文書からincludeまたは
ローカル参照で必要になったファイルは推移的に読み込み、依存関係を記録して変更を監視します。閉じた独立文書、
参照されていない文書およびファイル監視で初めて知った文書は解析の起点へ追加しません。

workspace folderは次の規則で設定探索とファイル読込の範囲を決めます。

* 各workspace folderを独立した権限の起点として扱います。
* 文書が複数のディレクトリfolderに含まれる場合は、最も内側のfolderを選びます。
* クライアントが通常のファイルをfolderとして渡した場合は、その親ディレクトリを権限の起点とし、そのファイルだけを
  解析の起点として認めます。
* workspace folderがない場合は、開いた文書の親ディレクトリをその文書の権限の起点とします。

起動時とworkspace folder変更時は、クライアントから受け取ったfolder URIだけを記録し、ファイルの列挙、設定の読込み、
pathの正規化および読込権限の確定は行いません。``didOpen``を受け取るたびに、上記の規則でその文書のfolderを選び、
文書ごとの``ProjectRequest``へ読込権限を設定します。``.adocweave.toml``の変更時は、開いている文書と既知の参照先
だけを新しい設定で組み立て直します。

この決定により、``workspace.scan``設定と``ProjectTarget::Workspace``を削除します。旧設定名を別名として受理せず、
移行用の警告や全件走査を有効にする代替設定も提供しません。CLIでディレクトリまたはglobを明示した一括処理は
変更しません。

== 検討した代替案

**初期走査を既定で無効にして設定で有効化。** 二つの解析対象モデルと走査関連の設定・状態が残るため採用しません。

**走査対象をさらに絞る除外pattern。** 大規模フォルダの負荷は減らせますが、利用していない文書を先に列挙する設計は
変わらず、除外規則と読込権限の違いも利用者が理解する必要があるため採用しません。

**ワークスペース全体の索引を別に構築。** 開いていない文書を含む横断検索には有効ですが、永続索引、差分更新および
整合性管理が必要です。現在のLanguage Serverの機能には不要なため採用しません。

== 帰結

Language Serverの起動時間と保持量は、ワークスペース全体の大きさではなく、開いた文書と実際の参照先に応じます。
``workspace.scan.exclude``、走査上限の通知および初期走査の再実行は不要になります。

開いていない独立文書の診断と参照索引は提供しません。将来これらが必要になった場合は、解析対象を暗黙に広げず、
用途と更新規則を定めた索引機能として別に設計します。
