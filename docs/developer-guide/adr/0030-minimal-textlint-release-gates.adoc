= ADR 0030: textlint境界と配布検査の最小化
:status: accepted; pull request gate amended by ADR 0031; release metadata amended by ADR 0036

== 文脈

textlint用パッケージでは、同じcandidateに対して完成archiveの検証、二つのclean buildによる再現性検査、
固定consumer、公開前の``npx``、複数のNode.jsとOSによる導入検査、および定期的な最新依存関係の確認を実行していました。
genericなglobal導入検査にもtextlint用のarchive一覧検査があり、専用の検証器と重複していました。

公開パッケージは実行時依存を持たず、対応するNode.jsとtextlintはpackage metadataと固定consumerで指定します。
同じarchiveを異なるrunnerや入口から繰り返し検査しても、保証する性質は増えず、検査時間と保守対象だけが増えます。

== 決定

``main``で未公開版のcandidateを作るとき、完成した``.tgz``を配布仕様に照らす独立した検証器を1回実行し、
その同じarchiveを固定consumerへ1回導入します。固定consumerは公開Processor、対応拡張子、標準入力、改行、UTF-16位置および
``--fix``による入力の非変更を検査します。

JavaScriptと固定同梱するWebAssemblyの間では、component versionを交換しません。WebAssemblyはnode階層と
``valueRange``の包含関係を検査し、JavaScriptはTxtASTの具体化に必要なUTF-16範囲だけを入力範囲と照合します。
完成archiveの検証器は、同梱WebAssemblyのmemory上限と``parseText``だけを公開するwrapperを検査します。

公開前の``npx``検査、Node.jsとOSの導入matrix、genericなglobal導入検査のtextlint分岐、および最新の推移的依存を
調べる定期workflowは設けません。再現性を調べる手動taskは、検証済みcandidateと1回のclean rebuildを比較します。
Pull Requestのgateには含めません。

公開後は、GitHub Releaseの実URLから取得したarchiveを``sha256.sum``と照合し、その実URLを``npx``へ指定して
単発実行します。完成archiveの構造は公開前に同じbyte列へ対して検証済みであるため、公開後に再検証しません。

== 検討した代替案

**OSごとの導入matrixを維持する。** パッケージのJavaScriptとNode.js向けWebAssemblyは固定consumerが同じ公開入口から
実行します。OS別の処理を持たないため、runnerを増やさず一つの環境で境界を検査します。

**candidateと公開後の両方で``npx``を実行する。** 公開前の固定consumerがパッケージの動作を検査します。
``npx``はGitHub Releaseの実URLから取得できることを確認する公開後の経路に限定します。

**最新依存関係を定期的に解決する。** 対応範囲は固定consumerとpackage metadataで明示します。
その範囲外の依存関係を定期的に観測するworkflowは、公開保証やmerge条件に含めません。

== 帰結

textlint用candidateの検査は、完成archiveの検証と固定consumer E2Eの二段階になります。
検査対象のarchiveと責務が一意になり、同じ性質を別のrunnerや入口から繰り返し検査しません。

再現性の追加調査と公開後の取得経路は残りますが、標準source gateから分離します。ADR 0017およびADR 0023のうち、
textlint用パッケージの検査回数と実行環境に関する決定を本ADRで置き換えます。GitHub Releaseで``.tgz``を配布し、
実行時依存を持たせず、checksum、第三者依存の通知およびArtifact Attestationを生成する決定は維持します。
SBOMを公開しない判断はxref:0036-no-unconsumed-sbom.adoc[ADR 0036]で置き換えました。
