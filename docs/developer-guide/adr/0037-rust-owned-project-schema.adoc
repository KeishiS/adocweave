= ADR 0037: プロジェクト設定Schemaの正本をRustへ集約

:status: accepted; schema source location amended by ADR 0045

== 文脈

プロジェクト設定は、TOMLを受け取るRustのwire型と手書きのJSON Schemaで同じ構造を別々に定義していました。
両者の一致を確認するため、23件の共通テストデータと、その一部だけを解釈する独自JavaScript検証器を
保守していました。相対パスの対象項目はRust sourceを正規表現で読み取っており、設定項目の追加が型、Schema、
検証器、テストデータの複数箇所へ波及していました。

JSON Schemaはエディタでの入力支援に必要です。一方、除外patternの合計文字数や二つのresource上限の
大小関係など、複数の値をまとめて評価する条件はJSON Schemaだけでは表現できません。Schemaと実行時検証の
責務を分けつつ、項目の構造を一か所で管理する必要があります。

== 決定

``adocweave-config``の非公開wire型をプロジェクト設定構造の正本とします。テストを構築するときだけ
``schemars``からJSON Schema Draft 2020-12を生成し、項目名、型、列挙値、未知の項目の拒否および
``serde``の既定値を反映します。Schema固有の説明、正規表現、動的なLint rule名および共有定数由来の上限は、
同じRust moduleで生成結果へ追加します。実行時のcrateにはSchema生成の依存を含めません。

生成したSchemaは標準のRust JSON Schema validatorで検査します。従来の23ケースはRustテストへ移し、
Schemaと実行時の双方へ適用します。生成結果は``config/adocweave.schema.json``とbyte単位で比較し、通常の
workspaceテストで差分を検出します。更新用のignored testだけが管理者の明示操作で生成物を書き換えます。

相対パスはどのOSでも``/``を区切りとし、``\``、絶対パス、drive名および``..``を拒否します。
従来は途中の``\``をSchemaで受理し、実行時の意味がOSによって異なっていました。設定をどのOSでも同じ意味で
解釈するため、schema-version 1で受理する相対パスを``/``区切りの表記に限定します。
除外patternの合計文字数とresource上限間の大小関係は実行時検証が所有し、Rustで上限・下限付近の値をテストして保証します。
JSON Schemaには各文字列、配列または数値へ単独で適用できる制約だけを記載します。

== 検討した代替案

**手書きSchemaと独自validatorを維持する。** 実行時依存は増えませんが、JSON Schemaの一部を再実装し、
Rust sourceの構造にも依存します。設定項目ごとの変更箇所が増えるため採用しません。

**SchemaからRust型を生成する。** 公開Schemaを先に設計できますが、TOMLの解決、権限の制限、既定値および
利用側の型への変換はRust固有です。生成後の型へ実行時処理を追加する構造になり、正本と主要な処理が離れるため
採用しません。

**Schemaを実行時に公開する。** 埋込み先がSchemaを取得できますが、通常の設定読込に不要な生成依存と公開APIが
増えます。現在はリポジトリ内の生成物でエディタへ提供できるため採用しません。

== 帰結

設定項目の構造変更はRust型を起点に行い、生成物の差分で公開Schemaへの影響を確認できます。独自JavaScript
検証器、外部テストデータおよびRust sourceの読み取り処理は不要になります。Schemaだけでは表せない条件は
実行時検証に残るため、条件を追加するときは単項目制約か複合制約かを判断し、対応するRustテストを追加します。

ADR 0011のstrict schemaと設定項目の一か所管理に関する決定を、本ADRの生成方式で具体化します。探索、権限制限
およびconsumer overrideに関する決定は維持します。設定形式を変更するとschema versionを上げる原則に対し、
OSによって意味が変わる``\``区切りの廃止だけは本決定でv1を厳格化します。この変更を含む製品を公開するときは、
対象製品のRelease Notesへ``/``区切りへ書き換える移行手順を記載します。
