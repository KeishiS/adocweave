= ADR 0013: VSIXとLanguage Serverの同一release境界

:status: accepted

== 文脈

VS Code拡張は``adocweave-lsp``を起動するadapterであり、意味解析を独自に実装しません。拡張とLanguage Serverを
別々のバージョン系列で配布すると、互換範囲、managed binaryの取得先および障害時の責任境界が増えます。
一方、Visual Studio MarketplaceやOpen VSXへ公開すると、GitHub Releaseとは別の資格情報、審査および
更新経路を保守する必要があります。

== 決定

VSIX、CLI、Language Server、browser packageおよびZed拡張を同じパッケージバージョンとGitHub Releaseへ含めます。
VSIXは同じcandidate workflowで一度だけ構築し、配布manifest、SBOM、checksumおよびArtifact Attestationの
対象にします。拡張は自身と完全に一致するバージョンのLanguage Serverだけを起動し、managed binaryは同じtagの
配布manifestから選択します。

GitHub Releaseを正本とし、VSIXをそこから取得して導入できる状態を常に保ちます。

Open VSX RegistryへはこのVSIXをそのまま公開します（2026-08-21の改訂、https://github.com/KeishiS/adocweave/issues/611[Issue 611]）。公開するのは
GitHub Releaseへ添付したものと同一のfileであり、Open VSX向けに作り直しません。公開は
GitHub Releaseの公開が成功した後、同じworkflowのjobがchecksumとattestationを検証してから行います。
Visual Studio MarketplaceおよびZed Extension Galleryへは公開しません。

== 結果

一つのcandidateと対象コミットから全成果物を追跡でき、拡張独自の互換表が不要になります。VSIXだけを修正する
場合も新しいパッケージバージョンとreleaseが必要です。

Open VSXの利用者はeditorの標準UIから導入と更新を行えます。公開するfileがGitHub Releaseのassetと同一であるため、
どちらの経路で入手しても同じattestationで確認できます。取り消しは行わず、問題のある版は新しいversionで置き換えます。
Open VSXの公開tokenという資格情報が一つ増えますが、参照できるのは公開後に動く専用jobだけです。
