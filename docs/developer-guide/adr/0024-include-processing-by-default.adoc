= ADR 0024: includeの既定での展開
:status: accepted

== 背景

``include::``は、一つの文書を複数のファイルへ分けて書くためのAsciiDocの構文です。分けて書いた文書は
それでも一つの文書であり、展開しなければ、そこにない文章に対して診断を出すことになります。

これまでAdocWeaveは、include先を読み込むかどうかを``resources.include``で選ばせ、既定値を「展開しない」
としていました。ファイルを読む機能を利用者が明示的に選ぶ、という考え方です。しかし実際の運用では、
次の二つの問題が起きていました。

一つ目は、Language Serverの挙動が設定ファイルの有無で変わることです。``.adocweave.toml``がない
workspace folderでは、Language Serverが展開を有効にしていました。一方、設定ファイルを置くと解析済み設定の
既定値である「展開しない」が効きます。つまり、lint規則を一つ書いただけ、あるいは初期走査の除外を書いただけで、
無関係なinclude解決が止まります。原因が設定ファイルの存在そのものであるため、利用者が原因にたどり着くのは
困難です。

二つ目は、CLIが他のAsciiDoc実装と異なることです。一般的な実装はincludeを既定で
解決します。``adocweave convert manual.adoc``がinclude先を無視するという挙動は、利用者の予想と一致しません。

== 決定

include処理を既定で有効にします。

``resources.include``の既定値を``true``とし、設定ファイルの有無で挙動が変わらないようにします。
解析済み設定の既定値と、``[resources]``節を書かない設定ファイルの解決結果を一致させます。
Language Serverが設定ファイルの不在を理由に展開を有効化していた特例は削除します。

CLIには``--no-include``を追加します。``--include``は、設定で無効にしている場合に一度だけ有効化する
optionとして残します。両方を同時に指定した場合はusage errorとします。

標準入力から読んだ文書は例外とします。標準入力には位置がないため、相対的なincludeが何を基準にするかを
決められません。``--stdin-base``がある場合だけ展開し、ない場合は展開しません。``--include``を明示した上で
``--stdin-base``がない場合は、要求に応えられないためusage errorのままとします。

== 帰結

読み込める範囲は変わりません。既定で展開するのはincludeの解決であり、どこまで読めるかは従来どおり
``resources.roots``、workspaceの許可範囲およびfilesystemの権限が決めます。この決定は新しいパスを開きません。

include先を読ませたくないプロジェクトは``resources.include = false``を書きます。一度だけ止める場合は
``--no-include``を使います。

``adocweave config show``が出力する``resources.include``の既定値が変わります。設定を書いていない
プロジェクトでは、解析対象のファイル数と読み込むbytes数が増えます。いずれも``resources``の上限が
従来どおり抑えます。
