= ADR 0034: 配布runtimeの依存監査を標準toolへ集約

:status: accepted; SBOM publication amended by ADR 0036

== 文脈

依存関係の検査では、Cargoとnpmの標準toolに加えて、manifestとlockfileの組を再掲する境界目録、固定した
RustSecデータベースのrevision、空の例外一覧、ビルド専用npm依存のlicense目録およびDependabot設定の完全一致検査を
保守していました。同じ依存関係を複数のfileへ記録するため、依存を更新するたびに配布時の安全性と直接関係しない
一覧の同期が必要でした。固定したRustSecデータベースは、revisionを更新するまで新しいadvisoryを検出しませんでした。

== 決定

依存監査の対象を、利用者の環境で動く配布runtimeへ限定します。Cargoは``cargo-deny``へ集約し、root workspaceと
Zed拡張についてadvisory、license、取得元およびwildcard依存を検査します。advisory検査ではdatabase取得を無効にせず、
実行時の最新RustSecデータベースを使用します。

npmは、runtime依存を持つVS Code拡張に対して``npm audit --omit=dev``を実行します。lockfileから得る推移runtime依存の
licenseと取得元は一つの小さな検査で確認し、同じ集合を第三者依存の通知とSBOMに使用します。Browserとtextlint用
パッケージはruntime npm依存を持たないことを、それぞれのパッケージ検査で維持します。

ビルド専用npm依存はmanifestとlockfileへ固定し、``npm ci --ignore-scripts``による取得時のintegrity検証に委ねます。
観測したlicense集合の別目録、lockfileを再掲する依存境界目録、空の例外一覧およびDependabot設定の完全一致検査は
置きません。

Advisoryの例外が必要な場合だけ``deny.toml``へ構造化したignoreを追加します。``reason``には、影響しないと判断した
理由、将来の期限および追跡IssueのURLを定めた書式で記載し、検査で必須にします。例外がない状態を表すfileは作りません。

== 検討した代替案

**RustSecデータベースのrevisionを自動更新する。** 再現可能な入力を保てますが、更新Pull Requestが統合されるまで
新しいadvisoryを検出できません。脆弱性情報には現在性を優先するため採用しません。

**ビルド専用依存も配布runtimeと同じ方針で監査する。** CIで実行するtoolのリスク把握には使えますが、利用者へ届く
依存の保証とbuild環境の管理が混ざり、license目録と監査対象が大きくなります。build環境はNix、lockfileおよび
scriptを実行しない導入経路で固定するため、配布runtimeの監査には含めません。

== 帰結

``security-audit``はnetworkへ接続し、取得時点の最新advisoryを検査します。network障害時は古いdatabaseへ戻さず、
監査を失敗させます。CIでは``main``のsource検査後にこのtaskを実行し、成功後だけ統合検査と公開経路へ進みます。
Pull Requestの標準source検査は時点依存のsecurity監査を含みません。

依存packageの一覧、versionおよび取得時integrityは標準のmanifest、lockfileとpackage managerを基準とします。
独自に残す判断は、配布runtimeの許可licenseと取得元、および成果物へ記録する第三者依存情報だけです。
