= ADR 0025: 走査の上限超過で部分結果を残す

== 状態

{status}

[NOTE]
====
Language Serverの初期走査はxref:0044-lsp-open-document-scope.adoc[ADR 0044]で廃止しました。本文に現れる
``adocweave-host`` crateもxref:0046-project-owned-local-filesystem.adoc[ADR 0046]で廃止し、ファイル操作は
``adocweave-project``が持ちます。以下は廃止前の判断です。

== 背景

Language Serverの初期走査は、ディレクトリの項目数が10万件に達すると失敗していました。失敗した走査は
ワークスペース全体を破棄する扱い(fail-closed)であり、その結果、開いている文書の解析、整形および
問い合わせもすべて止まっていました。利用者から見ると、大きなリポジトリを開いた途端にLanguage Serverが
何も応答しなくなります。

この扱いは、root外アクセス、権限拒否および不正な設定と同じ経路です。それらは「その結果を信じてはいけない」
失敗であり、破棄する理由があります。一方、項目数の上限は作業量の上限です。上限に達しても、そこまでに
見つけた文書は実際にディスク上にあり、開いている文書の解析結果も正しいままです。

上限超過をfail-closedにしていた理由は、ファイルシステムjobの設計にもありました。上限に達した予約を
確定すると、jobは終端状態になります。これは部分的な走査結果を完全な結果と取り違えないための仕組みですが、
同じjobが走査後のファイル読み込みにも使われるため、走査が上限に達しただけで後続の読み込みも失敗して
いました。

== 決定

走査の失敗を二つに分けます。

**権限と整合性の失敗**は従来どおりfail-closedとします。root外、権限拒否、symlinkの検査失敗、
取り消し、および不正な設定は、結果を公開しません。

**予算の失敗**では、そこまでに確定した走査結果を保持します。ディレクトリの項目数が上限に達した場合、
走査はその時点で止まり、見つけた文書を解析の起点として登録します。ワークスペースは動作し、
開いている文書は通常どおり解析します。

プロジェクト設定の``resources``による読み込み上限も予算です。あるプロジェクトが自分の文書数より小さい
``max-files``を設定している場合、初期走査はそのプロジェクトの残りの文書を読まずに飛ばし、ほかの
プロジェクトの走査を続けます。読み込みを断られてもcandidate状態は変わらないため、draftは汚染せず、
すでに読み終えた文書はそのまま登録します。文書を開いたときの解析ではこの上限を従来どおり適用します。
include先を欠いた文書は別の文書であり、部分的な結果を正しい解析として扱えないためです。

上限に達したことは、``window/showMessage``のWarningとしてエディタへ送ります。文面には
``workspace.scan.exclude``で除外できることを含めます。従来のerror診断
(``workspace-resource-error``)は権限と整合性の失敗のために残します。

診断ではなくメッセージにするのは、走査を終えられなかったことがワークスペース全体の事情であり、
特定の文書に原因がないためです。診断として公開すると、原因のない文書を含めて開いているすべての
ファイルの1行目に印が付き、しかも編集では消せません。

走査が終えられなかった原因は文字列ではなく、ディレクトリ項目数の上限とプロジェクトごとのresource上限を
区別する値として走査結果に保持します。一つの走査で複数の原因が生じた場合も、それぞれを失わずに保持します。
走査結果を組み込む処理は、直前の走査にも存在した原因を除き、新たに生じた原因だけを走査完了eventへ含めます。
このため、同じ原因が続く間は最初の1回だけ通知します。完全な走査によって原因がなくなった後の再発と、
workspace folder変更後の走査は新しい期間として通知します。通知待ちの状態をLanguage Server内部へ別に保持せず、
走査完了eventが通知対象をbackendへ明示的に渡します。多数のプロジェクトが同時に上限へ達してもメッセージを
連続送信しないよう、一つの走査で新たに生じた原因は一つのメッセージへまとめます。メッセージには該当する
プロジェクトの総数を必ず示し、設定ファイルのpathは先頭5件まで、1件あたり240文字まで表示します。

jobを終端状態にしないため、走査は上限に達した予約を確定しません。次の項目があるかどうかを確かめる
overflow probeの予約は、確定せずに解放して走査を止めます。probeの本来の役割である「ちょうど上限で
終わった」と「上限を超えた」の区別はそのまま働き、前者では走査を完全な結果として扱います。

== 帰結

10万件を超えるワークスペースでも、Language Serverは動作します。走査で見つからなかった文書は解析の
起点として登録されませんが、開けば解析し、include先としても読み込めます。

利用者は警告を見て``workspace.scan.exclude``を設定でき、設定後の再走査で完全な結果になります。
既定の除外patternと合わせて、設定を書かないまま上限に達する場面はさらに減ります。

10万件という上限そのものは変えていません。読み込むファイル数、bytes数およびsession数の上限も
従来どおりです。

``adocweave-host``の走査APIは、見つけたpathと「最後まで到達したかどうか」を返す
``discover_adoc_paths_within_budget``を追加します。従来の``discover_adoc_paths_with_control``は、
不完全な走査をerrorとして扱う呼び出し元のために残します。
