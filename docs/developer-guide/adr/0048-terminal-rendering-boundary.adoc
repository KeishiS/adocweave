= ADR 0048: 端末出力の整形とANSI変換の分担
:status: 採用

== 状態

{status}

== 背景

端末でAsciiDoc文書を読む経路がありませんでした。利用者は``convert``が出すHTMLをブラウザーで開くか、
記法を含む原文をそのまま読むしかなく、手元で文書を一読する作業がブラウザーに依存していました。

端末向けの出力を作る場合、どこまでをcoreが担当するかを決める必要があります。端末の幅、標準出力が端末か
どうか、環境変数``NO_COLOR``は、いずれも実行環境を見ないと分かりません。一方で、幅を決めたうえで文章を
折り返し、見出しやリストを並べる処理は、入力だけで結果が決まります。

``crates/adocweave-core``は環境を参照しない状態を保っています。``tests/repository_conventions.rs``の
``core_source_does_not_access_the_environment``が、core内での``std::env``や``std::fs``の使用を禁止します。

== 決定

**整形、折返しおよび配置は``adocweave-core``の``output::terminal``が持ちます。** 入力は文書と設定値だけで、
結果は行の並びです。同じ入力と設定値からは常に同じ結果になります。

**coreはANSIエスケープ列を生成しません。** 各行は装飾の意味を表すroleを付けたspanで構成します。roleは
``Heading``、``Admonition``、``Code``、``Link``、``TableBorder``のように、何であるかを表します。色や太字と
いった見え方は含めません。

**端末の判定とANSIへの変換はCLIが持ちます。** 幅は``--width``、環境変数``COLUMNS``、端末の実際の幅、
既定の80桁の順で決めます。色は``--color``と``NO_COLOR``で決めます。roleから端末の装飾への対応表もCLIに
置きます。

**表示桁数の計算には``unicode-width``を使います。** 全角文字は2桁、結合文字は0桁として数えます。曖昧な幅の
文字をどちらで数えるかは設定値で選べます。

**端末で表現できない要素は、内容が失われたと分かる形へ置き換えます。** 画像は``[Image: 説明]``、数式は原文、
表の縦の結合は先頭の行だけに内容を置く形です。黙って消すことはしません。

== 検討した代替案

**整形もCLIへ置く。** coreの意味情報に対する2つ目の走査がcore外にでき、構文を追加するときに解析、出力および
adapterを同時に確認する前提が崩れます。``Document``の内部表現は非公開であり、ブロックを再帰的にたどる処理は
core内で行う前提の構造です。

**coreがANSI文字列を返す。** WebAssemblyやLanguage Serverが同じ整形結果を使う場合、必要なのは構造化した
装飾情報です。ANSI文字列を返すと、利用側がそれを解析し直すことになります。比較用のfileにエスケープ列が
入ると差分を確認できなくなり、レビューで壊れたかどうかを判定できません。

**表示桁数の表を自前で持つ。** 依存を増やさずに済みますが、結合文字、絵文字および異体字選択子の扱いで
ずれます。ずれは表の桁が合わない形で表面化します。``src/cjk.rs``は語の間に空白を置くかどうかの判定であり、
表示桁数の判定とは目的が違うため流用できません。

== 結果

coreは環境を参照しない状態を保ったまま、端末向けの整形を提供します。比較用のfileは装飾を含まない文字列
なので、レイアウトの変更が差分として読めます。

将来、配色を``.adocweave.toml``で設定できるようにする場合、roleから色への対応表をCLI側で差し替えるだけで
済み、coreの公開APIは変わりません。端末のhyperlinkを使う場合も、spanが持つURLをCLIが符号化するだけです。
