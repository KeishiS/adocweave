= ADR 0038: ワークスペース走査の除外patternを組込み値へ追加
:status: 置換済み。ADR 0044により置換

== 状態

{status}

== 文脈

``workspace.scan.exclude``は、利用者が値を書くと組込みの4 patternをすべて置き換えていました。リポジトリ固有の
directoryを一つ除外するだけでも組込み値を再列挙する必要があり、組込み値の変更も既存設定へ反映されません。
空の配列には全directoryを走査する特別な意味があり、未指定と空を分けるwire型と解決処理も必要でした。

除外は初期走査の負荷を抑えるための方針であり、fileへのアクセス権限ではありません。組込み値が対象とする
版管理データ、仮想環境、導入済みpackageおよびビルド結果を解析の起点として探す利用場面はありません。

== 決定

``workspace.scan.exclude``は、組込みの``**/.git``、``**/.venv``、``**/node_modules``および``**/target``へ
追加するpatternの配列とします。空の配列は追加なしを表し、組込み値を解除する設定は提供しません。除外範囲の
文書も、明示的に開いた場合、include先として必要になった場合およびCLIへ直接渡した場合は読み込みます。

``adocweave-config``が組込み値と利用者入力を合成し、解決済み設定には実際に照合する順序付きのpatternだけを
保持します。文字列が同じpatternは最初の一件だけを保持します。globの包含関係は判定しません。入力件数と文字数の
上限は重複を除く前の利用者入力へ適用し、重複による上限の回避を防ぎます。Language Serverは合成規則を持たず、
解決済み設定の判定結果だけを初期走査へ適用します。

この意味の変更に合わせてプロジェクト設定をschema version 2とします。version 1との互換parserは残しません。
移行時は``schema-version``を2へ変更し、組込み4 patternの再列挙を削除してリポジトリ固有の追加分だけを残します。

== 検討した代替案

**組込み値を解除する別項目。** 特殊なリポジトリを走査できますが、追加と解除の優先順位、Schemaおよび表示方法が
増えます。除外は権限ではなく、必要な文書を読む経路は維持されるため採用しません。

**否定pattern。** 一つの配列で追加と解除を表現できますが、patternの順序と競合を利用者と実装の双方が解釈する
必要があります。初期走査の負荷を抑える設定には不要な複雑さなので採用しません。

**利用者入力がある場合の完全置換を維持する。** 実効値を直接指定できますが、組込み値の再列挙と、未指定と空を
区別する処理が残ります。リポジトリ固有の設定だけを書くという目的に合わないため採用しません。

== 帰結

設定ファイルにはリポジトリ固有の追加分だけが残り、組込み値の変更はすべての設定へ反映されます。
``adocweave config show``は組込み値に追加分を続けた実効値を表示します。同じpatternの重複は設定エラーにならず、
実効値にも増えません。

version 1の``exclude = []``で組込みdirectoryを走査していた利用者は同じ動作を選べなくなります。ただし、除外した
文書を開く操作、includeおよびCLI入力は維持されるため、初期走査以外のfile利用範囲は変わりません。
