= VS Code拡張の開発

この文書では、リポジトリの作業treeからVS Code拡張とLanguage Serverを検証する手順を説明します。
利用者向けのVSIX導入手順は
xref:../user-guide/release-installation.adoc#vscode-installation[VS Codeへの導入]を参照してください。

== 責務

``editors/vscode/``はAsciiDocのlanguage登録、TextMate grammarおよびLanguage Clientの起動を担当します。
Language Serverの導入と更新は利用者が行います。解析、診断、整形および意味問い合わせは``adocweave-lsp``だけが実装します。
解析設定は``.adocweave.toml``を正本とし、VS Code設定へ複製しません。

TextMate grammarはLanguage Server起動前の基本色付けを担当します。Semantic Tokensはlink、xref、anchor、
literalなどの意味的な補足を担当し、見出しの基本色付けを置き換えません。

== アイコン

拡張画面と拡張registryへ表示するアイコンは``editors/vscode/resources/icon.png``です。VSIXへ同梱するのは
128×128のこのfileだけで、元画像``resources/icon-source.png``(1254×1254)は同梱しません。元画像はChatGPTの
画像生成で作成したもので、このリポジトリの成果物として扱います。図案を変更する場合は元画像を差し替え、
同じ縦横比のまま128×128へ縮小して``icon.png``を更新します。

== 自動検証

Nix開発環境で次を実行します。

[source,console]
----
nix develop
cargo make verify
cargo make acceptance
----

Extension host testは固定バージョンの公式VS Codeを隔離したuser dataディレクトリへ取得し、local buildの
``adocweave-lsp``を絶対pathで指定します。診断、Outline、Code Action、Format、Hover、補完、Definition、
References、Document Link、Rename、Semantic Tokens、UTF-16位置、include先の更新、連続編集後の古い結果の不採用、
複数workspace folder、再起動および終了後のprocess残存を確認します。通常利用しているVS Code profileは使用しません。

``acceptance``のVS Code検査はVSIXを構築し、同梱fileが許可一覧と完全に一致すること、sizeの上限および
機械固有pathの不在を検査します。さらに、隔離したVS CodeへVSIXを導入し、更新、以前のバージョンへのrollbackおよび
uninstallを確認します。

公開するbyte列が入力だけから決まることも``acceptance``が確認します。同じソースから
VSIXをもう一度構築してSHA-256を比較するため、構築時間が2倍になります。成果物を公開する経路（``release-check``と
release candidateの構築）だけで実行します。Pull RequestではVSIXを構築せず、source、manifestおよびtestを検査します。

これらの構築と検査を行う``editors/vscode/scripts``はTypeScript（``.mts``）で書き、配布物で固定したNode.jsが型注釈を
取り除いてそのまま実行します（変換や追加の依存はありません）。型検査は``npm run check --prefix editors/vscode``の
``tsc -p tsconfig.scripts.json``で行い、型消去だけでは実行できない構文は拒否します。

== 手動確認

. Language Serverと拡張をbuildします。
+
[source,console]
----
cargo build -p adocweave-lsp
npm ci --ignore-scripts --prefix editors/vscode
npm run build --prefix editors/vscode
----

. 空のprofileディレクトリを作り、VS Code CLIの``--extensionDevelopmentPath``でExtension Development Hostを
  起動します。``code``は手元で使用するVS Codeの実行ファイルへ置き換えられます。
+
[source,console]
----
mkdir -p /tmp/adocweave-vscode-user /tmp/adocweave-vscode-extensions
code \
  --user-data-dir /tmp/adocweave-vscode-user \
  --extensions-dir /tmp/adocweave-vscode-extensions \
  --extensionDevelopmentPath="$PWD/editors/vscode" \
  "$PWD/editors/vscode/test/fixtures/adocweave.code-workspace"
----
. Extension Development Hostの利用者設定へ次を追加します。
+
[source,json]
----
{
  "adocweave.server.path": "/absolute/path/to/target/debug/adocweave-lsp"
}
----

. ``test/fixtures/workspace/root.adoc``を開き、自動検証と同じ機能を確認します。
. Output panelの``AdocWeave``を確認します。拡張独自のlogには文書本文、URI、環境変数およびdownload URLを
  出力しません。Language Client traceは既定で無効です。

== Language Serverの選択

次の順序で選択します。

. ``adocweave.server.path``で明示した絶対path
. extension hostの``PATH``上にある``adocweave-lsp``

``adocweave.server.path``はmachine scopeの設定であり、workspace設定から実行fileを指定できません。
拡張は未信頼workspaceでは起動しません。設定pathが相対pathの場合は``PATH``へ進まず停止します。
``PATH``では絶対directory内にある実行fileだけを候補にします。どちらにも見つからない場合は、
Language Serverの導入と設定方法を表示します。引数、環境変数および任意commandは設定できません。

拡張は製品versionを事前に問い合わせません。Language Server Protocolの``initialize``で機能を交換し、
対応しない機能はLanguage Clientの標準処理に従います。

== 清掃

Extension Development Hostを終了すると、VS CodeのLanguage Clientが``shutdown``と``exit``を送り、
Language Server processを停止します。拡張はprocess handle、download fileおよびcacheを独自に管理しません。

自動testの隔離profileはtest runnerが削除します。通常profile全体または共有extensionディレクトリは削除しません。
