= アーキテクチャ

この文書は、AdocWeaveを構成する各コンポーネントの責務と依存方向の正本です。公開APIと対応範囲は
xref:core-profile.adoc[コアの対応範囲]、文法はxref:grammar.adoc[文法の詳細]、
利用側アプリの実行順序はxref:server-execution.adoc[利用側アプリの実行仕様]を参照してください。

[#component-boundaries]
== コンポーネントの責務と依存方向

[source,text]
----
VS Code・Zed ──LSP──> adocweave lsp
ブラウザークライアント ──> Web Worker ──> adocweave-wasm ──> adocweave
textlint ──> adocweave-textlint ──> adocweave

adocweave-cli ──> adocweave-lsp, adocweave-project, adocweave-host, adocweave
adocweave-lsp ──> adocweave-project, adocweave-host, adocweave
adocweave-project ──> adocweave-host, adocweave
adocweave-workspace ──> adocweave
----

矢印は利用する側から利用される側へ向きます。下位コンポーネントは上位のプロトコル、実行環境または
製品固有の型へ依存しません。

[cols="2,5",options="header"]
|===
|コンポーネント |所有する責務

|``adocweave``
|I/Oに依存しない構文解析、意味情報、診断、整形、出力および問い合わせ

|``adocweave-host``
|ローカルファイルの読込権限、競合に耐えるパス検査および資源使用量の計測

|``adocweave-workspace``
|ディスク上のリソース、開いている文書、世代、依存関係およびI/Oに依存しない再開可能な前処理

|``adocweave-project``
|一回のプロジェクト処理で所有する全解析対象、設定の型とスキーマ、設定の指定と上書き、
検証済みのファイル読込権限、処理上限、対象探索、設定と関連ファイルの取得、有限回の解析および対象別の結果

|``adocweave-cli``
|``adocweave``のコマンド、標準入出力、ファイル操作、処理の調停および終了状態への変換

|``adocweave-lsp`` crate
|``adocweave lsp``から呼び出すLSPの通信、URIと位置の変換、通知順序、並行実行、接続単位の``Session``および
クライアントへの結果公開

|``adocweave-wasm``
|WebAssemblyの要求・応答・errorの検証と、公開する通信型とコア型の相互変換

|``adocweave-textlint``
|解析結果からtextlint用TxtASTへの変換と、コア解析およびTxtAST変換をNode.jsへ公開する
WebAssemblyインターフェイス

|ブラウザークライアントとWeb Worker
|Promiseと取消を含む公開入口、Workerの生存期間およびWebAssemblyの隔離

|VS Code拡張とZed拡張
|言語登録、基本色付けおよびLanguage Serverプロセスの起動。文書解析は所有しません。
|===

crateとpackageの正確な構成、依存先および版は各manifestを基準とします。この図は実装の直接依存を示します。
配布成果物と公開方法はxref:release-distribution.adoc[配布仕様]を基準とし、この文書へ複製しません。

BrowserのWorker入口とNode.jsのdirect入口は、同じWebAssembly要求、応答およびerrorの公開仕様を使います。
公開仕様は利用側が渡す文書、必要な結果および外部リソースを表し、前処理、正規化、出力変換などの内部段階を
含めません。具体的な設計判断はxref:adr/0042-wasm-public-contract.adoc[ADR 0042]を参照してください。

[#single-analysis]
== 単一解析

入力は一度解析し、同じ版の解析結果を整形、診断、HTML、Language Serverおよび利用側アプリで共有します。
利用側ごとにソースを再解析したり、見出し、参照または文書構造を再導出したりしません。

構文層は元のbyte列、空白、不完全な入力および回復地点を保持します。意味層は見出し、段落、表、参照、
属性などを出力形式に依存しない値として表します。HTMLやエディタ固有の規則はParserへ持ち込みません。
具体的な認識規則と回復結果はxref:grammar.adoc[文法の詳細]を基準とします。

[#host-boundary]
== 利用側アプリとの分担

コアはファイルシステム、ネットワーク、データベース、環境変数および非同期の実行環境へ直接アクセスしません。
利用側アプリは外部リソースを取得して権限と上限を確認し、一回の処理中に変化しないスナップショットとして渡します。

ローカルファイルの安全性は``adocweave-host``、保持中のリソースと解析世代は``adocweave-workspace``が
所有します。``adocweave-project``は設定と処理上限を解決し、同じ要求が持つファイル読込権限で設定を取得します。
CLIとLanguage Serverは``adocweave-project``を利用し、パス検査、使用量の計測またはinclude規則を
独自に実装しません。

``adocweave-project``の``process``は、一つの所有された要求を同期的に処理します。対象の探索、設定の読込、
主文書、include、スタイルシートおよびローカル参照先の取得では、要求が持つ同じ権限と使用量上限を共有します。
``ProjectTargetResult.analysis``は、主文書の解析結果を利用できるかを表します。``analysis``が成功の場合に得られる
``ProjectAnalysis``では、
``primary``に主文書だけの解析結果を保持します。``expanded``には、include展開、展開後の解析および原文位置との
対応付けに成功した``ProjectExpandedAnalysis``か、その処理の失敗理由を保持します。includeを展開できない場合も
``primary``は利用できます。取消しは対象ごとの結果に含めず、要求全体の``ProjectError::Cancelled``として返します。

結果は次の3種類です。

* ``analysis``が失敗の場合は、主文書の解析結果を利用できません。
* ``analysis``が成功し``expanded``が失敗の場合は、``primary``だけを利用できます。
* ``analysis``と``expanded``が成功の場合は、主文書とinclude展開後の解析結果を利用できます。

Language Serverは開いた文書だけを解析の起点とし、includeとローカル参照の推移的な参照先を必要に応じて
読み込みます。ワークスペースフォルダ内の文書は列挙しません。CLIの明示したディレクトリとglobは、指定された
範囲を従来どおり列挙します。
同じ``LogicalSourceId``の本文取得または存在確認を要求内で繰り返した場合は、同じ取得権限と取得方法で観測した
最初の成功、ファイル不在または失敗を再利用します。別の取得権限や、シンボリックリンクを許可しない取得方法では、
以前の拒否結果へ置き換えず、その権限と方法で改めて観測します。include先を解決する基準位置は
検証済みのOS上のパスへ対応付けるため、プロジェクト外やUTF-8で表せないディレクトリでも文字列への損失変換を行いません。
したがって、一度固定した取得結果は処理中の変更に左右されません。ただし、別々のリソースを同時刻に読み取った
ファイルシステム全体のスナップショットは保証しません。
本文取得と存在確認は別々に結果を固定します。取得済みの本文は存在の証拠として再利用できますが、本文の取得失敗は
存在確認の失敗を意味しないため再利用しません。権限を絞り込んだ場合も、取得時と同じファイル読込権限を保持すると
確認できた結果だけを再利用します。

プロジェクト外にある明示設定へ与えた権限は、設定本文の読込だけに使用します。その設定で指定した
includeの読込みを許可するディレクトリ、スタイルシートおよびローカル参照先へ権限を引き継ぎません。

解析対象の指定は、種類と正規化したパスまたはパターンの順に処理し、同じ指定だけを重複排除します。
ディレクトリとglobは別の指定として扱います。
globはコンパイルやディレクトリ走査の前に重複を除き、異なるパターンを256件、パターンのUTF-8表現を合計64 KiBに
制限します。この上限は要求を受理する処理自体を一定量に収めるための固定値であり、``ProjectLimits``では変更できません。
超過はファイル取得中の上限到達ではなく、``TargetSelectionError``として返します。
解析対象と関連リソースは安定した順序で返します。走査件数、ファイル件数、読込量、includeの深さと件数、
解析の再開回数および結果に保持する展開済み文書・リソース本文の量のいずれかが上限へ達した場合は、
完全な解析結果として扱いません。主文書の解析後にinclude展開または展開結果の保持量が上限へ達した場合は、
主文書の解析結果を残し、``expanded``に上限到達を返します。``adocweave-project``は長期状態、
汎用ファイルシステム抽象、キャッシュ
および非同期の実行基盤を所有しません。
取得済みの本文を結果量の上限によって省略する場合は``LoadedOmitted``とし、取得失敗へ書き換えません。
要求が持つファイル件数と読込量は、設定の探索を含む全物理取得の上限です。設定の``resources``上限は、
同じ設定ファイルを解決した全対象で共有します。設定を使わない対象はプロジェクトrootを同じ範囲として扱い、
入れ子の設定ファイルを解決した対象は別の範囲として計測します。主文書、include、スタイルシートの本文取得と
ローカル参照先の存在確認は取得前に件数を予約し、本文のバイト数は同じ取得権限で観測した本文ごとに一度だけ
計測します。本文の読込処理には、その設定で残っている合計量とファイルごとの上限を渡し、上限を判定するための
1バイトを超えて読み込みません。存在確認の後で本文が必要になった場合は、その本文のバイト数を追加で計測します。
同じ設定を使う対象は、設定スナップショットと解決済み設定を共有します。設定ファイルのUTF-8バイト数は保持量として
設定ファイルごとに一度だけ結果量へ加えます。別々の設定ファイルを大量に読み込む場合も、``max_output_bytes``を
超えて保持しません。

取得、取消しまたは解析に失敗した候補状態は公開状態へ反映しません。利用側アプリは結果を公開する直前に
入力の版と設定を再確認し、古い結果を破棄します。詳しい実行順序と失敗時保証は
xref:server-execution.adoc[利用側アプリの実行仕様]を基準とします。Language Server固有の通知と要求は
xref:language-server.adoc[Language Serverの実行仕様]を基準とします。

アプリ固有のID、データベーススキーマ、アクセス制御および検索用メタデータは、標準の意味情報へ混在させません。
利用側アプリは採用済みの解析結果から独自情報を検証・取得します。拡張方法は
xref:extensions.adoc[利用側アプリの拡張]を参照してください。

[#trust-boundary]
== 純粋性と安全性

同じ入力、設定、外部リソースのスナップショットおよびpackage版からは、同じ解析結果と出力を生成します。
時刻、乱数、ファイルシステムの列挙順およびmapの挿入順を結果へ反映しません。

文書入力、外部リソースおよび利用側アプリが返すURLを信頼済みのHTMLとして扱いません。HTML出力では
要素、属性、classおよびURLを許可集合へ制限します。出力規則は
xref:html-contract.adoc[HTML出力の仕様]を基準とします。

処理上限は構造要素や診断を全件生成する前に適用します。CPU処理、外部I/O、実行枠の待機および
クライアントとの通信中に共有状態のロックを保持しません。

[#change-invariants]
== 変更時の不変条件

実装変更では次の条件を維持します。

* 出力形式、実行環境または利用側アプリごとのParserの複製禁止
* 構文追加時における構文情報、意味情報、診断、整形、出力および代表アダプターの同時確認
* 未処理要素の明示と、回復処理の入力上での前進
* ルート文書とinclude文書における前処理規則、上限およびソースマップの共通化
* 外部I/Oを利用側アプリ、決定的な解析と変換をコアが担う責務分離
* 同じ入力スナップショットに対するnativeとWebAssemblyの意味情報および出力の一致

ファイル数や行数だけを理由に層を追加しません。分割する場合は、解析、出力、プロトコル変換、実行制御または
外部I/Oのいずれを所有するかを先に定めます。
