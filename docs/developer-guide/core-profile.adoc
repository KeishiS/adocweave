= コアAPIと対応範囲

この文書では、AdocWeaveが環境に依存せず扱う範囲、公開APIおよび処理上限を定義します。
通常の文書作成では xref:../user-guide/syntax-support.adoc[対応しているAsciiDocの書式]を参照してください。
ここで説明するRust APIは``adocweave-core`` crateが所有し、Rustコードからは
``adocweave_core``という名前で参照します。

== 対象範囲

AdocWeaveは、AsciiDocの読み取り、問題の検出、整形、HTMLへの変換、見出しやリンクなどの構造情報を提供します。
特定のノートアプリのデータベース、ログイン権限、画面の構成、ネットワーク通信は提供しません。
そのような機能は利用側アプリで追加します。

== バージョン

コアAPIはRustワークスペース内部のバージョンを使います。WebAssemblyの製品バージョンは
link:../../packages/wasm/package.json[WebAssembly package manifest]、必要なRustのバージョンは
link:../../toolchains.json[toolchain manifest]を基準とします。
公開結果を保存するアプリケーションは、AdocWeaveの更新時にHTMLおよび検索用情報を再構築してください。

0.y.zの間はminor版で互換性のない変更を行う場合があります。更新前に
https://github.com/KeishiS/adocweave/releases[GitHub Releases]のRelease Notesを確認してください。

== 対応する書式

文書の題名、見出し、段落、属性、アンカー、リテラル・ソースブロック、リスト、表、リンク、
相互参照、数式、画像・音声・動画などを扱います。各書式の対応状況は
xref:../user-guide/syntax-support.adoc[対応しているAsciiDocの書式]にあります。

未対応の書式を通常のHTMLとしてそのまま出力することはありません。``SyntaxMode::Permissive``では
内容を安全なテキストとして残し、``SyntaxMode::Strict``では未対応の書式を含む文書を処理しません。

[#document-projection]
== 構造情報

``adocweave_core::output::projection``は、一つの``Analysis``から必要な構造情報だけを取得するqueryを提供します。
各queryはHTMLを生成せず、ソースを再解析せず、ファイルシステム、ネットワーク、DBまたはアプリ固有のschemaへ
アクセスしません。

[cols="1,3",options="header"]
|===
|query |取得する情報

|``document_title``
|文書タイトル、表示文字列および元のrange

|``external_links``
|通常の外部link、その表示文字列、対象およびrange

|``reference_edges``
|文書内、文書間または任意schemeを参照するxrefと、その解決結果

|``source_blocks``
|Source blockの言語、未加工の本文、表示情報およびrange

|``formulas``
|inlineまたはblockの数式、その言語、未加工の式およびrange

|``ordered_lists``
|番号付きlistの開始番号、並び順、番号形式およびrange

|``block_presentations``
|admonition、quote、verse、example、sidebar、open、collapsible、figure、tableのtitle、role、展開状態、
番号付きcaptionおよびrange

|``searchable_text``
|検索用文字列と、各部分に対応する元のrange
|===

``reference_edges``だけは、同じrevisionに対応する``RenderInputs``も受け取ります。ソースのrangeが一致する解決結果が
一つだけあるedgeへ結果を付け、対象不在または重複時には付けません。このquery自体は参照先へアクセスしません。
ほかのqueryは``Analysis``だけを受け取ります。

文書の``SourceId``、明示anchorと見出しの対象、Footnote・bibliography・階層indexのcatalog、見出し・appendix・
book part・manpage headerの構造、および番号・TOC・captionなどの表示情報は、``Analysis``の``source_id``、
``reference_targets``、``catalogs``、``structure``および``presentation``から直接借用します。これらを一つの
構造体へ複製して保持しません。

WASM adapterは、利用者が``document``を要求した場合だけ、これらのqueryと``Analysis``から借用した値を
``DocumentView``へ集約します。公開するWASM protocolのfield名、列挙値、配列順および要求していないproductを
応答から省く処理は、このadapterが保証します。Rustのqueryは公開protocolの構造へ依存しません。

Language Serverはsemantic tokensやdocument linksの処理で必要なlinkやrangeだけを参照します。検索用文字列、数式、
Source block、catalogなどを同時に生成しません。

数式の``FormulaProjection.kind``は表示形式を表す``inline``または``block``です。Rust APIの
``MathLanguage::Latex``は``as_asciidoc_name()``で``latexmath``を返します。JSON/WASM protocolでは``latex``を使い、
AsciiDoc構文名やHTMLの``data-math-language``と混同しません。

Source blockの``sourceRange``は、開始区切り行の行頭から終了区切り行の行末までを表します。
先行するblock title、anchorおよび属性行は含みません。本文には``contentRange``、言語名には
``languageRange``、titleには``title.sourceRange``を使用します。metadataを含む記述全体が必要な場合は、
native APIの``VerbatimBlock.metadata.range``またはsyntax treeの先行する``BlockTitle``、``BlockAnchor``、
``BlockAttribute``を参照します。保存した構造情報とrange索引はAdocWeaveの更新時に再生成します。

``rendering_features``は、描画に追加対応が必要な数式言語、Source block言語および
TOC出力の有無を``RenderingFeatures``として返します。言語は重複を除きます。数式言語は固定順の
``latexmath``、``typst``で返し、将来の言語はこの順序表へ追加します。Source block言語はHTMLの言語classと
同じ規則でASCII英字を小文字化し、ASCII英数字、``-``および``_``以外を``-``へ置き換えてから文字列の
昇順で返します。言語指定のないSource blockは含めません。TOCは有効化され、かつ実際の取得結果に
一つ以上の項目がある場合にだけ``true``です。

このqueryは``Analysis``を直接受け取り、preprocessで展開されたincludeの内容も反映します。
返す値は文書が持つ意味上の機能だけであり、HTML構造、renderer、JavaScriptライブラリ、themeおよび資産URLを
選択しません。``RenderingFeatures``は非網羅的な公開型です。将来fieldを追加する場合や返す言語名を増やす
場合はminor版の変更としてRelease Notesに記録します。既存の``MathLanguage``へvariantを追加すると
利用側の網羅的なmatchへ影響するため、このqueryは同enumを公開fieldとして保持せず、安定したAsciiDoc向け
言語名を返します。

解決失敗は安定した種類だけを保持し、自由形式のmessageや表示名を含めません。権限拒否、対象不在または
内部障害から、非公開のタイトル、DB情報または内部例外を構造情報へ漏らしません。

同じパッケージバージョン、``Analysis``および解決結果からは、WASM adapterが同じ順序のJSONを生成します。
保存した構造情報はAdocWeaveの更新時に再生成してください。
公開protocolのfield、列挙値またはtag付きunionを変更する場合は``schemaVersion``を更新します。
Browser内部のWorker封筒は公開protocolに含めません。Package versionはリリース用Pull Requestで、
対象製品のversionの正本と配布物へ反映します。

=== 識別子と文書構造

見出しとanchorのIDは文書全体で一度だけ決定し、HTML、xref、Language Serverおよび構造情報で共有します。
明示IDには空白、制御文字、`[`、`]`、`<`、`>`、``,``および``#``を使用できません。Unicode正規化や
大小文字変換は行わず、入力の表記を保持します。

明示IDがない見出しでは、Unicode英数字を小文字化し、それ以外の連続部分を``_``へ置き換えて先頭に``_``を
付けます。英数字が残らない場合は``_section``とし、重複時は``_2``、``_3``のように最小の連番を付けます。

TOCとDocument Symbolsは共通の文書構造を使用し、個別に見出し階層を再構築しません。文書タイトル、
discrete headingおよび``notoc``を指定した見出しはTOCから除き、その子は直近の表示対象階層へ繰り上げます。

=== 検索用文字列

タイトル、見出し、段落、list項目、linkおよびxrefは、inline装飾を除いた可読文字列として検索対象にします。
Literal blockとsource blockはcodeとして区別します。数式、文書属性行、anchor記号および未対応blockは
検索文字列へ含めません。

各segmentは元sourceのUTF-8 byte rangeを保持します。連結した検索文字列内のoffsetとは一致しないため、
位置対応が必要な場合はsegmentごとのrangeを使用します。

=== textlint用文章構造

``adocweave-textlint`` crateの``plan``は、一つの``Analysis``からTxtASTに対応する``TxtAstPlan``を生成します。
校正対象の選択とTxtASTへの対応付けはコアへ含めず、この専用crateで行います。見出し、段落、リスト、表、
引用、code、commentおよびinline装飾の親子関係を保ち、各範囲をJavaScript文字列と同じUTF-16単位で返します。

planは文章を複製せず、原文から``raw``と``value``を取り出す範囲を持ちます。Node.js用WebAssemblyは
``parseText``でplanをJavaScriptへ渡し、JavaScript側は位置と文字列を付加するだけで、AsciiDoc構文を
再解釈しません。

Source blockとinline codeはcodeとして区別し、文章規則の対象から外します。数式、pass、属性参照および
表示文字列のないmacroも``Code``として元の親nodeに保持します。属性参照やinline記法を含まないfootnote本文、
画像の代替文、iconの代替文またはtitle、audioとvideoのtitleは校正対象です。UI macroは各表示要素を``Code``として
保持します。
macroの文章部分は、``is_plain_inline_text``で文書解析と同じ有界のinline recognizerを適用し、単一の
``Inline::Text``になるかを判定します。属性参照またはinline記法がある場合は、macro全体を文章規則から
除外します。block titleはTxtASTにcaption nodeがないため、depth 1の``Header``として扱います。includeは
展開せず、位置は解析した一つの物理文書を指します。

=== 利用側アプリの拡張

アプリ固有のID、tag、DB列、アクセス制御および検索engine固有のtokenを標準の構造情報へ追加しません。
利用側アプリは用途別queryの結果と``Analysis``から借用した情報を使い、固有の構造情報や検索索引を別に構築します。

== 処理の上限

大きすぎる入力で処理が止まらないように、既定の上限を設けています。次は主な上限であり、
完全な一覧は``AnalysisLimits``のAPI documentationを基準とします。

[cols="2,1",options="header"]
|===
|対象 |既定の上限

|入力 |10 MiB
|出力 |50 MiB
|1行 |1 MiB
|リストの深さ |8
|インライン書式の深さ |32
|表の本体 |5 MiB
|表のセル |100,000
|表の列 |1,000
|ブロック |100,000
|問題の件数 |1,000
|===

利用側アプリは用途に応じて上限を設定でき、安全側へ制限する場合は既定値より小さくします。CLIとWebAssemblyは
出力サイズも検査します。
ライブラリを直接使用してHTMLを表示するアプリは、表示前に同等の出力サイズ検査を行ってください。

== APIの利用

Rustからは``Engine``、`AnalysisOptions`、``Analysis``が主な入口です。
解析は``Engine::analyze``で実行します。``SourceId``や協調キャンセルを渡す場合は
``AnalysisInputs``を組み立てて``Engine::analyze_with``へ渡します。この構造体は
指定しない項目を既定値のままにできるため、渡す入力の組み合わせごとに別のmethodを
用意しません。位置ごとの属性値と
その値を決めたbindingは``Analysis::attribute_environment().resolve_at()``から、最終値viewは
``Analysis::attribute_environment().final_values()``から取得します。属性を記述した順番と
source rangeは``Analysis::document_attribute_occurrences()``から取得します。同じexpanded offsetに
複数の読込eventがある場合は``resolve_at_event()``でevent IDを指定します。属性値の
``source_text``と``source_range``は記述どおりの複数物理行を保持し、``folded_text``は通常の継続を
spaceへ畳み、hard breakのplusを残してmarkerを改行へ畳んだ意味評価用の値です。
``lines``から各物理行と継続markerのrangeを取得できます。
``Analysis::attribute_references()``は各参照の名前、range、有効値および決定binding IDを返します。
Binding IDは同じ解析スナップショット内だけで有効であり、``AttributeEnvironment::binding()``で対応する
source occurrenceを取得します。
属性fixtureと保証対象の対応は link:../../fixtures/attributes/manifest.json[属性の公開仕様manifest]を基準とし、
リポジトリ検査でfixture一覧とこの文書体系の同期を確認します。

前処理と解析を一度に行う場合は、``AnalysisOptions``と``PreprocessOptions``から
``EffectiveProcessingOptions``を作り、その``preprocess_and_analyze``を呼び出します。
この値は両段階で共有する文書外属性と属性展開上限の一致を構築時に検査します。``adocweave-project``も、
一回の要求に含まれる主文書とinclude展開後の解析へ同じ設定を適用します。

[source,rust]
----
use adocweave_core::output::html::{RenderPolicy, render};
use adocweave_core::{AnalysisOptions, Engine, ParseError};

fn convert() -> Result<String, ParseError> {
    let source = "\
= 文書
:toc:
:sectnums:

== 節
";
    let analysis = Engine::new(AnalysisOptions::default()).analyze(source)?;
    Ok(render(analysis.document(), &RenderPolicy::default()).html)
}
----

``:toc:``と``:sectnums:``はRust側のflagではなく、文書ヘッダの属性によって有効になります。
``:toclevels:``は1から5までの整数であり、省略時はlevel 1から5までを目次候補とします。不正な値は
``invalid-attribute``診断となります。

属性Lintは参照ごとに、その位置で有効なbindingを``AttributeEnvironment``から選択します。前方参照と
unset後の参照は``undefined-attribute``、循環と展開上限超過は``attribute-expansion``として診断します。
``unused-attribute``は名前全体ではなく個々のset bindingを対象とします。通常の再定義は有効な操作であり、
重複診断を行いません。

[#wasm-api]
== WebAssembly API

``adocweave-wasm``は、ブラウザーとNode.jsからコアAPIを利用するための入口です。ブラウザーの
``AdocWeaveClient``とNode.jsのdirect入口は、同じ``AnalyzeRequest``、``AnalyzeResult``および
``AdocWeaveError``を使います。

[source,javascript]
----
const result = await analyze({ source, products, resources });
----

ブラウザーの入口は``Promise``を返し、``AbortSignal``による取消しに対応します。Node.jsのdirect入口は
Web Workerを使いませんが、要求、応答およびエラーの項目は同じです。

=== 要求

``AnalyzeRequest``のトップレベルには次の3項目だけを指定できます。

[cols="1,1,1,3",options="header"]
|===
|項目 |型 |指定 |意味と省略時の値

|``source``
|``SourceInput``
|必須
|解析する主文書と、その文書に適用する解析入力です。``null``は受理しません。

|``products``
|``ProductRequest``
|必須
|必要な結果と、その結果だけに適用する設定です。1件以上のproductを指定します。

|``resources``
|``ResourceInput``
|省略可
|include文書と利用側アプリが解決した外部リソースです。省略時は空の入力です。
|===

この節に示す全てのobjectで未知の項目を拒否します。型に``null``を含む項目だけが``null``を受理します。
それ以外の省略可能な項目は、項目自体の欠落または``undefined``だけを省略として扱います。

==== ``source``

``SourceInput``は次の項目を持ちます。

[cols="1,1,1,3",options="header"]
|===
|項目 |型 |指定 |意味と省略時の値

|``text``
|``string``
|必須
|解析するJavaScript文字列です。

|``id``
|``string``
|省略可
|結果中で主文書を識別する論理IDです。省略時は論理IDを持ちません。空文字列と制御文字を含む値は拒否します。

|``attributes``
|``Record<string, string | null>``
|省略可
|文書へ事前に渡す属性です。文字列は設定、``null``は未設定を表します。省略時は空です。空の属性名と
制御文字を含む属性名は拒否します。object内の値には``undefined``を指定できません。

|``syntaxMode``
|``"permissive" | "strict"``
|省略可
|構文の判定方法です。省略時は``"permissive"``です。
|===

構文解析、属性展開および出力量の上限はpackageが固定します。利用側が上限を増やす項目は公開しません。
小さい上限を必要とする場合は、``source.text``と``resources.documents``を呼出し前に制限してください。
原文中の範囲は、対象のJavaScript文字列をUTF-8へencodeした後のバイト位置で表します。

==== ``products``

``ProductRequest``はproduct名をキーに持つobjectです。項目の存在が出力要求を表すため、値の``false``と
``null``は拒否します。設定を持たないproductには``true``、設定を持つproductには``true``または設定objectを
指定します。空のobjectは拒否します。

[cols="2,2,2,3",options="header"]
|===
|product |要求値 |応答値 |意味

|``syntax``
|``true``
|``string``
|元の範囲と回復結果を保持する構文情報です。

|``canonicalAst``
|``true``
|``string``
|正規化したASTのJSON文字列です。

|``html``
|``true | HtmlOptions``
|``string``
|安全方針を適用したHTMLです。``true``は``HtmlOptions``の既定値を使います。

|``attributeOccurrences``
|``true``
|``DocumentAttributeOccurrence[]``
|原文に対応する文書属性の出現です。

|``attributeQueries``
|``true``
|``AttributeQueryResult``
|属性の設定と参照の対応です。

|``resourceQueries``
|``true``
|``ResourceQuery[]``
|利用側アプリによる画像、音声および動画の解決が必要な箇所です。

|``diagnostics``
|``true | DiagnosticOptions``
|``Diagnostic[]``
|構文、意味、Lintおよび要求したHTML変換で生じた診断です。``true``は既定の診断設定を使います。

|``symbols``
|``true``
|``DocumentSymbol[]``
|文書タイトル、見出しおよびlist itemの階層です。

|``document``
|``true``
|``DocumentView | null``
|文書全体から得た、利用側アプリ向けの意味情報です。
|===

``HtmlOptions``は次の項目を持ちます。各項目と、項目に指定する方針objectの各項目は省略できます。

[source,typescript]
----
type HtmlOptions = {
  documentMode?: "fragment" | "complete";
  activeUrls?: {
    allowedSchemes?: string[];
    allowAuthoredRelative?: boolean;
    allowResolvedRelative?: boolean;
    allowResolvedRootRelative?: boolean;
    allowDataUris?: boolean;
  };
  externalLinks?: {
    openInNewContext?: boolean;
    noreferrer?: boolean;
  };
  sourceLanguages?: {
    allowed?: string[];
    unknown?: "preserve-sanitized" | "omit-class" | "diagnostic";
  };
  roles?: {
    allowed?: string[];
    unknown?: "silent" | "diagnostic";
  };
  mathLanguages?: Array<"latex" | "typst">;
  unresolvedReferences?: "target" | "label-only" | "hidden";
  resourceCapabilities?: { images?: boolean; media?: boolean };
  stylesheets?: Array<
    | { kind: "external"; url: string }
    | { kind: "inline"; css: string }
  >;
};
----

[cols="2,2,3",options="header"]
|===
|項目 |既定値 |意味

|``documentMode``
|``"fragment"``
|``"fragment"``は本文断片、``"complete"``は完全なHTML文書を返します。

|``activeUrls``
|schemeは``http``と``https``、相対URL、root相対URLおよびdata URIは不許可
|HTMLへ出す記述値と解決済みURLの許可範囲です。

|``externalLinks``
|新しい閲覧contextを開かず、``noreferrer``を付けない
|外部linkの表示方法です。

|``sourceLanguages``
|全言語を許可し、未知の言語は安全なclass名として保持
|source blockの言語classです。

|``roles``
|許可listは空、未知のroleは診断しない
|HTMLのclassへ出せるblock roleです。

|``mathLanguages``
|``["latex", "typst"]``
|数式として扱う言語です。

|``unresolvedReferences``
|``"target"``
|解決できない参照の表示方法です。

|``resourceCapabilities``
|画像、音声および動画を有効
|HTMLへ出せる外部リソースの種類です。

|``stylesheets``
|空の配列
|完全なHTML文書へ追加する、検証済みの外部またはinline stylesheetです。
|===

``DiagnosticOptions``は次の項目を持ちます。全て省略できます。

[source,typescript]
----
type DiagnosticOptions = {
  protectedAttributes?: Record<string, string | null>;
  authoredUrls?: {
    allowedSchemes?: string[];
    allowRelative?: boolean;
  };
  rules?: Record<string, {
    enabled?: boolean;
    severity?: "error" | "warning" | "information" | "hint";
  }>;
  maxDiagnostics?: number;
};
----

[cols="2,2,3",options="header"]
|===
|項目 |既定値 |意味

|``protectedAttributes``
|空のobject
|文書から変更できない属性と値です。文字列または``null``を指定し、object内の値には``undefined``を指定できません。

|``authoredUrls``
|schemeは``http``と``https``、相対URLは許可
|文書に記述されたURLの診断方針です。

|``rules``
|空のobject
|Lintルールcodeをキーにした``enabled``と``severity``の上書きです。未知のcodeは拒否します。

|``maxDiagnostics``
|``1000``
|返す診断件数の上限です。0以上1000以下だけを受理します。
|===

``HtmlOptions``と``DiagnosticOptions``でも、値に``null``を指定した項目と未知の項目を拒否します。
``html``と``diagnostics``を要求した場合は、HTML変換時の診断を``diagnostics``へ統合します。
``diagnostics``を要求せず、HTMLを生成できる問題が生じた場合は応答へ加えません。HTMLを生成できない問題は
``analysis-failed``として返します。

==== ``resources``

``ResourceInput``は、利用側アプリが取得または解決した入力だけを持ちます。全ての項目を省略できます。

[cols="2,2,2,3",options="header"]
|===
|項目 |型 |既定値 |意味

|``documents``
|``Record<string, string>``
|空のobject
|include先の論理IDとJavaScript文字列です。同じIDは一つだけ指定できます。

|``baseUri``
|``string``
|基準URIなし
|相対参照を解決する基準URIです。指定する場合は絶対URIだけを受理します。

|``safeMode``
|``"unsafe" | "server" | "safe" | "secure"``
|``"secure"``
|includeと属性処理へ適用するAsciiDoc safe modeです。

|``allowedSchemes``
|``string[]``
|空の配列
|include先として利用側アプリが許可するURI schemeです。空文字列、重複および制御文字を拒否します。

|``includes``
|``"expand" | "preserve"``
|``"expand"``
|includeを展開するか、原文のmacroとして保持するかを指定します。

|``references``
|``ResolvedReference[]``
|空の配列
|文書間参照について利用側アプリが解決した結果です。

|``assets``
|``ResolvedResource[]``
|空の配列
|画像、音声および動画について利用側アプリが解決した結果です。

|``citations``
|``ResolvedCitation[]``
|空の配列
|引用について利用側アプリが解決した結果です。

|``bibliography``
|``GeneratedBibliography | null``
|``null``
|利用側アプリが生成した参考文献です。
|===

``ResolvedReference``、``ResolvedResource``、``ResolvedCitation``および``GeneratedBibliography``は、
``status``で種類を区別します。各型の項目は生成したTypeScript宣言を参照してください。

参照と外部リソースのJSON表現および安全性の規則は、
xref:server-execution.adoc#render-inputs[変換入力]を基準とします。``documents``と解決済みの各配列には、
packageが固定する件数とバイト数の上限を適用します。解決済みの値は、JavaScript文字列をUTF-8へencodeした後の
半開区間のバイト位置で範囲を指定します。範囲外、逆順または重複して競合する値は拒否します。

=== 応答

``AnalyzeResult``は、要求したproductと同じ名前の項目だけを持ちます。要求したproductは、結果が空配列、空文字列
または``null``でも必ず存在します。要求していないproductは存在しません。

[source,javascript]
----
const result = await analyze({
  source: { text: "Paragraph." },
  products: { html: true, diagnostics: true },
});

Object.hasOwn(result, "html");        // true
Object.hasOwn(result, "diagnostics"); // true
Object.hasOwn(result, "syntax");      // false
----

TypeScript宣言では各productを省略可能な項目として表します。利用側は、要求した項目が存在することを確認してから
値を使います。応答内の項目順序は保証しません。要求した``products``の写し、構文解析回数、内部処理ごとの診断および
使用量は返しません。

=== 不正な要求

次の要求は``invalid-request``として拒否し、一部だけを採用しません。

* トップレベルまたは入れ子のobjectにある未知の項目
* ``source``または``products``の欠落と``null``
* ``source.text``の文字列以外の値
* 空の``products``
* product値の``false``、``null``、未知のproduct名およびproduct設定の未知項目
* enumに定義していない文字列、数値範囲外の値、逆順または入力外のバイト範囲
* 未知のLintルールcode、重複するschemeおよび上限を超える入力

JavaScriptでは、項目が存在しないことと値が``undefined``であることを同じ省略として扱います。JSONにない
``NaN``、``Infinity``、関数、symbolおよび循環参照は受理しません。

=== エラー

全ての公開入口は、失敗時に``AdocWeaveError``をthrowするか、そのエラーで``Promise``をrejectします。
``AdocWeaveError``は``Error``を継承し、読み取り専用の``code``を持ちます。``message``は英語の説明です。
処理で分岐する場合は``code``を使います。

[cols="2,4",options="header"]
|===
|code |条件

|``invalid-request``
|要求の形、値または組合せがこの節で定めた仕様に合いません。

|``input-limit-exceeded``
|主文書、外部入力または処理量がpackageの固定上限を超えました。

|``output-limit-exceeded``
|要求した結果がpackageの固定出力上限を超えました。

|``analysis-failed``
|診断として結果へ含められない解析または出力の失敗です。内部処理段階をcodeへ含めません。

|``cancelled``
|ブラウザーの公開clientで``AbortSignal``による取消しが完了しました。

|``analysis-in-progress``
|同じブラウザーclientで別の解析が実行中です。

|``disposed``
|破棄済みのブラウザーclientを使用しました。

|``unsupported-worker-protocol``
|同梱したJavaScriptとWebAssemblyのschema版が、Workerの起動時照合で一致しません。

|``wasm-trapped``
|WebAssemblyがtrapしました。

|``worker-failed``
|WorkerまたはWebAssemblyを初期化できない、またはWorkerの応答を検証できません。
|===

``sourceId``、バイト範囲、内部のエラー型名、RustのbacktraceおよびWorkerの``requestId``はエラーへ公開しません。
入力箇所を安全に特定できる問題は``diagnostics`` productへ含めます。``source``、応答およびエラーは
呼出しごとの所有値であり、次回の呼出しで無効になるポインタを公開しません。

=== 型と検証の正本

要求、応答およびエラーの公開型は``crates/adocweave-wasm``のRust定義が正本です。TypeScript宣言
``packages/wasm/protocol.d.mts``はここから生成します。項目、列挙値またはtag付きunionを変更する場合は、
生成物とprotocol検査を同時に更新します。

ブラウザークライアントとWASMの互換性は、WASM protocol schemaの照合で検査します。Worker内部の要求番号と
封筒の形式は公開APIに含めません。公開仕様をこの構成にした理由は
xref:adr/0042-wasm-public-contract.adoc[ADR 0042]を参照してください。
