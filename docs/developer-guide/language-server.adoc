= Language Serverの実行仕様

この文書は、``adocweave lsp``で外部から観測できるプロトコル、並行実行および失敗時の保証の正本です。
コンポーネント間の責務はxref:architecture.adoc#component-boundaries[アーキテクチャ]、
一般的な解析の実行順序はxref:server-execution.adoc[利用側アプリの実行仕様]を参照してください。
エディタへの導入方法はxref:../user-guide/release-installation.adoc[インストールと更新]を参照してください。

[#lsp-scope]
== 対応範囲

Language Serverはstdio上のLanguage Server Protocol 3.18を使用し、診断、Outline、Code Action、整形、Hover、
補完、Definition、References、Document Link、条件付きRenameおよびSemantic Tokensを提供します。
プロトコル基盤は``async-lsp``、実行環境はTokioです。これらの型と非同期処理をコアcrateへ持ち込みません。

製品が提供する通信手段はstdioだけです。ネットワーク通信は提供しません。JSON-RPCの要求IDは応答へ保持し、
通知には応答しません。未知の要求は``MethodNotFound``、既知の要求の不正な引数は``InvalidParams``とします。
未知の``$/``通知は無視し、JSON-RPC batchは受理しません。不正なJSONまたは要求objectを受け取った場合は
接続を終了します。

[#lsp-lifecycle]
== ライフサイクル

``initialize``より前の要求は``ServerNotInitialized``、重複した``initialize``と``shutdown``後の要求は
``InvalidRequest``とします。無効な状態で届いた通知は破棄します。``shutdown``後の``exit``だけを正常終了とし、
クライアントのプロセスIDが指定された場合はクライアント終了も監視します。

``initialize``ではworkspace folderを記録し、``initialized``の後に読込を開始します。初期読込を待つ間も、
開いた文書に対する要求へ応答します。

一つのLSP接続には一つの``Session``を作ります。``Session``は、開いている文書のURI、LSP文書version、
未保存本文、採用済み結果、クライアントのcapability、位置encoding、server設定、workspace folder、
検証済みの読込範囲および実行中の解析を取り消すtokenを所有します。文書、設定またはworkspace folderが
有効に変わるたびに、接続内で単調に増える入力revisionを更新します。古いLSP文書versionは本文と
入力revisionのどちらも変更しません。

プロトコルの``Backend``は通知と非同期taskを接続します。task handleと実行枠は``Backend``に置きますが、
現在の入力、取消しtokenおよび採用済み結果を重ねて所有しません。移行中のworkspace読込状態も
``Session``の非公開fieldとし、文書通知とworkspace読込結果を受け取る処理から更新します。

[#lsp-concurrency]
== 通知、要求および取消し

``didOpen``、``didChange``、``didSave``および``didClose``は受信順に適用します。文書同期はincrementalです。
一つの通知に複数の変更がある場合は、その直前の変更を適用した本文に対して順番に処理します。位置は
初期化時に合意したencodingで解釈し、UTF-8、UTF-16、LFおよびCRLFの変換にはコアの行索引を使用します。

読み取り要求とCPU解析は有界に並行実行します。新しい文書更新は同じ文書の古い解析を取り消し、待機中の処理を
入力回数に比例して蓄積しません。取消しはコアの協調的な検査点まで伝わります。

``$/cancelRequest``による取消しは``RequestCancelled (-32800)``、処理中の文書更新による取消しは
``ContentModified (-32801)``を返します。両方が発生した場合は、明示的な要求取消しを優先します。
結果を公開する直前に文書の版と設定を再確認し、古い診断、編集または応答をクライアントへ送りません。

ワーカー、スナップショットおよびロックの共通規則はxref:server-execution.adoc#asynchronous-execution[非同期実行]を
基準とします。

[#lsp-workspace]
== ワークスペースとプロジェクト設定

Language Serverはworkspace folderごとに読込範囲を設け、各文書に最も近い``.adocweave.toml``を使用します。
設定の作成、変更または削除を受け取ると、影響する開いている文書を新しい設定で解析します。設定本文と属性値を
ログへ記録しません。エディタ設定の``enabledRules``はプロジェクト設定の後に適用し、ファイルの読込範囲や処理量の上限を
広げません。

``workspace/didChangeConfiguration``は、設定の直下または``adocweave``オブジェクト内にある``debounceMs``と
``enabledRules``を受け取ります。``debounceMs``の既定値は30 msで、1,000 msを超える値は1,000 msへ制限します。
負数など型として不正な値、未知の項目または未知の診断コードを受け取った場合は現在の設定を維持し、
サーバーを停止しません。

初期走査は通知処理を止めないワーカーで行います。古くなった走査、取り消した走査および失敗した候補状態は採用せず、
走査中に開いた文書や受け取ったファイル変更を古いディスク内容で上書きしません。ファイル監視の更新は同じ文書へまとめ、
回復のための走査を同時に増やし続けません。

走査対象の除外、入れ子のworkspace root、走査件数と読込量の上限、上限超過時の部分結果および利用者への通知は
xref:../user-guide/project-configuration.adoc#workspace-scan[プロジェクト設定]を基準とします。走査対象からの除外は
includeの読込許可を変更しません。明示的に開いた文書にも走査除外を適用しません。

走査が不完全な場合は``window/showMessage``で一度通知し、同じ不完全な状態で繰り返し通知しません。この通知を
文書診断へ混在させません。完全な走査に回復した後で再発した場合は、改めて通知します。

ファイル監視の動的登録に対応するクライアントには、任意の拡張子を持つinclude先の作成も検知できるよう
``**/*``の作成、
変更および削除を購読します。ただし、未知のファイルは走査対象となる``.adoc``だけを新しい解析rootの候補とし、
既知のinclude先とプロジェクト設定以外を通知だけで読みません。通知されたURIにもworkspaceの読込範囲、symlink検査および
ファイル件数と読込量の上限を再適用します。監視登録に失敗してもサーバーを停止しません。Language Serverはネットワーク上の
リソースを取得しません。

初期走査またはプロジェクト設定の読込に失敗した場合も、``didOpen``した文書の状態は保持します。既定設定へ
切り替えて解析せず、原因を文書診断として公開します。この失敗は、部分結果を利用できる不完全な走査の
``window/showMessage``通知と区別します。

ディスク上の本文と開いている本文は別の版として保持します。文書を開いている間はエディタの本文を優先し、
閉じた後は確認済みのディスク内容へ戻します。include依存関係を保持し、変更されたリソースに依存するrootだけを
再解析します。

[#lsp-client-capabilities]
== クライアント機能

``initialize``で合意したクライアントのcapabilityは、その接続中の応答形式を決めます。クライアントが宣言していない
追加表現は送りません。

[cols="2,3",options="header"]
|===
|クライアントのcapability |応答

|Hover ``contentFormat``
|クライアントの優先順でMarkdownまたはPlain Textを選択。未指定時はplain text

|Document Symbol ``hierarchicalDocumentSymbolSupport``
|対応時は階層形式、それ以外は平坦な``SymbolInformation[]``

|Code Action literalと``isPreferredSupport``
|``quickfix``を扱えるクライアントだけに提供し、対応時だけ``isPreferred``を付与

|Workspace Edit ``documentChanges``
|対応時はversion付き``documentChanges``、それ以外は``changes``

|Publish Diagnostics ``versionSupport``
|対応時だけ文書versionを通知へ付与

|Document Link ``tooltipSupport``
|対応時だけtooltipを付与

|Semantic Tokens
|full、relative、``string``および``variable``を扱えるクライアントだけに提供

|Rename ``prepareSupport``
|対応時だけ``prepareProvider``を広告し、それ以外はbooleanのproviderを広告
|===

workspace folderに対応するクライアントにはfolder変更の購読を知らせます。対応するクライアントが
``workspaceFolders: null``を送った場合は空集合として扱い、``rootUri``へ切り替えません。未対応のクライアントだけが
``rootUri``を使用し、必要な場合に``rootPath``へ切り替えます。

[#lsp-diagnostics]
== 診断と編集

Language Serverはコアの診断とinclude元の位置との対応をLSP診断へ変換し、入力を独自にLintしません。
push diagnosticsだけを使用し、現在の文書の版を確認してから通知します。workspace全体の走査通知は
文書診断と分離します。

安全に適用できる修正候補は優先するCode Action、利用者の判断を要する候補は通常のCode Actionとして公開します。
どちらも診断と同じ文書versionにだけ適用します。

Definition、References、Document LinkおよびRenameは、採用済みの同じ解析スナップショットとソースマップを使用します。
Renameは明示したアンカーIDだけを対象とし、生成ID、複数の物理範囲へまたがる名前、既存IDと重複する変更、
参照集合を確定できない変更には編集を返しません。``prepareRename``とRenameは同じ判定を使用します。

任意schemeや製品固有の索引は``HostReferenceIndex``から読み取り専用で問い合わせます。索引の実装は同期I/Oを
行わず、古い世代の結果を返しません。索引の障害は要求の失敗として扱い、コア診断やサーバープロセスを停止しません。

[#lsp-projections]
== エディタ向け構造情報

Outline、Hover、Semantic Tokensその他の機能は、採用済みの同じ解析結果からLSP型を生成します。文書storeを
読み直したり、ソースを再解析したりしません。

Semantic Tokensはリンク、xref、アンカーID、literalおよび数式内容を意味情報から生成します。見出しmarker、
commentおよび書式delimiterなど構文だけで決まる基本色付けは各エディタのgrammarが所有します。
補完はsource block言語と現在の文書で解析済みの候補に限定し、任意schemeや開いていない文書の内容を推測しません。

プロトコルと状態遷移の検証はcrate ``adocweave-lsp``の試験を正本とします。開発版をエディタで確認する方法は
xref:zed-development.adoc[Zedで開発版を試す]と
xref:vscode-development.adoc[VS Codeで開発版を試す]を参照してください。
