= AsciiDocとの互換性

この文書では、AsciiDocの公式仕様および他のAsciiDoc実装に対するAdocWeaveの意図的な違いを説明します。
AdocWeaveはAsciiDoc全体や他実装に固有の機能の再現を目的としません。
対応範囲は xref:syntax-support.adoc[対応しているAsciiDocの書式]、
実装する文法は xref:../developer-guide/grammar.adoc[文法の詳細]に記述します。

参照する標準仕様は以下のとおりです。

* https://docs.asciidoctor.org/asciidoc/latest/[AsciiDoc Language documentation]
* https://docs.asciidoctor.org/asciidoc/latest/_exports/asciidoc-pre-spec.pdf[AsciiDoc pre-specification, 2026-02-03版]

== 意図的な違い

=== 未対応構文

``permissive``モードでは元の内容を保持し、``strict``モードでは未対応構文を含む文書の解析をエラーにします。

=== ブロックメタデータ

ブロックタイトル、ID、role、optionなどの構文を認識します。
ただし、ブロックの種類ごとに、指定した属性が利用可能かどうかを検査する機能には対応していません。

=== 文書属性参照

循環参照、展開の深さおよび展開後のバイト数に上限を設けています。
上限を超えた文書属性参照は展開せず、問題として報告します。

=== 日本語の書式認識と空白

日本語のように単語を空白で区切らない文章では、空白の省略と書式の開始・終了位置の判定を次の3つで調整します。

constrained形式（``*太字*``のような単一記号の書式）は、公式仕様ではマーカーの前後に英字または数字が
ある場合、単語内の記号と見なされ、書式として認識されません。AdocWeaveでは、日本語の文字とマーカーが
隣接する位置を単語の区切りと見なし、``*太字*と書く``のような日本語の地の文でも書式を認識します。
英字または数字と隣接する位置は、公式仕様どおり単語の内部として扱います。

段落内の改行は、仕様では空白1つに変換されます。改行の前後がどちらも日本語の文字である場合は、
空白を出力せずに行をつなぎます。ソース上で日本語の文章を改行しても、出力に不要な空白が入らないようにするためです。

inline macroは、直前に空白がなければmacroとして認識されません。
この空白の直前が日本語の文字である場合は、空白を出力しません。
macroの直後の空白と、書式記号の前後の空白は出力します。

判断に使うのは空白の直前にある地の文の文字だけで、macroの中身や、macroがHTML要素になるかどうかは
見ません。hostの機能設定で画像を無効にした場合や、相互参照を解決できなかった場合でも結果は同じです。
空白の直前が英字または数字である場合は、空白をそのまま出力します。

=== 空行を挟んだリスト項目

AsciiDocでは空行を挟んだ項目も一つのリストと認識しますが、
AdocWeaveは空行を全ブロック共通の区切りとして扱い、リストも空行で分割します。

=== インライン書式

highlight、subscript、superscript、typographic quoteを含む対応書式について、
マーカー前後の条件と、不完全なマーカーを通常の文字として扱う動作を定めています。
制約付き等幅表記の開始・終了条件を満たさない単一バッククォートの対は等幅として認識せず、
バッククォートを含む元の文字列をそのまま表示して問題を報告します。他のAsciiDoc実装と常に同じ結果になることは保証しません。

=== Passthroughと置換

passthroughは置換を抑止する内容として保持しますが、生のHTMLとして出力せずHTMLエスケープします。
任意の``subs``属性による置換段階の追加、削除および並べ替えには対応していません。

=== ブロックのroleとHTML class

roleをそのままclassにせず、利用側が許可した名前だけを``role-<name>``として出力します。
文書入力から利用側ページのstylesheetへ任意のclassが届かないようにするためです。
open blockは``div.open``、example blockは``div.example``、sidebar blockは``div.sidebar``で囲み、
他実装の``openblock, content``構造は再現しません。

=== 図表のcaption番号

titleを持つ画像block、表、example blockへ``Figure 1. ``形式の番号を付けます。
blockごとの``caption``属性による上書きには対応しません。
source/listing blockは``listing-caption``属性を設定した場合だけ番号を付けます。

=== Quoteとverse

styleなしの``____``は入れ子を許すブロックとして扱い、
``[quote,Author,Source]``だけを``blockquote``として出力します。
``[verse]``は改行を保持し、内容のインライン書式を解釈しません。

=== Admonition

admonition paragraphとadmonition blockを識別し、未知のstyleは通常のブロックとして保持します。

=== 表

PSV/CSV/DSV/TSVと対応する表示属性を扱います。AsciiDoc style cellのブロック解析はPSVを対象とし、
開始区切り直後の単一物理行と後続の空行によるheader推論に対応します。
複数物理行の先頭行は``header`` optionで明示します。

=== ソースブロック

`linenums`、`%linenums`または``options=linenums``と、同時に指定した1以上の``start``を扱います。
その他のsource option、行番号の描画、テーマおよびコピー操作には対応しません。

=== 相互参照とメディア

文書間xrefとメディアの実在確認、取得および権限検査を行わず、利用側アプリが解決結果を渡します。
メディアのactive要素にはmacro種別と一致するMIME typeを必須とし、動画のposterも独立した画像リソースとして
解決します。メディアのリンク化とアイコンset固有の表示には対応していません。

=== Preprocessor

前処理では、利用側アプリから受け取ったリソースだけを読み込みます。
同じ処理中にリソースの内容が変わることはありません。
ワイルドカードを使った複数ファイルの指定と、
URIで指定したリソースをネットワークから取得する機能には対応しません。

前処理を行わずに解析した場合、ディレクティブは評価せず、
元の文字列と``unprocessed-directive``の問題報告を残します。

=== 書誌情報と索引

bibliography anchor、footnote macroおよびindex termの構文を認識します。
ただし、書誌情報の解析・組版、citation styleによる整形およびindex rangeには対応していません。

=== Markdown互換構文

AsciiDoc標準の必須範囲ではなく、一部の他実装が提供するoptional機能には対応していません。
