= コマンドライン

``adocweave``はAsciiDoc文書の変換、確認、整形およびプレビューを行います。
入力ファイルを省略すると、標準入力を読み、結果を標準出力へ書きます。
help、診断、要約およびエラーは英語で表示します。
利用できるコマンドは``adocweave --help``、各コマンドのオプションは
``adocweave <COMMAND> --help``で確認できます。

== よく使うコマンド

[cols="1,3",options="header"]
|===
|コマンド |用途

|`adocweave convert manual.adoc`
|HTMLへ変換します。

|`adocweave view manual.adoc`
|端末で読める形に整形して表示します。

|`adocweave preview manual.adoc`
|ローカルプレビューを起動します。

|`adocweave serve dist/talk`
|生成済みスライドをローカルで配信します。

|`adocweave check manual.adoc`
|文書の問題を確認します。

|`adocweave format manual.adoc`
|整形後の内容を標準出力へ書きます。

|`adocweave symbols manual.adoc`
|見出しなどの文書構造をJSONで出力します。

|`adocweave rules`
|利用できる診断規則を表示します。
|===

``-``から始まるファイル名は、``--``より後ろへ指定します。

[source,console]
----
adocweave check -- -manual.adoc
----

== HTML変換

``convert``はHTMLを標準出力へ書き、描画時の診断を標準エラー出力へ書きます。
診断には元ファイル、行番号、UTF-8のバイト数による列番号、重要度およびcodeを表示します。
include先の診断も、その元ファイルの位置を示します。HTMLには診断を混在させません。

描画時のerrorがある場合は終了コード1、warning、informationおよびhintだけの場合は0を返します。
読み書き、引数、stylesheetおよび上限の失敗は、それぞれの終了コードを返します。
安全に描画できたHTMLは、描画時の診断がある場合も標準出力へ書きます。

``.notes``は通常HTMLでは汎用roleです。本文は保持し、``html.roles``で許可した場合だけ
CSS用の``role-notes`` classを付けます。``.notes``を非公開の指定として扱いません。

[#diagnostics]
== 診断

``check``は問題の位置、重要度、codeおよびmessageを表示します。自動処理では、変更される可能性がある
messageではなくcodeを使用してください。

出力形式は``--format human|json|github|sarif``で選びます。

[cols="1,3",options="header"]
|===
|形式
|用途と出力内容

|``human``
|端末で読むための既定形式です。問題ごとに情報を1行で表示します。

|``json``
|プログラムで処理するためのJSON配列です。問題ごとに情報をオブジェクトとして出力します。

|``github``
|GitHub Actionsが解釈できる形式です。問題を対象ファイルの該当箇所へ注釈として表示します。

|``sarif``
|静的解析結果をほかのツールへ渡すためのSARIF 2.1.0形式です。1回の実行結果をJSON文書として出力します。
|===

include先の問題も、元ファイルのパス、行番号および行内の位置で表示します。

[source,console]
----
adocweave check --fail-on warning --format json --summary docs
adocweave check --fail-on warning --format github docs
adocweave check --fail-on warning --format sarif docs > adocweave.sarif
----

``--summary``は重要度別の件数を標準エラー出力へ書きます。診断本体の出力には影響しません。

=== 診断規則

主な規則は次のとおりです。

[cols="2,4",options="header"]
|===
|code |内容

|``asciidoc-file-link``
|AsciiDoc文書を``link``で参照した場合に``xref``を提案します。

|``non-asciidoc-xref``
|AsciiDoc以外のファイルを``xref``で参照した場合に``link``を提案します。

|``macro-boundary``
|inline macroの直前に空白が必要な場合に報告します。既定では無効です。

|``monospace-boundary``
|単一バッククォートによる等幅表記の開始または終了条件に問題がある場合に報告します。
|===

既定で無効な規則は``--enable-rule CODE``で有効にできます。利用可能な規則は次のコマンドで確認できます。

[source,console]
----
adocweave rules
adocweave rules --format json
adocweave check --enable-rule macro-boundary document.adoc
----

[#check-exit-status]
=== 終了状態

``--fail-on error``はerrorがある場合、``--fail-on warning``はerrorまたはwarningがある場合に終了コード1を返します。
既定値は``error``です。``--fail-on never``では、診断の重要度を終了コードへ反映しません。

[cols="1,4",options="header"]
|===
|コード |意味

|0
|処理が完了し、指定した重要度以上の診断がありません。

|1
|指定した重要度以上の診断があります。

|2
|引数またはオプションに問題があります。

|3
|ファイル、ストリームまたはリソースの読み書きに失敗しました。

|4
|入力サイズまたはリソースの上限を超えました。
|===

=== ローカル参照の確認

通常の``check``は、参照先が実在するかを確認しません。相対リンク、文書間参照、画像およびinclude先を
確認する場合は、``--project-root``で確認を許可するディレクトリを指定します。

[source,console]
----
adocweave check --project-root . docs/manual.adoc
----

参照先は記述元ファイルの親ディレクトリを基準に解決し、
``--project-root``で指定したディレクトリの外側へ移動する参照を拒否します。
標準入力から読み込んだ文書の相対参照は、``--project-root``で指定したディレクトリを基準に解決します。
絶対パス、外部URL、文書内アンカーおよびscheme付き参照は確認対象外です。

一意な参照先の確認件数は``resources.max-files``までです。
上限を超えると``local-target-limit-exceeded``を報告します。
macOSとWindowsで信頼できない文書を確認する場合は、
書換え不能なワークスペースへコピーしてから実行してください。

[#formatting]
== 整形

``format``は整形結果を標準出力へ書き、入力ファイルを変更しません。
複数入力では``--check``、`--diff`または``--write``のいずれかを指定します。

[source,console]
----
adocweave format --check docs
adocweave format --diff --glob 'docs/**/*.adoc'
adocweave format --write docs README.adoc
----

ディレクトリを指定すると``.adoc``ファイルを再帰的に処理します。symlinkはたどりません。
``--write``は書換え直前に元ファイルが変更されていないことを確認し、ファイル単位で置換します。

整形するのは、安全に意味を保てる段落、空行、行末空白および改行です。
sourceブロック、数式、macro、インライン書式、見出し、属性、アンカー、リスト
および不完全な構文は元の内容を保ちます。

== 安全な自動修正

``check --fix``は、常に安全と判定された修正だけを適用します。
修正範囲が重なる場合は、そのファイルを変更せずエラーにします。
変更内容を確認するには``--diff``を併用します。この場合はファイルを書き換えません。

[source,console]
----
adocweave check --fix docs
adocweave check --fix --diff --summary docs
----

[#multi-file-updates]
== 複数ファイルの書換え

``format --write``と``check --fix``は、すべての変更内容を確定してから、ファイルごとに一時ファイルへ
書き込み、元ファイルを置き換えます。一つのファイルに不完全な内容は残しません。

複数ファイル全体の一括更新は保証しません。途中の置換に失敗しても、それまでに更新したファイルを
元へ戻しません。実行結果と終了コードを確認してください。

== 色とshell completion

``--color auto|always|never``で、``human``形式の診断結果、差分および``view``の出力に色を付ける条件を
指定します。既定の``auto``は、標準出力がterminalで、かつ環境変数``NO_COLOR``が空でない値に設定されて
いない場合だけ色を付けます。``--color always``は``NO_COLOR``より優先します。
JSON、GitHub Actions annotationおよびSARIFには色を付けません。

completion scriptは標準出力からshellの設定へ保存します。

[source,console]
----
adocweave completion bash
adocweave completion zsh
adocweave completion fish
adocweave completion powershell
----

== ローカルファイルの展開

``convert``、``view``、`check`および``symbols``は、``include::``で指定したローカルファイルを既定で
展開します。
展開しない場合は``--no-include``を指定します。設定で無効にした展開を一度だけ有効にする場合は``--include``を
指定します。

[source,console]
----
adocweave convert docs/manual.adoc
adocweave convert --no-include docs/manual.adoc
----

ファイル入力では、root文書の親ディレクトリを基準にinclude先を解決します。標準入力では``--stdin-base``が必要です。
許可するディレクトリを追加する場合は``--allow-root``を複数回指定できます。相対パスは現在のディレクトリを
基準に解決します。``..``がファイルシステムのrootを越える指定は、意図より広いディレクトリを許可することに
なるため拒否します。

[source,console]
----
adocweave convert --include --stdin-base docs --allow-root docs - < root.adoc
----

絶対パス、`..`、scheme付きtarget、制御文字および許可したディレクトリの外側を指すsymlinkは拒否します。
ネットワーク上のリソースは取得しません。

個別のリソースは10 MiB、全体は50 MiB、ファイル数は10,000件までです。循環、includeの深さ、展開後の要素数と
バイト数にも上限があります。``format``はroot文書だけを整形し、include先へ書き戻しません。

[#terminal-view]
== 端末表示

``view``は、文書を端末の幅に合わせて整形し、標準出力へ書きます。見出し、段落、リスト、表、admonition、
引用およびソースブロックは、字下げ、行頭の記号および罫線で区別します。装飾がなくても構造が読めるため、
パイプやリダイレクトでもそのまま利用できます。

[source,console]
----
adocweave view manual.adoc
adocweave view --width 100 docs/README.adoc
cat manual.adoc | adocweave view -
----

折返しの桁数は次の順で決まります。

. ``--width``で指定した桁数
. 環境変数``COLUMNS``
. 標準出力が端末の場合はその幅
. 既定の80桁

``--width``が受け付けるのは20桁から1000桁までです。字下げが深い場合でも、本文は20桁を下回らず、
必要ならその行だけが指定した桁数を超えます。読めない幅へ押し込めないためです。

色は``--color``で指定します。既定の``auto``では、標準出力が端末で、かつ環境変数``NO_COLOR``が
空でない値に設定されていない場合だけ色を付けます。``--color always``は``NO_COLOR``より優先します。

端末で表現できない要素は、内容が失われたと分かる形に置き換えます。

* 画像、動画および音声は``[Image: 説明]``のように、そこに何があるかを示す1行にします。
* 数式は評価も描画もせず、原文をそのまま表示します。
* ソースブロックは、言語の指定がある場合に色分けします。行番号の指定がある場合は行番号を添えます。
* 表で縦に結合したセルは、先頭の行に内容を置き、続く行を空欄にします。端末に縦の結合を描く手段がないためです。
* 表が指定した桁数に収まらない場合は列の幅を詰めます。それでも収まらない場合は、列を3桁より狭くせず、
  表が幅を超えることを許します。
* リンクは表示文字列を出します。辿れる形にできない場合は、URLを後ろへ併記します。
* 脚注は本文中へ``[1]``のような番号を置き、文書の所定の位置へ番号と本文の一覧を出します。
* 目次は移動できないため、リンクにはせず字下げで階層を示します。

出力先が先に閉じた場合は、失敗ではなく正常終了として扱います。
``adocweave view manual.adoc | head``のように先頭だけを読む使い方のためです。

画面に収まらない長さの文書は、環境変数``PAGER``が指すプログラムへ渡します。``PAGER``が未設定の場合は
``less``を使い、色をそのまま通す指定と、1画面に収まる場合はそのまま表示する指定を与えます。

[source,console]
----
adocweave view --pager never manual.adoc
adocweave view --pager always manual.adoc
PAGER='less -S' adocweave view manual.adoc
----

既定の``auto``は、標準出力が端末で、かつ組み立てた行数が画面の高さを超える場合だけpagerを起動します。
``PAGER``を空文字列に設定した場合と、pagerを起動できなかった場合は標準出力へ書きます。pagerへ渡す場合も
読むのは人であるため、色を付ける条件は端末へ書く場合と同じです。

対応した端末では、リンクを文字列のまま辿れる形で出力します。``--hyperlinks``で条件を変えられます。

[source,console]
----
adocweave view --hyperlinks never manual.adoc
----

既定の``auto``は、出力が端末に届き、かつ環境変数``TERM``が``dumb``でない場合に辿れる形にします。この
形式を知らない端末は何も表示しません。辿れる形にできるURLは本文へ併記せず、``http``と``https``以外の
URLのように辿れる形にできないものだけを併記します。読み手が見ることも辿ることもできないURLを残さない
ためです。辿れることと色が付くことは別の条件で決まります。

配色は、読む端末の背景に合わせて選べます。既定の``dark``は暗い背景、``light``は明るい背景を前提に
した色です。

[source,console]
----
adocweave view --theme light manual.adoc
----

``.adocweave.toml``の``[terminal]``でも指定でき、``--theme``はその指定より優先します。見出しやリンク
などの役割ごとに色を選ぶこともできます。設定の書き方は
xref:project-configuration.adoc#terminal-colors[プロジェクト設定]を参照してください。

``[source,rust]``のように言語を指定したソースブロックは、コメント、文字列、数値、キーワード、呼び出す
名前および定義する名前を色分けします。色はthemeに合わせて変わります。対応していない言語と、言語の指定が
ないブロックは、ブロック全体を1色で表示します。色を付けない場合は色分けも行いません。

== ローカルプレビュー

通常の``preview``は完全なHTML文書をプレビュー用の画面内で表示し、既定では``127.0.0.1:4000``で配信します。表示されたURLをブラウザーで
開いてください。終了するには kbd:[Ctrl+C]を押します。

[source,console]
----
adocweave preview manual.adoc
adocweave preview --port 8080 --css theme.css manual.adoc
----

ポートを自動選択する場合は``--port 0``を指定します。起点文書、include先、CSSおよびプロジェクト設定の変更は自動的に反映されます。
連続した変更をまとめる待ち時間は``--debounce-ms``で指定できます。

既定では同じ端末からだけ接続できます。ほかの端末から接続できるようにするには
``--bind ADDRESS --allow-external``を指定します。プレビューには利用者認証とTLSによる暗号化がないため、
信頼できないネットワークへ公開しないでください。

== 完全なHTML文書とCSS

``convert``は既定でHTML fragmentを出力します。完全なHTML文書を生成するには``--complete``を指定します。
``--css``と``--css-url``は``--complete``と併用し、複数回指定できます。

[source,console]
----
adocweave convert --complete --css theme.css --css-url https://example.com/print.css manual.adoc
----

CSSの指定はプロジェクト設定と合わせて16件までです。CSSファイルはUTF-8で、1件あたり1 MiBまでです。
symlinkのCSSファイル、安全でない内容、許可されていないURLおよび上限を超えたCSSは拒否します。

[#revealjs-slides]
== reveal.jsスライド

AsciiDocの本文から、ローカルで開けるスライド一式を生成します。生成先の``index.html``をブラウザーで開くと、
同梱したreveal.jsとCSSで表示します。表示時に外部のJavaScriptやフォントを取得しません。
``public``出力はファイルとしても開けます。発表者画面は、以下の``preview``または``serve``によるローカルHTTP配信を使ってください。

[source,console]
----
adocweave convert talk.adoc --to revealjs --output dist/talk
adocweave convert talk.adoc --to revealjs --output dist/talk --audience presenter
----

``--output``は必須です。``--complete``と``--css-url``は併用できません。
通常の``convert``は引き続きHTML fragmentを標準出力へ書き出します。

``--css FILE``とプロジェクト設定の``html.stylesheet-files``には、UTF-8のローカルCSSを指定できます。
固定のテーマの後に、指定順で適用します。ファイル数と内容の上限は通常のHTML出力と同じです。
CSS内の``@import``や``url()``が指定する資産は探索・コピーせず、その表示を保証しません。
外部のstylesheet URLを指定した設定は拒否します。

文書タイトルと``==``見出しが横方向のスライド、``===``見出しが直前の``==``スライドに属する縦方向のスライドになります。
``====``以降はスライド内の見出しです。``[%notitle]``をスライド見出しへ付けると表示だけを隠し、参照用IDを保持します。
明示的なIDは``[#method]``形式で指定します。本文の参照リンクは、参照先のスライドと段階表示へ移動します。

通常の順序なし・順序付きリストへ``[%step]``を付けると、直下の項目を順番に表示します。
通常のopenブロックへ付けると、そのブロック全体を一度に表示します。子リストへの個別指定、stepの入れ子、
inlineの段階表示、追加の効果および表示順の数値指定は診断します。
``[.columns]``をスライド見出しへ付け、その直下へ``[.column]``を付けたopenブロックを2つ置くと、等幅の2列になります。

``[.notes]``を付けた通常のopenブロックは発表者ノートです。既定の``public``出力ではノートとノート専用の図を除外します。
``presenter``出力はノートを保持し、``S``キーで発表者画面を開きます。通常のHTML変換では``notes`` roleの本文を保持します。
共有用には``public``のスライド出力を使います。本文からノート専用IDへの参照は診断し、保存しません。

図は、許可されたローカルディレクトリから取得したPNG、JPEG、GIF、WebPおよびSVGに対応します。
ノートを除外した後に、表示する図だけを読み込みます。図の生成ファイル名は内容のhashから作り、原稿のファイル名を含めません。
SVGは図形、文字、ローカルIDへの参照および限定したCSSを検証して保存します。DOCTYPE、script、イベント属性、
foreignObject、外部参照およびCSSによる外部資産の取得には対応しません。

LaTeX数式と外部の書誌データを使う引用には、別途Node.js 24.19.0以降と補助プログラムが必要です。
これらを含まない原稿では、補助プログラムを起動しません。npmから導入する場合は、以下の``X.Y.Z``を
公開済みの版へ置き換えてください。

[source,console]
----
npm install --global --ignore-scripts @adocweave/slides-helper@X.Y.Z
adocweave convert talk.adoc --to revealjs --output dist/talk \
  --bibliography references.json --csl-style style.csl --csl-locale locale.xml
----

公開前の補助を使う場合は、リポジトリの``packages/slides-helper``へ``npm ci --ignore-scripts``で依存を導入し、
その``bin.mjs``を``--slides-helper``へ指定してください。詳しい導入方法は
xref:release-installation.adoc#slides-helper-installation[スライド用補助パッケージの導入]を参照してください。

``--bibliography``にはCSL JSONの配列、``--csl-style``と``--csl-locale``にはCSLのXMLファイルを指定します。
CSLで整形する引用がある場合にだけ、3つのファイルを読み込みます。3つの指定をすべて省略すると、
表示する引用の全キーが手書きの書誌定義へ解決する場合に限り、補助プログラムなしで描画します。
いずれかを指定した場合は全引用をCSLで処理し、3つすべての入力を必要とします。
同じ生成内で手書き定義への引用とCSLで整形する引用を混在させることには対応しません。
生成した参考文献は本文の最後に1枚だけ追加します。
発表者ノートの参考文献は、最後の原稿スライドのノートへ1回だけ掲載します。
同じキーの手書きの書誌項目と外部の引用を混在させると診断します。手書きの``[bibliography]``本文はそのまま描画します。
引用処理を使ったスライドには、本文とは別の領域に処理ライブラリーの帰属を表示し、ライセンスを同梱します。

LaTeX数式は静的SVGに変換し、原TeXも保持します。AsciiMathには対応しません。
``:stem: latexmath``と``:eqnums:``を使うと、``stem``記法にLaTeXを選び、AMS環境の式番号を有効にできます。
独自のLaTeXマクロは``--math-macros FILE``へJSON配列で渡します。
各要素の``name``と``definition``は必須で、引数を使う場合は``arguments``、既定の引数は``default``で指定します。
本文とノートはそれぞれ別に処理し、その間のLaTeX参照の解決は保証しません。
脚注は各スライドの末尾に置き、本文とノートの番号を分けます。ノートの追加によって本文の図表や脚注の番号は変わりません。
脚注本文の数式と引用は、本文・ノートそれぞれの処理範囲で、最初の脚注参照の位置へ原稿の順番で加え、一度だけ処理します。
同じ脚注を繰り返す場合は確定済みの内容を再利用し、配置先ごとに参照用IDを分けます。
脚注内の数式への外側からの参照は最初の掲載先へ移動し、同じ脚注内の参照はその配置内へ移動します。
ノートは本文の脚注定義を使用できますが、本文からノート専用の脚注定義は使用できません。
脚注本文内のanchorと書誌定義には対応しません。脚注の外で定義し、脚注から参照してください。

補助プログラムの明示的な指定には``--slides-helper FILE``を使います。
指定がなければ環境変数``ADOCWEAVE_SLIDES_HELPER``、次に``PATH``上の既知の実行名を調べます。
Windowsの標準的なnpmインストールにも対応します。独自の配置では、実行ファイルか``bin.mjs``を明示してください。
``public``で除外したノートだけに数式や引用がある場合は、そのためのデータファイルや補助プログラムを読み込みません。

出力先は新規か空の専用ディレクトリ、またはAdocWeaveのmanifestと全ファイルの内容が一致するディレクトリに限ります。
``.``、ファイルシステムのルート、原稿・include元のディレクトリ、symlinkを含むパスは拒否します。
手書きのファイルや生成後に編集されたファイルを検出すると、その内容を保持して更新を中止します。
``presenter``から``public``へ更新すると、不要になったノート専用資産も削除します。保存や削除に失敗した場合は成功を返しません。

=== スライドのプレビューと配信

編集中のスライドを表示するには、``preview``へ``--to revealjs``を指定します。
既定は``presenter``で、出力先ディレクトリの指定は不要です。共有用の表示確認には``--audience public``を使います。
数式・引用の入力とローカルCSSは``convert``と同じオプションで指定できます。

[source,console]
----
adocweave preview talk.adoc --to revealjs
adocweave preview talk.adoc --to revealjs --audience public --css research.css
adocweave serve dist/talk --port 8080
----

スライドのプレビューでは、スライド本体を配信したページで表示します。
原稿や、表示に使うinclude・図・CSS・数式と引用の入力ファイルを変更すると、表示を更新します。
生成に失敗した場合は診断を表示し、最後に成功したスライドと資産一式を保持します。
更新後は見出しIDと段階表示の位置をURLから復元します。表示中の段階を削除した場合は残った段階へ補正し、
表示中の見出しIDを削除した場合は先頭のスライドへ戻ります。

``serve``は保存済みのmanifestと全ファイルの内容を検証してから配信します。
原稿、補助プログラムおよび引用の入力ファイルは不要です。内容を更新する場合は``convert``で生成し直してください。
``serve``は起動時の生成物を配信し続けます。更新した生成物を配信するには``serve``を再起動してください。
``--bind``、``--port``および``--allow-external``の指定は通常のプレビューと共通です。
