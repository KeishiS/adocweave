[#nix-installation]
== Nixによる導入

一時的に実行する場合は``nix run``を使用します。
結果を再現できるようにする場合は、タグまたはコミットを指定します。

[source,console]
----
nix run github:KeishiS/adocweave -- --version --json
nix run 'github:KeishiS/adocweave?ref=vX.Y.Z' -- convert document.adoc
nix run github:KeishiS/adocweave -- lsp
----

利用者のprofileへ導入する場合は次のコマンドを使用します。

[source,console]
----
nix profile install github:KeishiS/adocweave
nix profile upgrade AdocWeave
nix profile rollback
nix profile remove AdocWeave
----

継続して使用する場合は、flake inputを利用側の``flake.lock``へ固定し、
``adocweave.packages.${system}.default``を使用します。
このパッケージには``adocweave``が含まれます。Language Serverは``adocweave lsp``で起動します。

Linuxでは、リリースタグを指定すると``https://keishis.cachix.org``からビルド済みパッケージを取得できます。

[source,nix]
----
nix.settings = {
  extra-substituters = [ "https://keishis.cachix.org" ];
  extra-trusted-public-keys = [
    "keishis.cachix.org-1:j3UwGrrgTifYMa9Uo6fyDU8GEJBcorOzrHdkXBXruK4="
  ];
};
----

NixOS以外では、同じ値をシステムの``nix.conf``へ記載します。

== 配布物の選択

ネイティブ実行ファイルと次の追加成果物は、``vX.Y.Z``タグのGitHub Releaseから取得します。

[cols="2,2,2,2",options="header"]
|===
|用途
|Linux
|macOS
|Windows

|CLIとLanguage Server
|``adocweave-<target>.zip``
|``adocweave-<target>.zip``
|``adocweave-x86_64-pc-windows-msvc.zip``

|VS Code拡張
3+|``adocweave-vscode-<version>.vsix``

|textlint用Processor
3+|``adocweave-textlint-plugin-asciidoc-<version>.tgz``
|===

``<target>``には次のいずれかを指定します。

* Linux ARM64: ``aarch64-unknown-linux-musl``
* Linux x86-64: ``x86_64-unknown-linux-musl``
* macOS ARM64: ``aarch64-apple-darwin``
* Windows x86-64: ``x86_64-pc-windows-msvc``

32-bit環境、Windows ARM64およびIntel macOS向けの実行ファイルは配布しません。
macOSは14.0以降、WindowsはWindows 10 version 1809以降を対象とします。

macOSとWindowsの実行ファイルにはOSのコード署名を行っていないため、実行時に警告が表示される場合があります。
macOSでGatekeeperに拒否された場合は、後述する検証を完了してから、信頼すると判断した実行ファイルだけの
quarantine属性を削除してください。親ディレクトリへ再帰的に適用しないでください。

[source,console]
----
xattr -d com.apple.quarantine "$ROOT/bin/adocweave"
----

== 取得したファイルの検証

バージョンと配布ファイルを決め、そのバージョンのReleaseにある``sha256.sum``と一緒に
空のディレクトリへダウンロードします。次の例では``VERSION``と``ASSET``を置き換えてください。

[source,console]
----
VERSION=X.Y.Z
ASSET=adocweave-x86_64-unknown-linux-musl.zip
mkdir "adocweave-$VERSION"
gh release download "v$VERSION" \
  --repo KeishiS/adocweave \
  --pattern "$ASSET" \
  --pattern sha256.sum \
  --dir "adocweave-$VERSION"
cd "adocweave-$VERSION"
sha256sum --check --ignore-missing sha256.sum
----

続いて、配布ファイルと``sha256.sum``のArtifact Attestationを確認します。

[source,console]
----
gh attestation verify "$ASSET" --repo KeishiS/adocweave
gh attestation verify sha256.sum --repo KeishiS/adocweave
----

チェックサムでファイルの内容を、Artifact Attestationで配布元を確認できます。

Release画面から手動で保存した場合は、配布ファイルを正常に展開できることも確認してください。

== native実行ファイルの導入

=== LinuxとmacOS

次の例ではバージョン別のディレクトリへ配置し、``current``シンボリックリンクで使用するバージョンを選びます。

[source,console]
----
VERSION=X.Y.Z
TARGET=x86_64-unknown-linux-musl
PREFIX="$HOME/.local"
ROOT="$PREFIX/lib/adocweave/$VERSION"

mkdir -p "$ROOT/bin" "$PREFIX/bin"
mkdir "native-$VERSION"
unzip "adocweave-$TARGET.zip" -d "native-$VERSION"
install -m 0755 "native-$VERSION/adocweave" "$ROOT/bin/adocweave"

ln -sfn "$ROOT" "$PREFIX/lib/adocweave/current"
ln -sfn "$PREFIX/lib/adocweave/current/bin/adocweave" "$PREFIX/bin/adocweave"
----

``$HOME/.local/bin``が``PATH``に含まれていない場合は、シェルの起動ファイルへ追加します。導入後は次を確認します。

[source,console]
----
command -v adocweave
adocweave --version --json
adocweave lsp --help
----

補完用ファイルは xref:command-line.adoc[コマンドライン]の``adocweave completion``で生成できます。

複数の利用者が使用する端末では、``$PREFIX``を``/opt/adocweave``、
実行ファイルへのシンボリックリンクを``/usr/local/bin``へ配置します。
検証と展開は通常利用者で行い、配置だけを管理者権限で実行してください。

=== Windows

検証済みZIPをバージョン別のディレクトリへ展開し、
実行ファイルのディレクトリを利用者の``PATH``へ追加します。

[source,powershell]
----
$Version = "X.Y.Z"
$Target = "x86_64-pc-windows-msvc"
$Root = Join-Path $env:LOCALAPPDATA "AdocWeave\$Version"
New-Item -ItemType Directory -Force $Root | Out-Null
Expand-Archive "adocweave-$Target.zip" $Root
& (Join-Path $Root "adocweave.exe") --version --json
& (Join-Path $Root "adocweave.exe") lsp --help

$ManagedRoot = [Regex]::Escape((Join-Path $env:LOCALAPPDATA "AdocWeave\"))
$Previous = [Environment]::GetEnvironmentVariable("Path", "User") -split ";" |
  Where-Object { $_ -and $_ -notmatch "^$ManagedRoot" }
$Next = @($Root) + $Previous
[Environment]::SetEnvironmentVariable("Path", ($Next -join ";"), "User")
$env:Path = $Next -join ";"
Get-Command adocweave.exe
----

更新時は別のバージョン別ディレクトリへ展開し、動作確認後に``PATH``を切り替えます。
ロールバックする場合は、以前の``$Version``を指定して``PATH``の更新部分を再実行します。

== 更新とロールバック

新しいバージョンは既存のディレクトリへ上書きせず、別のディレクトリへ展開して検証します。
LinuxとmacOSでは``current``、Windowsでは``PATH``を切り替えた後に``--version --json``を確認してください。
ロールバックの確認が終わるまで、以前のディレクトリは削除しません。

WebAssemblyパッケージは独立したバージョンを持ち、npm Registryから取得します。ほかの配布物は
``vX.Y.Z``タグのバージョンを使用します。
エディタ拡張は起動時に実行ファイルのバージョンを比較せず、LSPの初期化で利用できる機能を判断します。

[#textlint-plugin-installation]
== textlint用Processorの導入

``@adocweave/textlint-plugin-asciidoc``はnpm registryから導入します。
対応環境はNode.js 24.19.0以上とtextlint 15.8系です。

[source,console]
----
npm install --save-dev textlint@15.8.0 \
  @adocweave/textlint-plugin-asciidoc@X.Y.Z
----

``.textlintrc.json``ではProcessorと文章規則を別々に指定します。
文章規則のパッケージも開発用依存へ追加してください。

..textlintrc.json
[source,json]
----
{
  "plugins": ["@adocweave/asciidoc"],
  "rules": {
    "preset-ja-technical-writing": true
  }
}
----

既定では``.adoc``、``.asciidoc``および``.asc``を認識します。

[source,console]
----
npx textlint "docs/**/*.{adoc,asciidoc,asc}"
----

includeの展開と自動修正には対応しません。

更新時は``package.json``のバージョンを変更し、``npm install``を実行します。
ロールバックする場合は以前のバージョンを指定するか、``package-lock.json``を戻して``npm ci``を実行します。
削除は次のコマンドで行います。

[source,console]
----
npm uninstall --save-dev @adocweave/textlint-plugin-asciidoc
----

[#wasm-npm-installation]
== WebAssemblyパッケージの導入

npmから導入する場合は、使用するバージョンを指定します。

[source,console]
----
npm install @adocweave/wasm@X.Y.Z
----

ブラウザでは``@adocweave/wasm``を、Node.jsでは``@adocweave/wasm/direct``をimportします。
APIの詳細はxref:../developer-guide/core-profile.adoc#wasm-api[WebAssembly API]を参照してください。

更新する場合はバージョンを変更して``npm install``を実行します。削除は次のコマンドで行います。

[source,console]
----
npm uninstall @adocweave/wasm
----

[#browser-library-deployment]
== WebAssemblyライブラリの配備

npmで導入した``@adocweave/wasm``の``worker``と``wasm``ディレクトリを、相対位置を保って静的配信します。
公開APIは``worker/index.mjs``、TypeScriptの型定義は``worker/index.d.mts``です。

[source,javascript]
----
import { AdocWeaveClient, defaultAssetUrls } from "./worker/index.mjs";

const entryUrl = new URL("./worker/index.mjs", import.meta.url);
const client = new AdocWeaveClient(defaultAssetUrls(entryUrl));
const result = await client.analyze({
  source: { text: "= Title\n\nText\n" },
  products: {
    html: { documentMode: "fragment" },
    diagnostics: true,
  },
});
console.log(result.html, result.diagnostics);
----

バンドラを使用する場合も、``defaultAssetUrls``には公開先へコピーした``worker/index.mjs``のURLを指定します。
APIの詳細は
xref:../developer-guide/core-profile.adoc#wasm-api[WebAssembly API]を参照してください。

[cols="2,3",options="header"]
|===
|拡張子
|Content-Type

|``.mjs``、``.js``
|``text/javascript``

|``.wasm``
|``application/wasm``

|``.html``
|``text/html; charset=utf-8``
|===

これらのファイルは同じオリジンから配信します。CSPでは少なくとも
``script-src 'self' 'wasm-unsafe-eval'``、``worker-src 'self'``および``connect-src 'self'``を許可します。
HTML結果をDOMへ挿入する場合は、利用側で内容を検証し、表示用sandboxを適用してください。

[#editor-language-server]
== エディタからLanguage Serverを使う

VS Code拡張とZed拡張は、必要なLanguage Serverを自動取得します。VS Code拡張は取得時にチェックサムを
確認しますが、Zed拡張は確認しません。Artifact Attestationはどちらも確認しません。

自分で検証した版や特定の版を使用する場合は、この文書の手順で``adocweave``を導入し、エディタの設定へ
その実行ファイルの絶対パスを指定してください。``PATH``上にある``adocweave``も自動取得より優先されます。
どの経路で選んだ場合も、拡張は``adocweave lsp``として起動します。

[#zed-installation]
=== Zedへの導入

ZedのExtensions画面から``AsciiDoc``と``AdocWeave``を導入します。``AsciiDoc``拡張は言語認識と構文強調、
``AdocWeave``拡張はLanguage Serverとの接続を提供します。

ソースから使用する場合は``AsciiDoc``拡張を導入した後、リポジトリを取得し、``Install Dev Extension``または
``zed: install dev extension``から``editors/zed``を選択します。

Language Serverの場所を指定する場合は、``lsp.adocweave.binary.path``へ絶対パスを設定します。
指定がなければ``PATH``を確認し、見つからない場合は最新の安定版GitHub Releaseから対応するネイティブ実行ファイルを
取得します。拡張とネイティブ実行ファイルのバージョンは一致していなくても構いません。

[#vscode-installation]
=== VS Codeへの導入

Open VSX RegistryまたはVisual Studio Marketplaceから``adocweave.adocweave-vscode``を導入できます。
発行者は``adocweave``です。

[source,console]
----
codium --install-extension adocweave.adocweave-vscode
code --install-extension adocweave.adocweave-vscode
----

ReleaseのVSIXを使用する場合は、チェックサムとArtifact Attestationを確認してから導入します。特定の
バージョンへ固定する場合もこの方法を使用します。

[source,console]
----
code --install-extension "adocweave-vscode-$VERSION.vsix" --force
----

Language Serverの場所を指定する場合は、machine scopeの``adocweave.server.path``へ絶対パスを設定します。
設定の変更後は``AdocWeave: Restart Language Server``で再起動してください。

更新時は新しいVSIXを同じコマンドで導入し、ウィンドウを再読み込みします。ロールバックする場合は、以前の
Releaseから検証済みVSIXを取得して導入します。

== 削除

Zedではdev extensionを、VS Codeでは拡張画面または次のコマンドで拡張を削除します。

[source,console]
----
code --uninstall-extension adocweave.adocweave-vscode
----

LinuxとmacOSでは、導入したバージョンとAdocWeaveが管理するシンボリックリンクだけを削除します。

[source,console]
----
VERSION=X.Y.Z
PREFIX="$HOME/.local"
rm "$PREFIX/bin/adocweave"
rm "$PREFIX/lib/adocweave/current"
rm -rf "$PREFIX/lib/adocweave/$VERSION"
rmdir --ignore-fail-on-non-empty "$PREFIX/lib/adocweave"
----

``$PREFIX/bin``やエディタの保存領域全体を再帰的に削除しないでください。別のバージョンを残す場合は、先に
``current``をそのバージョンへ切り替えます。

Windowsでは利用者の``PATH``からAdocWeaveのディレクトリだけを除き、対象バージョンのディレクトリを削除します。

[source,powershell]
----
$ManagedRoot = [Regex]::Escape((Join-Path $env:LOCALAPPDATA "AdocWeave\"))
$Next = [Environment]::GetEnvironmentVariable("Path", "User") -split ";" |
  Where-Object { $_ -and $_ -notmatch "^$ManagedRoot" }
[Environment]::SetEnvironmentVariable("Path", ($Next -join ";"), "User")
Remove-Item -Recurse (Join-Path $env:LOCALAPPDATA "AdocWeave\$Version")
----
