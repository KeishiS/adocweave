= インストールと更新

この文書では、GitHub ReleasesからCLI、Language Serverおよびtextlint用AsciiDoc Processorを導入し、
更新および削除する手順を説明します。

Rustツールチェーンおよびソースの取得を行わない場合はGitHub Releaseを、Nixを利用する場合はflakeを使用できます。
GitHub Release archiveとNixパッケージは別の配布経路であり、Nixパッケージはarchiveを再包装せず、ソースからbuildします。

この文書は複数の導入経路を扱います。全体を順に読む必要はありません。目的に応じて次の節へ進んでください。

[cols="2,3"]
|===
| 目的 | 読む節

| 自分の端末でCLIを使う（Nix）
| <<nix-installation>>

| 自分の端末でCLIを使う（Nixを使わない）
| 「配布物の選択」「取得と完全性の検証」「利用者単位の導入」

| 複数の利用者が使う端末へ導入する
| 「配布物の選択」「取得と完全性の検証」「システム全体への導入」

| Webアプリへ組み込む
| <<browser-library-deployment>>

| エディターで使う
| <<zed-installation>>、<<vscode-installation>>

| AsciiDoc文書をtextlintで検査する
| <<textlint-plugin-installation>>
|===

いずれの経路でも、導入前に「取得と完全性の検証」のchecksumとattestationの確認を行ってください。

[#nix-installation]
== Nixによる導入

一時的にCLIを実行する場合は次のコマンドを使用します。再現性が必要な場合はtagまたはコミットを指定します。

[source,console]
----
nix run github:KeishiS/adocweave -- --version --json
nix run 'github:KeishiS/adocweave?ref=vX.Y.Z' -- convert document.adoc
nix run github:KeishiS/adocweave#adocweave-lsp
----

利用者profileへ導入する場合は次のコマンドを使用します。

[source,console]
----
nix profile install github:KeishiS/adocweave
nix profile upgrade AdocWeave
nix profile rollback
nix profile remove AdocWeave
----

継続的に利用する構成では、flake inputを利用側の``flake.lock``へ固定し、
``adocweave.packages.${system}.default``を使用します。同じパッケージに``adocweave``と
``adocweave-lsp``が含まれます。``adocweave.overlays.default``から``pkgs.adocweave``として参照することもできます。
専用のNixOS service moduleは提供しません。

Nixパッケージは``Cargo.lock``に固定したソースからbuildします。Rust compiler、Cargo、Node.js、Chromiumおよび
fuzz toolは完成したパッケージのruntime closureへ含めません。

stable releaseの公開時には、tagと同じcommitでbuildしたx86_64-linuxとaarch64-linux向けパッケージの
runtime closureをbinary cache``https://keishis.cachix.org``へpushしています。利用側で次のsubstituterと
公開鍵を設定し、flake inputをrelease tagのcommitへ固定すると、Rust buildを実行せずにパッケージを取得できます。

[source,nix]
----
nix.settings = {
  extra-substituters = [ "https://keishis.cachix.org" ];
  extra-trusted-public-keys = [
    "keishis.cachix.org-1:j3UwGrrgTifYMa9Uo6fyDU8GEJBcorOzrHdkXBXruK4="
  ];
};
----

NixOS以外では、system全体の``nix.conf``へ同じ``extra-substituters``と``extra-trusted-public-keys``を
記載します。cacheへpushするのはrelease tagのcommitだけです。tag以外のcommitを使う場合や、利用側flakeで
``inputs.adocweave.inputs.nixpkgs.follows``のようにinputを差し替えた場合はderivationが変わるため取得できず、
利用側でRust buildが実行されます。

== 配布物の選択

[cols="2,2,2,2",options="header"]
|===
|用途 |Linux |macOS |Windows

|CLI
|`adocweave-cli-<target>.zip`
|`adocweave-cli-<target>.zip`
|`adocweave-cli-x86_64-pc-windows-msvc.zip`

|Language Server
|`adocweave-lsp-<target>.zip`
|`adocweave-lsp-<target>.zip`
|`adocweave-lsp-x86_64-pc-windows-msvc.zip`

|browser library
3+|`adocweave-browser-<version>.tar.xz`

|Zed開発拡張
3+|`adocweave-zed-<version>.tar.xz`

|VS Code拡張
3+|`adocweave-vscode-<version>.vsix`

|textlint用AsciiDoc Processor
3+|`adocweave-textlint-plugin-asciidoc-<version>.tgz`
|===

targetはLinux ARM64の``aarch64-unknown-linux-musl``、Linux x86-64の``x86_64-unknown-linux-musl``、
macOS ARM64の``aarch64-apple-darwin``、Windows x86-64の
``x86_64-pc-windows-msvc``です。32-bit環境とWindows ARM64向けのnative archiveは配布しません。
Intel macOSも対応対象外です。

Linux musl binaryは静的linkします。macOSは14.0以降、WindowsはWindows 10 version 1809以降を対象とし、
system libraryへ動的linkします。macOSとWindowsのbinaryにはOS code signingを行っていないため、
download元に応じてOSの警告が表示される場合があります。

macOSでは展開後にquarantine属性を確認できます。

[source,console]
----
xattr -p com.apple.quarantine "$ROOT/bin/adocweave" || true
xattr -p com.apple.quarantine "$ROOT/bin/adocweave-lsp" || true
----

実行がGatekeeperにより拒否された場合は、checksumとattestationが正しいことを先に確認します。そのうえで
配布元を信頼すると判断した実行ファイルだけからquarantine属性を削除します。この操作はOSの保護を弱めるため、
親ディレクトリへ再帰的に適用しません。

[source,console]
----
xattr -d com.apple.quarantine "$ROOT/bin/adocweave"
xattr -d com.apple.quarantine "$ROOT/bin/adocweave-lsp"
----

== 取得と完全性の検証

製品、バージョンおよび利用するarchiveを固定し、その製品のReleaseにある``sha256.sum``とともに空の
ディレクトリへdownloadします。GitHub CLIを使う例は次のとおりです。``PRODUCT``、``VERSION``および
``ASSET``を実際の値へ置き換えます。

[source,console]
----
VERSION=X.Y.Z
PRODUCT=adocweave-cli
ASSET=adocweave-cli-x86_64-unknown-linux-musl.zip
mkdir "adocweave-$VERSION"
gh release download "$PRODUCT/v$VERSION" \
  --repo KeishiS/adocweave \
  --pattern "$ASSET" \
  --pattern sha256.sum \
  --dir "adocweave-$VERSION"
cd "adocweave-$VERSION"
sha256sum --check --ignore-missing sha256.sum
----

GitHub CLIを使わない場合は、Release画面から各assetを個別に保存します。HTMLをarchive名で保存する事故を避けるため、
download後にnative archiveでは``unzip -t <archive>``、browserとZedのarchiveでは
``tar -tJf <archive>``、textlint用パッケージでは``tar -tzf <archive>``も成功することを確認します。
``curl | sh``形式のinstallerは提供しません。

checksumとは別に、必要なassetのGitHub Artifact Attestationを検証します。

[source,console]
----
gh attestation verify "$ASSET" \
  --repo KeishiS/adocweave
gh attestation verify sha256.sum --repo KeishiS/adocweave
----

checksumは取得したbyte列が配布時の値と一致することを示します。attestationは、そのbyte列が対象リポジトリの
GitHub Actionsから生成された来歴を示します。いずれも、成果物に脆弱性や悪意ある処理がないことまでは保証しません。

[#textlint-plugin-installation]
== textlint用AsciiDoc Processorの導入

``@adocweave/textlint-plugin-asciidoc``はnpm registryへ公開しません。検証したGitHub Releaseのtarball URLと
対応するtextlintを、利用するプロジェクトの開発用依存として固定します。

[source,console]
----
VERSION=X.Y.Z
RELEASE_URL="https://github.com/KeishiS/adocweave/releases/download/adocweave-textlint%2Fv$VERSION"
npm install --save-dev textlint@15.8.0 \
  "$RELEASE_URL/adocweave-textlint-plugin-asciidoc-$VERSION.tgz"
----

対応環境はNode.js 22.18.0以上27未満とtextlint 15.8.0です。パッケージの``engines``と
``peerDependencies``にも同じ範囲を記録します。パッケージにはNode.js用WebAssemblyを同梱するため、
Rust、Cargo、``wasm-bindgen``、AdocWeave CLIおよび実行時の追加downloadは不要です。

プロジェクトへ依存を導入せずに一度だけ試す場合は、``npx``の``--package``で必要な三つのパッケージを
一時的に取得できます。次の例は、日本語技術文書向けの規則で``document.adoc``を検査します。

[source,console]
----
VERSION=X.Y.Z
RELEASE_URL="https://github.com/KeishiS/adocweave/releases/download/adocweave-textlint%2Fv$VERSION"
PLUGIN="$RELEASE_URL/adocweave-textlint-plugin-asciidoc-$VERSION.tgz"
npx --yes \
  --package=textlint@15.8.0 \
  --package="$PLUGIN" \
  --package=textlint-rule-preset-ja-technical-writing@12.0.2 \
  textlint --no-textlintrc \
  --plugin @adocweave/asciidoc \
  --preset ja-technical-writing \
  document.adoc
----

この方法では作業ディレクトリへ``package.json``、``package-lock.json``および``node_modules``を作成しません。
取得したパッケージはnpmのキャッシュへ保存されます。継続して利用する場合は、依存とバージョンを
``package.json``と``package-lock.json``へ記録してください。

公開工程では、Releaseの実URLから同じ単発実行を行い、取得したarchiveが公開checksumの対象と一致することを
公開後に検査します。

``.textlintrc.json``では、AsciiDoc Processorと利用する規則を別々に指定します。次の例では、規則のパッケージも
利用側で開発用依存へ追加します。

[source,json]
----
{
  "plugins": ["@adocweave/asciidoc"],
  "rules": {
    "preset-ja-technical-writing": true
  }
}
----

既定では``.adoc``、``.asciidoc``および``.asc``を認識します。別の拡張子をAsciiDocとして扱う場合は、
pluginの``extensions``へ先頭の``.``を含む名前を追加します。

[source,json]
----
{
  "plugins": {
    "@adocweave/asciidoc": {
      "extensions": [".guide"]
    }
  }
}
----

見出し、block title、段落、リスト、引用、表、リンク、属性参照やinline記法を含まないfootnote本文、
画像の代替文、iconの代替文またはtitle、audioとvideoのtitleおよびinline装飾を文章規則へ渡します。
block titleはdepth 1の``Header``としてtitle向け規則の対象にします。
code、UI macro、表示文字列のないURL、数式、属性参照、passおよび未対応構文は``Code``として保持し、``Str``を
対象とする文章規則から除外します。属性参照またはinline記法を含むmacroの文章部分も保守的に除外します。
includeは展開せず、入力した一つの物理ファイルだけを検査します。

[source,console]
----
npx textlint "docs/**/*.{adoc,asciidoc,asc}"
----

このProcessorは自動修正に対応しません。規則が修正情報を返してもProcessorが除去するため、
``npx textlint --fix``を実行してもAsciiDoc文書を変更しません。問題の検出と元の文書上の行・列の報告だけを
利用してください。

更新時は新しいReleaseのtarball URLへ変更して``npm install``を実行し、``package-lock.json``の差分と検査結果を
確認してから統合します。rollbackでは以前の検証済みURLへ戻し、lockfileから依存を再導入します。tarballと
同梱WebAssemblyを別々のバージョンへ変更することはできません。削除する場合は次を実行します。

[source,console]
----
npm uninstall --save-dev @adocweave/textlint-plugin-asciidoc
----

== 利用者単位の導入

以下ではバージョン別のディレクトリを基準とし、`current` symlinkで選択したバージョンを固定します。この構成なら、
更新中に旧バージョンを壊さずrollbackできます。

[source,console]
----
VERSION=X.Y.Z
TARGET=x86_64-unknown-linux-musl
PREFIX="$HOME/.local"
ROOT="$PREFIX/lib/adocweave/$VERSION"

mkdir -p "$ROOT/bin" "$PREFIX/bin" "$PREFIX/share/adocweave/$VERSION"
mkdir "cli-$VERSION" "lsp-$VERSION"
unzip "adocweave-cli-$TARGET.zip" -d "cli-$VERSION"
unzip "adocweave-lsp-$TARGET.zip" -d "lsp-$VERSION"
install -m 0755 "cli-$VERSION/adocweave" "$ROOT/bin/adocweave"
install -m 0755 "lsp-$VERSION/adocweave-lsp" "$ROOT/bin/adocweave-lsp"
tar -xJf "adocweave-browser-$VERSION.tar.xz" -C "$PREFIX/share/adocweave/$VERSION"
mv "$PREFIX/share/adocweave/$VERSION/adocweave-browser-$VERSION" \
  "$PREFIX/share/adocweave/$VERSION/browser"
tar -xJf "adocweave-zed-$VERSION.tar.xz" -C "$PREFIX/share/adocweave/$VERSION"
mv "$PREFIX/share/adocweave/$VERSION/adocweave-zed-$VERSION" \
  "$PREFIX/share/adocweave/$VERSION/zed"

ln -sfn "$ROOT" "$PREFIX/lib/adocweave/current.new"
mv -Tf "$PREFIX/lib/adocweave/current.new" "$PREFIX/lib/adocweave/current"
ln -sfn "$PREFIX/lib/adocweave/current/bin/adocweave" "$PREFIX/bin/adocweave"
ln -sfn "$PREFIX/lib/adocweave/current/bin/adocweave-lsp" "$PREFIX/bin/adocweave-lsp"
----

``$HOME/.local/bin``が``PATH``にない場合だけshellの起動ファイルへ追加し、新しいshellで確認します。

[source,console]
----
command -v adocweave
command -v adocweave-lsp
adocweave --version --json
adocweave-lsp --version --json
----

配布archiveはcompletionのファイルを自動配置しません。必要なshellでは
xref:command-line.adoc[コマンドライン]の``adocweave completion``で生成してください。

== システム全体への導入

複数利用者向けには、上の手順の``$PREFIX``を``/opt/adocweave``へ、symlinkの置き場所を``/usr/local/bin``へ
読み替えます。archiveの検証と展開は通常利用者で行い、検証済みのファイルの配置だけを管理者権限で実行します。
既存のファイルを上書きする前に、symlinkの参照先がAdocWeave管理下であることを確認します。

browser library、Zed拡張およびVS Code拡張は利用者ごとの設定を伴うため、原則としてuser-local配置を使用します。

=== Windowsへの導入

PowerShellで検証済みZIPをバージョン別のディレクトリへ展開し、そのディレクトリを利用者の``PATH``へ追加します。

[source,powershell]
----
$Version = "X.Y.Z"
$Target = "x86_64-pc-windows-msvc"
$Root = Join-Path $env:LOCALAPPDATA "AdocWeave\$Version"
New-Item -ItemType Directory -Force $Root | Out-Null
Expand-Archive "adocweave-cli-$Target.zip" (Join-Path $Root "cli")
Expand-Archive "adocweave-lsp-$Target.zip" (Join-Path $Root "lsp")
& (Join-Path $Root "cli\adocweave.exe") --version --json
& (Join-Path $Root "lsp\adocweave-lsp.exe") --version --json

$ManagedRoot = [Regex]::Escape((Join-Path $env:LOCALAPPDATA "AdocWeave\"))
$Previous = [Environment]::GetEnvironmentVariable("Path", "User") -split ";" |
  Where-Object { $_ -and $_ -notmatch "^$ManagedRoot.*\\(cli|lsp)$" }
$Next = @((Join-Path $Root "cli"), (Join-Path $Root "lsp")) + $Previous
[Environment]::SetEnvironmentVariable("Path", ($Next -join ";"), "User")
$env:Path = $Next -join ";"
Get-Command adocweave.exe
Get-Command adocweave-lsp.exe
----

更新時は新しいバージョン別のディレクトリを作成して動作確認後に``PATH``を切り替えます。rollbackでは以前の
バージョンを``$Version``へ指定して同じ``PATH``更新部分を再実行します。実行中の``.exe``を上書きせず、VS Codeと
Zedを終了してから不要なバージョン別のディレクトリだけを削除します。

Windowsから完全に削除する場合は、上記と同じ正規表現でAdocWeave管理下の2 entryだけを利用者``PATH``から
除き、導入したバージョン別のディレクトリを削除します。

[source,powershell]
----
$ManagedRoot = [Regex]::Escape((Join-Path $env:LOCALAPPDATA "AdocWeave\"))
$Next = [Environment]::GetEnvironmentVariable("Path", "User") -split ";" |
  Where-Object { $_ -and $_ -notmatch "^$ManagedRoot.*\\(cli|lsp)$" }
[Environment]::SetEnvironmentVariable("Path", ($Next -join ";"), "User")
Remove-Item -Recurse (Join-Path $env:LOCALAPPDATA "AdocWeave\$Version")
----

== 更新、バージョン固定およびロールバック

新しいバージョンは既存ディレクトリへ上書きせず、別のディレクトリへ展開・検証します。``current``を切り替えた後に
``--version --json``を確認します。rollbackは``current``を以前のバージョン別のディレクトリへ戻すだけであり、動作確認が終わるまで
旧ディレクトリを削除しません。CLI、Language Server、Browser、Zed拡張、VS Code拡張およびtextlint用
Processorは、それぞれ独立した製品バージョンを持ちます。Browserとtextlint用Processorは、同じ製品archiveに
JavaScriptとWebAssemblyを同梱するため、別々に組み合わせません。エディター拡張とLanguage Serverの
製品バージョンを一致させる必要はありません。利用できる機能は、接続時に交換する標準LSP capabilityから決まります。

[#browser-library-deployment]
== ブラウザーライブラリーの配備

``$HOME/.local/share/adocweave/<version>/browser``をそのまま静的hostingへ配置します。公開入口は
``worker/index.mjs``だけです。``worker/worker.mjs``とWASM補助ファイルは内部用であり、直接importしません。
TypeScriptの型定義は``worker/index.d.mts``にあります。

[source,javascript]
----
import { AdocWeaveClient, defaultAssetUrls } from "./worker/index.mjs";

const client = new AdocWeaveClient({
  ...defaultAssetUrls(),
  onResult(result) {
    console.log(result.html, result.diagnostics);
  },
  onError(error) {
    console.error(error.code, error.message);
  },
});

client.update({
  version: 1,
  source: "= Title\n\nText\n",
  renderPolicy: { documentMode: "fragment" },
});
----

``update``は単調増加するgenerationを返します。``cancel``は現在の処理を無効化し、``dispose``はclientを
終了します。bundlerから利用する場合は、配備した``worker/index.mjs``のbase URLを
``defaultAssetUrls``へ渡します。WebAssembly APIの詳細は
xref:../developer-guide/core-profile.adoc#wasm-api[WebAssembly API]を参照してください。

serverは少なくとも次を設定します。

[cols="2,3",options="header"]
|===
|対象 |Content-Type

|`.mjs`、`.js`
|`text/javascript`

|`.wasm`
|`application/wasm`

|`.html`
|`text/html; charset=utf-8`
|===

協調cancelに``SharedArrayBuffer``を使う場合、main document、WorkerおよびWASMを含む同一contextへ
``Cross-Origin-Opener-Policy: same-origin``と``Cross-Origin-Embedder-Policy: require-corp``を設定します。使えない環境では
Worker再生成へ縮退します。CSPは``script-src 'self'``、``worker-src 'self'``を基本とし、inline scriptや``unsafe-eval``を
要求しません。HTML結果はDOMへ無検証で挿入せず、ホストの表示sandboxとpolicyを適用します。

URLにはバージョンまたはarchive digestを含め、WASMとJavaScriptへ同じcache keyを使います。更新時に既存URLの内容を
置換せず、新URLへ切り替えます。配備前のarchiveは``sha256.sum``で検証し、配備後はserverから取得したファイルのdigestを
deploy記録へ残します。展開物の``example/index.html``と``example/app.mjs``はリアルタイム変換の最小例であり、同じserverから
配信して入力更新、最新generationだけの表示およびfallback動作を確認できます。

[#editor-language-server]
== エディターからLanguage Serverを使う

VS Code拡張とZed拡張はLanguage Serverを同梱せず、download、導入、更新および削除を行いません。
先にこの文書の「配布物の選択」「取得と完全性の検証」と、利用環境に応じた導入手順に従って
``adocweave-lsp``を導入してください。エディター拡張とLanguage Serverは独立した製品であり、
更新とrollbackも別々に行います。

拡張は次の順序でLanguage Serverを探します。

. エディターで有効な設定に明示した絶対path
. エディターprocessから見える``PATH``上の``adocweave-lsp``
. この文書を参照する導入案内

三つ目は実行ファイルを自動取得する処理ではありません。見つからない場合は導入案内を表示し、Language Serverを
起動しません。エディターをGUIから起動すると、shellの起動ファイルで設定した``PATH``が反映されない場合があります。
その場合はエディターを起動する環境へ``PATH``を設定するか、導入した実行ファイルの絶対pathを利用者設定へ記載します。

VS Codeでは設定をmachine scopeに限定し、未信頼ワークスペースに対して拡張自体を起動しません。Zedでは本体の
Worktree Trustに従います。未信頼worktreeではZedがproject設定を適用せず、Language Serverを起動しません。
信頼したworktreeではproject設定の絶対pathも候補になります。拡張にはZedの信頼判定を迂回する処理を設けません。

拡張はLSPの初期化時にLanguage Serverが返す標準capabilityから、診断、補完および定義への移動などの
利用可能な機能を判断します。拡張とLanguage Serverの製品バージョンや``lspApiVersion``の一致は要求しません。
標準capabilityがない機能はeditorのLSP clientが有効にしません。初期化できない場合だけ起動失敗として理由を表示します。

[#zed-installation]
== Zedへの導入

Zed Extension Galleryへ公開しないため、展開済み``$HOME/.local/share/adocweave/<version>/zed``をdev extensionとして
導入します。Extension Galleryの``Install Dev Extension``またはコマンドパレットの``zed: install dev extension``から、この
ディレクトリを選びます。ソースリポジトリの取得は不要です。

[#zed-language-server-selection]
=== ZedのLanguage Server選択

Zedでは``lsp.adocweave.binary.path``へ導入済み実行ファイルの絶対pathを指定できます。指定しない場合は、
Zed processから見える``PATH``を使用します。``binary.arguments``と``binary.env``は使用せず、引数なしで起動し、
環境変数はZedがworktreeへ提供するshell環境を使用します。

更新時は新しいバージョンのZed ディレクトリを別に展開し、dev extensionをそのディレクトリへ再設定します。旧ディレクトリは、新しいバージョンの
拡張と、別に更新したLanguage Serverでeditor機能を確認するまで保持します。

[#vscode-installation]
== VS Codeへの導入

Open VSX Registryを利用できる環境では、editorの拡張画面から``adocweave.adocweave-vscode``を導入できます。
公式の発行者はnamespace``adocweave``です。同じ名前のほかのnamespaceが現れた場合は、
https://open-vsx.org/extension/adocweave/adocweave-vscode[公式の拡張ページ]で発行者を確認してください。
Open VSXへ公開するfileは、同じReleaseへ添付したVSIXと同一です。

[source,console]
----
codium --install-extension adocweave.adocweave-vscode
----

Visual Studio Marketplaceへは公開しないため、Visual Studio Code本体では同じReleaseの
``adocweave-vscode-<version>.vsix``を検証して手動で導入します。

[source,console]
----
code --install-extension "adocweave-vscode-$VERSION.vsix" --force
----

VS CodeのExtensions viewにAdocWeaveと対象バージョンが表示されることを確認します。更新時は新しいバージョンの
VSIXを同じcommandで導入し、Windowを再読込します。rollbackでは以前のVS Code拡張製品のReleaseから
検証済みVSIXを取得し、同じ方法で導入します。拡張とLanguage Serverの製品バージョンを一致させる必要はありません。

[#vscode-language-server-selection]
=== VS CodeのLanguage Server選択

VS Codeではmachine scopeの``adocweave.server.path``へ導入済み実行ファイルの絶対pathを指定できます。
未信頼ワークスペースでは拡張を起動しません。Language Serverの再起動には
``AdocWeave: Restart Language Server``を使用します（拡張のコマンド名は英語です）。

[#legacy-editor-managed-cache-removal]
=== 旧拡張が残したLanguage Serverキャッシュの削除

managed downloadに対応していた旧版の拡張は、更新後に使用されないLanguage Serverをeditorの保存領域へ残す場合があります。
VS Code拡張を更新する前なら、旧版で``adocweave.server.download``を``false``にしてから
``AdocWeave: Remove Managed Language Server``を実行します。自動取得を無効にしてから削除することで、
Language Serverの再起動時に同じキャッシュが再作成されることを防ぎます。

すでに更新した場合はeditorを終了し、VS Codeでは拡張のglobal storageにある
``adocweave.adocweave-vscode/servers``、ZedではAdocWeave拡張のworking ディレクトリにある
``adocweave-lsp-<version>-<target>``形式のディレクトリを手動で削除します。VS Codeでは削除前に``servers``内の
``.adocweave-vscode-managed-cache`` marker、Zedでは対象ディレクトリ内の``verified.json``を確認してください。
markerと同じ親ディレクトリだけを削除し、editorのglobal storageまたは拡張用working ディレクトリ全体は削除しません。
このキャッシュを削除しても、利用者が別途``PATH``または任意のディレクトリへ導入したLanguage Serverは削除されません。

== 削除

Zedでは最初にExtension GalleryからAdocWeave dev extensionを削除し、Zedを終了します。VS CodeではExtensions viewまたは
次のcommandで拡張を削除してVS Codeを終了します。旧拡張のmanaged cacheが残っている場合は、前節の手順で削除します。

[source,console]
----
code --uninstall-extension adocweave.adocweave-vscode
----

続いて、導入したバージョンを指定してAdocWeave管理対象だけを削除します。

[source,console]
----
VERSION=X.Y.Z
PREFIX="$HOME/.local"
rm "$PREFIX/bin/adocweave" "$PREFIX/bin/adocweave-lsp"
rm "$PREFIX/lib/adocweave/current"
rm -rf "$PREFIX/lib/adocweave/$VERSION"
rm -rf "$PREFIX/share/adocweave/$VERSION"
rmdir --ignore-fail-on-non-empty "$PREFIX/lib/adocweave" "$PREFIX/share/adocweave"
----

`$PREFIX/bin`、Zed user data全体または共有親ディレクトリを再帰削除してはいけません。別のバージョンを保持する場合は``current``を
先にそのバージョンへ切り替え、該当するバージョンだけを削除します。通常profileに残るZedの一般キャッシュはZedが所有するため、場所を
推測して削除せず、ZedのUIから拡張を削除します。完全に隔離したprofileで試験した場合だけprofile ディレクトリ全体を削除します。
