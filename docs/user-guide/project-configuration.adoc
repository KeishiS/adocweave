= プロジェクト設定

AdocWeaveは、CLIとLanguage Serverで共通の``.adocweave.toml``を使用します。設定ファイルは処理対象の
ディレクトリから親へ探索し、起動時のワークスペースルートまたはCLIの作業ディレクトリで探索を停止します。
最も近い設定ファイルを一つだけ使用し、複数のファイルを処理する場合はファイルごとに探索します。設定の継承、
環境変数とチルダの展開、外部ファイルの読み込みおよびネットワークアクセスは行いません。

探索を停止する位置は、いずれも利用者が与えた根です。Language Serverではエディターが開いている
workspace folder、CLIではコマンドを実行した作業ディレクトリです。処理対象がその根の外にある場合、
設定ファイルは適用しません。作業ディレクトリの外にあるファイルへ設定を適用したい場合は``--config FILE``で
明示してください。

設定ファイルの読み込みには1 MiBの上限があります。設定ファイルが記述するのは根、上限および規則の設定であり、
この大きさを超えることはありません。上限を超えるファイルは読み込まずにエラーとします。

最小の設定は次のとおりです。

[source,toml]
----
schema-version = 2
----

不明な項目、未対応の``schema-version``、絶対パス、親ディレクトリへ移動するパスおよび上限を超える値は
エラーになります。設定内の相対パスは設定ファイルのディレクトリを基準にします。設定ファイルはワークスペース外への
ファイルシステム権限を与えず、CLIとLanguage Serverが独立して定めたワークスペース境界内でだけ使用できます。
``--config``でワークスペース外の設定ファイルを明示した場合も、外部から読み込むのは設定本文だけです。その設定に
記載した``roots``、``project-root``およびstylesheetがワークスペース外にある場合、対象機能を使用するとエラーに
なります。外部のファイルを利用する場合は、``--allow-root``、``--project-root``または``--css``で明示してください。

== 設定例

[source,toml]
----
schema-version = 2

[analysis]
syntax-mode = "strict"

[analysis.attributes.release]
value = "draft"

[analysis.attributes.private]
unset = true

[lint.rules.macro-boundary]
enabled = true
severity = "error"

[lint]
max-line-length = 100
max-consecutive-blank-lines = 1
max-diagnostics = 1000

[resources]
include = true
roots = ["docs"]
max-files = 1000
max-total-bytes = 52428800
max-resource-bytes = 10485760

[workspace.scan]
exclude = ["**/generated"]

[local-targets]
enabled = true
project-root = "docs"

[format]
newline = "lf"
final-newline = true
max-consecutive-blank-lines = 1

[html]
complete = true
stylesheet-files = ["styles/manual.css"]
stylesheet-urls = ["https://example.com/manual.css"]
roles = ["definition", "theorem"]
----

属性は``value``または``unset = true``のどちらか一方を指定します。値は解析とinclude前処理の両方へ
同じhard-locked属性として渡されます。``config show``は属性値を表示せず、setまたはunsetの状態だけを
表示します。

``lint.rules.CODE``では、組込み規則ごとに``enabled``と``severity``を指定できます。既定で有効な規則の
無効化と重要度変更、および既定で無効な規則の有効化を同じ形式で行います。不明なcodeはエラーです。

``html.roles``は、HTML出力で``role-<name>`` classとして残すblock roleの名前を列挙します。文書に書いた
roleのうち列挙していないものは出力しません。名前にはASCIIの英数字、``-``および``_``だけを使えます。

``resources.include``は、``include::``で指定した文書を読み込んで展開するかどうかを決めます。既定値は
``true``です。設定ファイルを置いていない場合も同じです。読み込める範囲は``roots``、ワークスペース境界
およびファイルシステムの権限が決めるため、この項目は範囲を広げません。include先を読ませたくない場合は
``include = false``を指定します。

リソース上限は組込み上限以下にだけ設定できます。`roots`、``project-root``およびstylesheetのファイルは
設定ディレクトリ内の相対パスに限定されます。ネットワーク経由のincludeは設定できません。
一つの処理が保持できるfilesystem rootは128件までです。多数の下位ディレクトリを許可する場合は、必要な範囲を
含む上位ディレクトリへまとめてください。この上限は``max-files``とは別に適用します。

[#workspace-scan]
``workspace.scan.exclude``は、Language Serverがワークスペースを最初に走査するときに、内容を調べない
ディレクトリを指定します。

次の四つは組込みの除外patternとして常に適用します。``.adocweave.toml``自体を置いていない場合も同じです。

[source,toml]
----
exclude = ["**/.git", "**/.venv", "**/node_modules", "**/target"]
----

いずれも版管理の内部データ、仮想環境、導入済みパッケージおよびビルド結果で、AsciiDoc文書を置く場所では
ありません。一方で件数は多く、これらだけで10万件の走査上限に達することがあります。パッケージやcrateごとに
同名のディレクトリを持つ構成があるため、既定値はどの深さにも一致する``**/``付きにしています。

``workspace.scan.exclude``には、この四つへ追加するpatternだけを書きます。例えば生成した文書をどの深さでも
除外する場合は``exclude = ["**/generated"]``と指定します。空のリストは追加patternがないことを表し、組込みの
四つは解除しません。同じpatternを複数回書いた場合と組込みpatternを再び書いた場合は、一度だけ適用します。
実際に適用されているpatternは``adocweave config show``で確認できます。

各patternはワークスペースのルートからの相対位置に対して照合します。区切りには
OSにかかわらず``/``を使います。``*``と``?``は一つのディレクトリ名の中だけに一致し、単独の``**``は
0個以上のディレクトリに一致します。例えば``target``はルート直下だけ、``**/target``はどの深さの
``target``にも一致します。照合では大文字と小文字を区別します。
workspace folderが入れ子になっている場合、内側のfolderは外側の走査では展開せず、内側のfolder自身の
``workspace.scan.exclude``を使って走査します。

走査が10万件の上限に達した場合は、そこまでに見つけた文書を解析の起点として登録し、エディターへ警告
メッセージを1回送ります。ワークスペースは動作し、開いている文書は通常どおり解析します。見つからなかった
文書も、開けば解析し、include先としても読み込めます。警告を解消するには``workspace.scan.exclude``へ
除外するディレクトリを追加してください。

同じ扱いを``resources``の上限にも適用します。あるプロジェクトの``max-files``、``max-total-bytes``または
``max-resource-bytes``が、そのプロジェクト内の文書数に足りない場合、初期走査は読み込めた文書までを登録し、
上限を設けている設定ファイルを名指しした同じ警告を送ります。ワークスペース全体やほかのプロジェクトは
影響を受けません。文書を開いたときの解析では、これらの上限は従来どおり適用します。include先を含めて
上限を超える文書は、開いた時点でエラーになります。

この警告は文書の診断ではなく、``window/showMessage``によるメッセージとして送ります。走査が終えられなかった
ことはワークスペース全体の事情であり、特定の文書に原因があるわけではないためです。同じ原因が続く間は
最初の1回だけ送ります。完全な走査に戻った後で同じ原因が再発した場合と、workspace folderを変更した場合は、
新しい状態としてもう一度送ります。ディレクトリ項目数の上限とプロジェクトのresource上限が同時に原因と
なった場合や、複数のプロジェクトがresource上限に達した場合は、一つの警告に原因の種類、該当する
プロジェクト数および先頭の設定ファイルをまとめます。

除外するディレクトリ自体は走査件数に数えますが、その中身は列挙せず、10万件の走査上限にも数えません。
この設定は初期走査の対象だけを狭めます。除外したディレクトリ内の文書でも、エディターで明示的に開いた場合、
初期走査後の編集を含めてinclude先として必要になった場合、またはCLIへ入力として渡した場合は通常どおり
読み込みます。file watcherは既知の文書とinclude先を更新しますが、通知だけを理由に除外範囲の新しい文書を
解析対象へ追加しません。許可範囲内のinclude先がまだ存在しない場合やUTF-8として読み込めない場合は、作成または
修復の通知を受けた時点で読み直します。絶対パス、``..``、
``\\``区切り、空の区間、単独の区間ではない``**``、文字クラス``[]``および選択肢``{}``は指定できません。
patternは1件あたり1024文字、全体で4096文字までです。Unix上で名前をUTF-8として表せないディレクトリは
通常の文字patternには一致しませんが、``**``はその階層を通過します。

JSON Schemaはlink:../../config/adocweave.schema.json[`config/adocweave.schema.json`]です。
このSchemaは、項目名、型、列挙値、未知の項目の拒否、既定値および項目単位の上限を表します。
相対パスにはOSに依存しない``/``区切りを使います。``\``区切り、絶対パス、drive名および
親ディレクトリへ移動する``..``は指定できません。
ただし``max-resource-bytes``が``max-total-bytes``を超えないという条件と、除外patternの合計が4096文字を
超えないという条件は、複数の項目をまとめて計算するためJSON Schemaでは表現できません。これらの条件は
実行時に検出します。

``format.newline``と``format.final-newline``を省略した場合は、入力文書の改行形式と末尾改行の有無を
維持します。特定の形式へ統一するときだけ明示してください。

== CLIでの選択

通常は設定を自動探索します。明示的な設定ファイルを使う場合は``--config FILE``、探索を停止して既定値を
使う場合は``--no-config``を指定します。この二つは同時に指定できません。解決済み設定は次のcommandで
確認できます。

[source,console]
----
adocweave config show
adocweave config show --config config/ci.toml
----

優先順位は組込み既定値、プロジェクト設定、明示的なCLI optionの順です。例えば``--allow-root``を
指定すると設定の``resources.roots``ではなくCLIのroot集合を使用し、``--complete``は設定にかかわらず
完全なHTML文書を選択します。

== Language Serverでの使用

Language Serverはworkspace folderごとに設定探索を停止し、文書ごとに最も近い設定を使用します。
``.adocweave.toml``の作成、変更または削除を監視し、open文書を新しい設定generationで再解析します。
解析中に設定が変わった場合、古い結果は採用しません。不正な設定を既定値へ置き換えず、設定のエラーが
解消するまで、その設定に依存する診断、整形および問い合わせ結果を公開しません。

初期走査の除外設定には、各workspace folderの直下にある``.adocweave.toml``だけを使用します。
走査を始める前にこの設定を読み込む必要があるためです。下位ディレクトリに別の設定がある場合も、
``workspace.scan``以外の項目は従来どおり文書に最も近い設定から解決します。

エディターが通常ファイルをworkspace folderとして渡した場合は、そのファイルだけを解析の起点として
読み込みます。親ディレクトリは設定探索とファイルアクセスの検証範囲に使用しますが、同じディレクトリ以下の
``.adoc``ファイルを初期走査しません。include先のファイルも読み込む必要がある場合は、親ディレクトリを
workspace folderとして開いてください。

エディターの``enabledRules``はプロジェクト設定の後に適用します。これにより、共有設定を維持したまま
個別のエディターで追加のopt-in規則を有効にできます。
