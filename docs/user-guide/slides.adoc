= スライドの作成

AsciiDocの原稿から、reveal.jsで表示するスライドを作成します。
原稿を編集しながらブラウザーで確認し、発表者ノート付きで発表したり、ノートを除いたHTMLやPDFを配布したりできます。
このガイドでは、補助プログラムを使わない短い原稿から始め、数式、引用、見た目の調整へ進みます。

* 初回の操作：xref:#slides-start[最初のスライド]
* 原稿の記法：xref:#slides-authoring[原稿の構成]、xref:#slides-math-citations[数式と引用]
* 見た目の変更：xref:#slides-css[CSSによるデザイン調整]
* 発表と配布：xref:#slides-preview[プレビューと配信]、xref:#slides-export[HTMLの生成と配布]、xref:#slides-pdf[PDF保存]

== 前提

CLIの導入方法はxref:release-installation.adoc[インストールと更新]を参照してください。
以下では、導入した``adocweave``を端末から実行できる状態を前提にします。
ソースから試す場合は、開発環境を用意したリポジトリ内で、各コマンドの``adocweave``を
``cargo run -p adocweave --``へ置き換えてください。
原稿とCSSのパスは、コマンドを実行するディレクトリから指定します。

本文、図、表、脚注だけの原稿には、スライド用補助プログラムは不要です。
LaTeX数式や外部の文献データを使う引用を追加する場合は、
xref:release-installation.adoc#slides-helper-installation[スライド用補助パッケージの導入]も参照してください。
生成したHTMLを見る側に補助プログラムは必要ありません。

[#slides-start]
== 最初のスライド

サンプルのlink:../../examples/slides/talk.adoc[``talk.adoc``]と
link:../../examples/slides/theme.css[``theme.css``]を同じ作業ディレクトリへコピーし、
そのディレクトリを端末で開いてください。ソースからCLIを実行する場合は、リポジトリ内に作業ディレクトリを作ります。
次のコマンドで、原稿とCSSの変更が反映されるプレビューを起動します。

[source,console]
----
adocweave preview talk.adoc --to revealjs --css theme.css
----

端末に表示されたURLをブラウザーで開き、矢印キーでスライドを進めてください。
``talk.adoc``の本文を変更して保存すると、表示が更新されます。
プレビューは既定で発表者用（``presenter``）です。``S``キーでノートを表示する発表者画面を開けます。
終了するには、起動した端末で``Ctrl+C``を押してください。

サンプルの本文や見出しを書き換え、次の節の記法を必要に応じて加えてください。
共有用のHTMLを作る操作はxref:#slides-export[HTMLの生成と配布]、
PDFを保存する操作はxref:#slides-pdf[ブラウザーからのPDF保存]で説明します。

[#slides-authoring]
== 原稿の構成

=== 見出しとスライド

文書タイトルと``==``見出しが横方向のスライド、``===``見出しが直前の``==``スライドに属する縦方向のスライドになります。
``====``以降はスライド内の見出しです。``[%notitle]``をスライド見出しへ付けると表示だけを隠し、参照用IDを保持します。
見出しの自動IDは文書全体で重複を避けるため、ノート内に同名の見出しを追加すると変わる場合があります。
固定するIDは``[#method]``形式で指定してください。本文の参照リンクは、参照先のスライドと段階表示へ移動します。
非表示の見出し内に``[[id]]``や書誌アンカーを置くことには対応しません。``[#method%notitle]``で見出し自身へIDを付けてください。
先頭のノートだけの領域は最初の本文スライドのノートへ移し、空のスライドを作りません。
表示できる本文や見出しがない原稿はエラーにします。

=== 定義リスト

項目名と説明を組にして示す場合は、定義リストを使います。
例えば、目的と学習データを整理するスライドは次のように書けます。

[source,asciidoc]
----
== 生成したいデータ

目的:: 手元にあるデータと同じ分布に従って、新しいデータをサンプリングしたい
学習データ:: データ分布として例えば画像データ（+画像のラベル情報等）
----

既定のテーマでは項目名を強調し、説明をその次の行に1字分（``1em``）下げて配置します。

=== 段階表示と2列配置

通常の順序なし・順序付きリストへ``[%step]``を付けると、直下の項目を順番に表示します。
``--``で囲んだ本文のまとまりをopenブロックと呼びます。通常のopenブロックへ付けると、その全体を一度に表示します。
子リストへの個別指定、stepの入れ子、
本文の一部分だけの段階表示、追加の効果および表示順の数値指定は診断します。
``[.columns]``をスライド見出しへ付け、その直下へ``[.column]``を付けたopenブロックを2つ置くと、等幅の2列になります。

次の例では、左列の項目を順番に表示し、右列に説明を置きます。

[source,asciidoc]
----
[#method.columns]
== 方法

[.column]
--
[%step]
* 観測値の取得
* 結果の推定
--

[.column]
--
ここに図や説明を置きます。
--
----

=== 発表者ノート

``[.notes]``を付けた通常のopenブロックは発表者ノートです。``convert``の既定である``public``出力では、ノートとノート専用の図を除外します。
``presenter``出力はノートを保持し、``S``キーで発表者画面を開きます。通常のHTML変換では``notes`` roleの本文を保持します。
共有用には``public``のスライド出力を使います。本文からノート専用IDへの参照は診断し、保存しません。
``[NOTE.notes]``、``[NOTE.speaker]``、``[NOTE.aside]``と、``speaker``・``aside`` roleはエラーにします。
発表者ノートには``[.notes]``を付けた通常のopenブロックを使ってください。

[source,asciidoc]
----
[.notes]
--
このスライドでは、観測条件を補足して説明します。
--
----

=== 脚注と図

脚注は``footnote:condition[観測条件の補足]``で定義し、同じ名前の``footnote:condition[]``で再び参照できます。
脚注は各スライドの末尾に置き、本文とノートの番号を分けます。ノートの追加によって本文の図表や脚注の番号は変わりません。

本文とノートの脚注定義は独立しています。ノートで本文の脚注を再利用する場合も生成を止めるため、
ノート用の脚注は別の名前で定義してください。
脚注本文内のアンカーと書誌定義には対応しません。脚注の外で定義し、脚注から参照してください。

図は、許可されたローカルディレクトリから取得したPNG、JPEG、GIF、WebPおよびSVGに対応します。
例えば、原稿と同じディレクトリへ``figure.png``を置き、次のように記述してください。

[source,asciidoc]
----
.条件ごとの比較結果
image::figure.png[条件ごとの比較結果]
----

ノートを除外した後に、表示する図だけを読み込みます。図の生成ファイル名は内容から計算した値で決まり、原稿のファイル名を含めません。
SVGは図形、文字、ローカルIDへの参照および限定したCSSを検証して保存します。DOCTYPE、script、イベント属性、
foreignObject、外部参照およびCSSによる外部資産の取得には対応しません。

=== スライドの縦横比

スライドの縦横比は、原稿の文書ヘッダで``slides-aspect-ratio``を指定して選べます。
省略、``auto``、属性の解除では、ページを最初に開いた画面の幅と高さから比率を取得します。
画面寸法はCSS上のピクセル数で取得し、例えば1920×1200の画面では16:10になります。
画面寸法を取得できない場合や、比率が対応範囲外の場合は16:9を使います。
ウィンドウの大きさを変えても比率を保持し、表示の大きさだけを調整します。
発表者画面の現在・次のスライドには、発表元の画面で決めた寸法を使います。
本文中の``slides-aspect-ratio``指定はエラーにします。文書ヘッダへ移してください。

画面に関係なく比率を固定するには、次のように文書ヘッダへ指定してください。

[source,asciidoc]
----
= 研究発表
:slides-aspect-ratio: 16:9
----

``WIDTH:HEIGHT``の両方に正整数を指定します。幅を高さで割った比率は1:4から4:1までに限ります。
画面から自動で取得する比率にも同じ範囲を適用します。
``16:9``は横長の標準的なスライド、``16:10``は1920×1200などの画面に合う比率です。
指定した比率は画面から取得した比率より優先し、通常表示とPDF保存で共通に使います。
配布する資料には比率を明示すると、閲覧する画面が変わっても同じ寸法で表示できます。
既定テーマの代表的な比率は16:9、16:10、4:3です。指定できる比率でも、原稿の内容量によっては
スライドからはみ出すため、配布前に使用する比率で表示を確認してください。

[#slides-math-citations]
== 数式と引用

LaTeX数式と、CSLという書誌情報の書式指定を使う引用には、スライド用補助プログラムが必要です。
導入と選択方法はxref:release-installation.adoc#slides-helper-installation[補助パッケージの導入]を参照してください。
補助を明示する場合は、以下のコマンドへ``--slides-helper FILE``を追加します。
数式やCSLで整形する引用が表示対象にない場合は、補助プログラムを起動しません。
``public``で除外したノートだけにある数式や引用のために、入力ファイルや補助プログラムを読み込むこともありません。

=== LaTeX数式

文書ヘッダで``:stem: latexmath``を指定し、本文に数式を記述します。
元のサンプルを残す場合は、次の内容を``math.adoc``へ保存してください。
式に付けた``mean``という名前を``\eqref``で参照します。

[source,asciidoc]
----
= 数式と引用
:lang: ja
:slides-aspect-ratio: 16:9
:stem: latexmath
:eqnums:

== 平均値の定義

観測値を latexmath:[x_1,\ldots,x_n] とし、平均値を次の式で定義します。

[stem]
++++
\begin{equation}
\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i
\label{mean}
\end{equation}
++++

式 latexmath:[\eqref{mean}] では、 latexmath:[n] は観測値の個数です。
----

補助を導入済みなら、次のコマンドで数式を確認できます。

[source,console]
----
adocweave preview math.adoc --to revealjs --css theme.css
----

LaTeX数式は静的SVGに変換し、原TeXも保持します。原TeXは表示せず、数式の``aria-label``にも設定します。
数式の自然言語による読み上げは保証しません。AsciiMathには対応しません。
``:stem: latexmath``と``:eqnums:``を使うと、``stem``記法にLaTeXを選び、AMS環境の式番号を有効にできます。
数式ブロックの``[stem,latexmath]``もLaTeXを選びます。文書タイトルの``stem:[]``は後続のヘッダ属性を参照しないため、
タイトルでは``latexmath:[]``を使うか、原稿の外から初期``stem``属性を指定してください。
独自のLaTeXマクロは``--math-macros FILE``へJSON配列で渡します。
各要素の``name``と``definition``は必須で、引数を使う場合は``arguments``、既定の引数は``default``で指定します。
本文とノートはそれぞれ別に処理し、その間のLaTeX参照の解決は保証しません。

[#slides-math-extensions]
=== 数式の色と追加記法

数式へ色、取消線、追加の数学記号を使う場合は、プロジェクト設定で必要な拡張を選びます。
次の内容を``math-extensions.toml``へ保存してください。

[source,toml]
----
schema-version = 2

[math]
extensions = ["color", "cancel", "mathtools"]
----

[cols="1,3",options="header"]
|===
|拡張 |用途と記法の例
|``color`` |文字色や背景色の指定。``\textcolor``、``\colorbox``、``\fcolorbox``
|``cancel`` |数式の取消線。``\cancel``、``\cancelto``
|``mathtools`` |追加の数学記号や配置。定義を表す``\coloneqq``など
|===

例えば、``math.adoc``へ次の数式ブロックを加えます。

[source,asciidoc]
----
[latexmath]
++++
\colorbox{pink}{$x+y$} \qquad \cancelto{0}{x} \qquad x \coloneqq y
++++
----

設定ファイルを指定して、プレビューを起動します。

[source,console]
----
adocweave preview math.adoc --to revealjs --config math-extensions.toml --css theme.css
----

原稿と同じディレクトリの``.adocweave.toml``へ設定を追加した場合は、``--config``を省略できます。
設定の探索範囲はxref:project-configuration.adoc#configuration-selection[設定ファイルの選択]を参照してください。
スライドのプレビュー中に設定を変更すると、数式も生成し直します。
リポジトリには、link:../../fixtures/slides-browser/math-extensions.adoc[拡張を使う原稿]と
link:../../fixtures/slides-browser/math-extensions.toml[対応する設定]もあります。これらを試す場合も、設定は``--config``で指定します。

``math.extensions``の省略または空配列は、追加拡張なしを表します。
指定できるのは上の3つだけで、重複や未知の名前はエラーにします。
基本の数式、式番号と参照、マクロに必要な``base``、``ams``、``newcommand``、``configmacros``は常に有効です。
これらの内部名は設定へ書かず、追加拡張だけを指定してください。
指定順に関係なく``color``、``cancel``、``mathtools``の順で有効にします。
``\require``などによる任意の拡張の読込みや、外部からの追加取得には対応しません。

数式SVGの色には、CSS標準の148色名、``#``に続く3・4・6・8桁の16進数、
``transparent``、``currentColor``、``none``を使えます。色名の大文字と小文字は区別しません。
TeXの``\definecolor``で指定する``rgb``、``RGB``、``gray``は、MathJaxが16進数の色へ変換します。
任意のCSS関数や``url()``による外部参照を、色として指定することはできません。

=== 文献データを使う引用

引用には、原稿中のキーと対応する文献データが必要です。
次の内容を``references.json``へ保存してください。これは入力形式を説明するための架空の資料です。

[source,json]
----
[
  {
    "id": "example-report",
    "type": "report",
    "title": "説明用の架空資料",
    "author": [{"literal": "例示研究班"}],
    "issued": {"date-parts": [[2026]]}
  }
]
----

``math.adoc``の末尾へ次のスライドを加えます。
``example-report``は文献データの``id``と一致させます。``locator=3,label=page``は3ページを参照する指定です。

[source,asciidoc]
----
== 文献の参照

引用記法は cite:[example-report,locator=3,label=page] のように記述します。

この文献データは入力形式を示すための架空の資料です。
----

文献データを指定してプレビューを起動します。

[source,console]
----
adocweave preview math.adoc --to revealjs --bibliography references.json --css theme.css
----

``--bibliography``にはCSL JSONの配列を指定します。既定のCSLスタイルとロケールは実行ファイルに内包しているため、
文献データだけで引用と参考文献を生成できます。引用は出現順の``[1]``、``[2]``形式で、ページなどの位置を指定した
場合はその値も表示します。参考文献は番号順に並び、データにある著者、表題、年、掲載誌などを表示します。
既定のロケールは英語（``en-US``）です。原稿や文献の日本語を翻訳するものではなく、ページの略記などに使う語を定めます。
生成する参考文献の見出しは``References``で固定し、CSLロケールでは変更しません。

書式を変更する場合は``--csl-style style.csl``、語や日付の表記を変更する場合は``--csl-locale locale.xml``を追加してください。
それぞれ個別に指定でき、省略した側には組込みの値を使います。明示したファイルの取得や解析に失敗した場合は、
既定値へ戻さずエラーを表示します。実行時にCSLスタイルやロケールをダウンロードすることはありません。

CSLで整形する引用が表示対象にある場合にだけ、文献データと明示したCSLファイルを読み込みます。
3つの指定をすべて省略すると、表示する引用の全キーが手書きの書誌定義へ解決する場合に限り、補助プログラムなしで描画します。
いずれかを指定した場合は全引用をCSLで処理し、``--bibliography``を必要とします。
CSLの入力を指定した場合、表示対象に手書きの書誌定義があると生成を止めます。
引用キーが異なる場合や、その書誌定義を引用していない場合も、二つの方式を併用できません。
生成した参考文献は本文の最後に1枚だけ追加します。長い参考文献を自動で縮小・分割しません。
収まらない場合は、掲載する文献やCSLの書式を調整してください。
発表者ノートの参考文献は、最後の原稿スライドのノートへ1回だけ掲載します。
本文の引用は本文の手書き書誌、ノートの引用は本文とノートの手書き書誌を参照できます。
手書きの``[bibliography]``本文はそのまま描画します。
CSLの出力は文字列、強調、上付き・下付きなどの装飾とHTTP(S)リンクに対応します。
参考文献の段落、インデントと左右の列配置は空白で区切った本文へまとめます。
複数の文献を一つの項目にまとめる書式や、対応する装飾以外のHTMLは診断します。
任意のCSL書式について元の配置を再現する保証はありません。
引用処理を使ったスライドには、本文とは別の領域に処理ライブラリーの帰属を表示し、ライセンスを同梱します。

=== 脚注内の数式と引用

脚注本文の数式と引用は、本文・ノートそれぞれの処理範囲で、最初の脚注参照の位置へ原稿の順番で加え、一度だけ処理します。
同じ脚注を繰り返す場合は確定済みの内容を再利用し、配置先ごとに参照用IDを分けます。
本文の脚注・引用へ付ける生成IDは非公開ノートの量に依存せず、発表者出力でも同じ本文IDを使用します。
脚注の数式は``latexmath:[z=3]``のような番号なしの本文中の式に限ります。
脚注内の式番号や``\label``の定義は診断します。同じ処理範囲（本文またはノート）の脚注外で定義した
式番号を``\eqref``で参照できます。

=== 処理時間と取消し

補助の実行時間は30秒に制限し、CLIから変更できません。
制限を超えた場合は、式や引用の数を減らして再試行してください。
取消しや時間超過では補助とその子孫を停止します。Unixでは同じprocess group、Windowsでは起動前に所属させた
Job内が対象です。明示した補助がUnixで別のsessionやgroupへ離れる場合は、その子孫の停止を保証しません。

[#slides-css]
== CSSによるデザイン調整

CSSを指定しない場合は、実行ファイルに内包したテーマを使います。外部のCSSを取得する必要はありません。
既定のテーマは本文を左上に揃え、表紙のタイトルを大きく表示します。
脚注は本文と重ならないようにスライドの下側へ配置し、本文、数式、図表、参考文献で文字サイズと余白を分けます。
本文には端末にあるNoto Serif CJK JP、游明朝、ヒラギノ明朝などの明朝体を使います。
和文明朝フォントがない場合は端末の代替フォントを使うため、日本語が明朝体にならない場合があります。
必要に応じてNoto Serif CJK JPなどを端末へ導入してください。

色や文字の大きさを変える場合は、短いCSSファイルを作成して``--css``で読み込ませます。
CSSは、HTMLのどの要素へどの見た目を適用するかを指定するファイルです。
まずテーマのCSS変数を変更し、必要な箇所だけ個別の規則を追加してください。
リポジトリの``examples/slides/theme.css``をコピーして始められます。
編集するのは読み込ませるCSSファイルです。生成先のCSSを直接編集せず、プレビューの更新や再生成で反映してください。

[source,console]
----
adocweave convert talk.adoc --to revealjs --output dist/talk --css theme.css
adocweave preview talk.adoc --to revealjs --css theme.css
----

``--css``は複数回指定できます。プロジェクト設定の``html.stylesheet-files``でも読み込めます。
同梱の``theme.css``、``content.css``より後に利用者のCSSを適用します。
複数のCSSでは指定順に読み込むため、同じ対象へ同じ強さの規則を書いた場合は後の指定が優先します。
対象をどれだけ具体的に絞るかを表す「詳細度」や、規則を優先する``!important``によっては、
後から書くだけでは上書きできません。

=== 配色と文字

CSS変数は、色や文字サイズを複数の箇所で共有するための名前です。
``:root``へ指定すると、スライド全体で使えます。

[source,css]
----
:root {
  --adocweave-accent: #245c86;
  --adocweave-font-size: 28px;
  --adocweave-font-family: "Noto Serif CJK JP", "Yu Mincho", "Hiragino Mincho ProN", serif;
}
----

[cols="1,2",options="header"]
|===
|変数 |用途
|``--adocweave-background`` |ページ全体の背景色
|``--adocweave-foreground`` |本文と見出しの文字色
|``--adocweave-muted`` |脚注、図表の説明、ページ番号などの補助的な文字色
|``--adocweave-accent`` |リンク、見出しの線、箇条書きの記号などの強調色
|``--adocweave-surface`` |引用、コード、表の見出しなどの背景色
|``--adocweave-border`` |表、脚注、スライド下部などの区切り線の色
|``--adocweave-font-size`` |本文の基準サイズ。見出しや脚注の相対サイズにも影響
|``--adocweave-font-family`` |本文のフォントと、数式SVG内でserifを指定した文字のフォント
|===

フォント名は左から順に、閲覧する端末へ導入済みのものを使います。
HTMLを配布してもフォント自体は配布されません。最後に``serif``などの代替指定を置いてください。
フォントが変わると改行位置も変わるため、発表に使う端末で確認します。
色の変数だけで変更されない装飾もあります。例えば表の偶数行の背景色は個別の規則です。

=== 調整する箇所の指定

セレクターは、規則を適用するHTML要素を選ぶ指定です。
例えば``.reveal h2``はスライド内の``h2``見出しを選びます。
通常の本文スライドは、おおむね次の構造です。脚注は存在する場合だけ出力します。

[source,html]
----
<div class="reveal">
  <div class="slides">
    <section id="method">
      <div class="slide-body">
        <div class="slide-content">
          <h2>方法</h2>
          <p>本文</p>
        </div>
        <div class="footnotes">脚注の内容</div>
      </div>
    </section>
  </div>
</div>
----

``.slide-body``は本文と脚注をまとめ、``.slide-content``は見出しと本文を含みます。
縦方向のスライド群には、これらの``section``を囲む``section.stack``もあります。

[cols="1,2",options="header"]
|===
|セレクターの例 |対象
|``.reveal .title-slide`` |表紙のスライド
|``.reveal .slides section:not(.stack):not(.title-slide)`` |表紙と縦方向のグループ容器を除いた各スライド
|``.reveal .slide-content`` |見出しと本文の領域
|``.reveal h2`` |本文スライドなどのレベル2見出し
|``.reveal figure img`` |図の中の画像
|``.reveal figcaption, .reveal caption`` |図と表の説明
|``.reveal th, .reveal td`` |表の見出しセルと本文セル
|``.reveal dl`` |定義リスト全体
|``.reveal dt`` |定義リストの項目名
|``.reveal dd`` |定義リストの説明
|``.reveal .footnotes`` |脚注の領域
|``.reveal .columns`` |2列全体。列間の間隔などを指定する対象
|``.reveal .column`` |2列のうちの各列
|===

例えば、見出し、脚注、画像の大きさを次のように調整できます。
``em``はその箇所の文字サイズを基準にした単位で、``px``はCSS上のピクセルです。
スライド全体は画面に合わせて拡大・縮小されます。

[source,css]
----
.reveal h2 { font-size: 1.4em; }
.reveal .footnotes { font-size: .7em; }
.reveal figure img { max-height: 360px; }
----

特定のスライドだけ変える場合は、原稿の見出しへ``[#method]``のようなIDを付けます。
そのスライドの2列の間隔だけを変えるには、次のように指定します。

[source,css]
----
.reveal #method .columns { gap: 32px; }
----

既定の``.slide-body``では、子要素の並び方や空間の配分を決めるflex配置を使い、本文と脚注の重なりを防ぎます。
見た目の調整では、この配置方式や``.slide-content``の構造を保ってください。
同梱の``content.css``は数式と引用の表示、および発表者ノートで共有する規則を持ちます。
数式の元テキストを隠す``.math-source``や、数式SVGの幅を調整する規則を解除すると、
数式が二重に見えたり、番号付き数式がはみ出したりする原因になります。
数式全体の大きさは周囲の文字サイズも含めて確認してください。

発表者画面の現在・次のスライドには、スライド本体のCSSが反映されます。
一方、独立したノート欄へ渡すのは``content.css``です。
``--css``で変更した本文のフォントや装飾が、そのままノート欄へ反映されるわけではありません。

=== 画面とPDFの余白

通常のCSS規則は画面と印刷用表示の両方へ適用されます。
``?print-pdf``で開いたページには``html.reveal-print``が付き、PDF用のページ配置へ切り替わります。
``@media print``内の規則は、ブラウザーが実際の印刷を行うときに適用されます。
したがって、印刷用ページを画面で見ている段階と、PDFに保存する段階の両方を確認してください。

同梱テーマは印刷用のスライド余白を``!important``付きで指定します。
表紙の配置を保ち、本文スライドの余白を画面とPDFで揃える例は次のとおりです。

[source,css]
----
.reveal .slides section:not(.stack):not(.title-slide) {
  padding: 40px 56px 56px;
}
html.reveal-print .reveal .slides section:not(.stack):not(.title-slide) {
  padding: 40px 56px 56px !important;
}
----

``padding``の値は上、左右、下の余白です。ここでは印刷用の余白だけに``!important``を使います。
脚注や下部の装飾に必要な空間を残し、内容の多いスライドで重なりを確認してください。
表紙には専用の上余白があるため、同じ規則を一律に適用しません。
文字サイズや余白の変更後は、表紙、本文、図表、脚注、2列のスライドを確認します。
PDFでは内容が多いスライドが複数ページに続く場合があります。

=== CSSファイルと資産の制約

利用者のCSSはUTF-8のローカルファイルで指定します。
件数と容量の上限は、xref:command-line.adoc#html-css[通常HTMLのCSS]と共通です。
CSS内の``@import``や``url()``から、画像やフォントを探索・コピーすることはありません。
単一HTMLにもそれらの別ファイルは収集しません。
外部stylesheetのURL指定は受け付けません。
外部の画像やフォントの取得も、ページが読み込める資源を制限するCSPで制限します。
背景画像やWebフォントを別ファイルから読み込むテーマの表示は保証しません。
図は原稿の画像指定から取り込み、フォントは閲覧端末へ導入したものを指定してください。

既定の値や個別の規則は、同梱のlink:../../crates/adocweave/assets/slides/theme.css[``theme.css``]と
link:../../crates/adocweave/assets/slides/content.css[``content.css``]で確認できます。

[#slides-preview]
== スライドのプレビューと配信

編集中のスライドを表示するには、``preview``へ``--to revealjs``を指定します。
既定は``presenter``で、出力先ディレクトリの指定は不要です。共有用の表示確認には``--audience public``を使います。
数式・引用の入力とローカルCSSは``convert``と同じオプションで指定できます。

[source,console]
----
adocweave preview talk.adoc --to revealjs
adocweave preview talk.adoc --to revealjs --audience public --css theme.css
----

スライドのプレビューでは、スライド本体を配信したページで表示します。
原稿や、表示に使うinclude・図・CSS・数式と引用の入力ファイルを変更すると、表示を更新します。
生成に失敗した場合は診断を表示し、最後に成功したスライドと資産一式を保持します。
更新後は見出しIDと段階表示の位置をURLから復元します。表示中の段階を削除した場合は残った段階へ補正し、
表示中の見出しIDを削除した場合は先頭のスライドへ戻ります。

``serve``は保存済みのmanifest（生成ファイルの一覧と内容の記録）と登録ファイルの内容を検証してから配信します。
スライドの用途は生成物のメタデータから読み取ります。メタデータがない生成物は、原稿から生成し直してください。
原稿、補助プログラムおよび引用の入力ファイルは不要です。内容を更新する場合は``convert``で生成し直してください。
``serve``は起動時の生成物を配信し続けます。更新した生成物を配信するには``serve``を再起動してください。
``--bind``、``--port``および``--allow-external``の指定は通常のプレビューと共通です。
生成と配信のコマンドはxref:#slides-export[HTMLの生成と配布]で説明します。

== HTMLの生成と配布

=== ディレクトリ出力

AsciiDocの本文から、ローカルで開けるスライド一式を生成します。
既定のディレクトリ出力では、生成先の``index.html``をブラウザーで開くと、
同梱したreveal.jsとCSSで表示します。表示時に外部のJavaScriptやフォントを取得しません。
``public``出力をファイルとして開く動作は、固定したChromiumで検証しています。
発表者画面は、xref:#slides-preview[``preview``または``serve``によるローカルHTTP配信]を使ってください。
読み込める資源を制限するCSPは、ファイル表示ではHTMLの``meta``要素で指定します。
そのため、埋込み先のページを制限する``frame-ancestors``など、HTTPヘッダ専用の制限は適用されません。
ローカルHTTP配信ではヘッダでもCSPを指定します。

[source,console]
----
adocweave convert talk.adoc --to revealjs --output dist/talk --css theme.css
adocweave convert talk.adoc --to revealjs --output dist/talk-presenter --audience presenter --css theme.css
----

``dist/talk``はノートを除いた共有用、``dist/talk-presenter``はノートを含む発表者用です。
発表者画面を使う場合は、生成したディレクトリを次のコマンドで配信し、表示されたURLを開いてください。

[source,console]
----
adocweave serve dist/talk-presenter --port 8080
----

ディレクトリ出力では``--output``が必須です。``--complete``と``--css-url``は併用できません。
``--to revealjs``を指定しない通常の``convert``は、HTMLの本文部分を標準出力へ書き出します。

出力先は新規か空の専用ディレクトリ、またはAdocWeaveのmanifestと全ファイルの内容が一致するディレクトリに限ります。
``.``、ファイルシステムのルート、原稿・include元のディレクトリ、symlinkを含むパスは拒否します。
手書きのファイルや生成後に編集されたファイルを検出すると、その内容を保持して更新を中止します。
``presenter``から``public``へ更新すると、不要になったノート専用資産も削除します。保存や削除に失敗した場合は成功を返しません。
未知・欠落・変更済みのファイルやI/Oエラーによって更新できない場合は、元のディレクトリを保持し、
新規か空の出力先へ生成してください。失敗した出力先を自動で復旧する保証はありません。
例えば、移動先``dist/talk-retained``が存在しないことを確認してから、既存の出力を別名へ移して保持します。

[source,console]
----
mv dist/talk dist/talk-retained
adocweave convert talk.adoc --to revealjs --output dist/talk --css theme.css
----

``serve``はmanifestに登録されたファイルを検査して配信します。
``.DS_Store``など未登録のファイルは配信も削除もしません。登録済みファイルの欠落や改変はエラーにします。
生成物の更新では未登録ファイルも保護するため、``serve``が成功しても同じ出力先へ再生成できない場合があります。

=== 単一HTML

配布する資料を1つのHTMLにまとめるには、``--single-file``を指定します。
通常HTMLと同じく標準出力へ書き出すため、次のように保存してください。診断は標準エラー出力へ表示します。

[source,console]
----
adocweave convert talk.adoc --to revealjs --single-file --css theme.css > talk.html
----

``talk.html``だけを移動・配布し、ブラウザーで直接開けます。JavaScript、CSS、本文の画像と依存物の通知を
HTMLへ含め、表示に必要な別ファイルを読み込みません。数式SVGと引用も通常のスライド出力と同じ内容です。
利用する数式・引用に応じて、``--slides-helper``や``--bibliography``などを追加できます。
``--single-file``は``public``の出力に限り、発表者ノートとノート専用の資産を含めません。
``--output``および``--audience presenter``とは併用できません。``preview``と``serve``では指定できません。
埋込み後のHTMLは50 MiBまでです。画像のBase64化でサイズが増え、同じ画像を繰り返す場合はその分も増えます。
システムフォントは同梱しないため、使用する端末のフォントで表示します。
ライセンス全文は画面左上の``Licenses and notices``から確認できます。全文はPDFの印刷対象には含めません。

[#slides-pdf]
== ブラウザーからのPDF保存

ChromeまたはChromiumで、スライドのURLへ``?print-pdf``を付けて開きます。
PDF保存の自動検証には固定したChromiumを使います。Firefoxの印刷結果は保証しません。
保存済みの``public``出力の``index.html``を直接開く場合も、``serve``や``preview``で配信する場合も同じです。
``--single-file``で生成したHTMLも同じ方法で印刷できます。
例えば、``serve dist/talk --port 8080``で配信したスライドは``http://127.0.0.1:8080/?print-pdf``で開いてください。
URLに``#``以降のスライド位置がある場合は、``?print-pdf``を``#``より前へ置きます。

. 印刷用の表示を開き、数式や図が表示されるまで待ちます。
. ``Ctrl+P``で印刷画面を開き、ブラウザー内蔵の「PDFに保存」を送信先に設定します。macOSでは``Command+P``を使います。
. 余白をなくし、背景を印刷する設定を有効にします。レイアウトの指定が必要な場合は、選んだ縦横比に合わせます。
. ページの上下にURLや日時を印字する設定を無効にして、PDFを保存します。

PDFの用紙にはスライドと同じ縦横比を指定します。
OSのPDFプリンターや実際のプリンターを送信先にすると、そのプリンターの用紙設定が優先される場合があります。
ブラウザー内蔵のPDF保存を使って、印刷画面でページの比率を確認してください。

段階表示のあるスライドは、すべての段階を表示した最終状態を印刷し、段階ごとのページを追加しません。
既定では発表者ノートを印刷しません。
内容がスライドの高さを超えると、複数ページへ続きます。1スライド1ページの保証はありません。
長い本文を自動で縮めたり、1ページの高さで切り捨てたりしません。
印刷前に表示を確認し、収まらない本文はスライドを分けるか、ローカルCSSで文字サイズと余白を調整してください。
