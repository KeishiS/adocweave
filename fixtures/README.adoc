= Fixture

fixtureは担当機能ごとに分類する。各機能ディレクトリには次のファイルを配置できる。

- `*.adoc`: ソース文書
- `*.html`: 期待するHTML断片
- `*.diagnostics.json`: 期待する診断
- `*.formatted.adoc`: 期待するFormatter出力

各fixtureは一つの動作へ集中させる。内容を表す名前を使い、正常、不正、不完全、上限・下限付近の値の
入力を別ファイルとして追加する。

`release/core.adoc`は機能横断のコアリリースfixtureである。期待HTMLを同じディレクトリへ
置き、CLI、Lint、Formatterのテストで同じソースを使う。

runtime横断fixtureのmanifestは、``adocweave-core`` crateが所有するruntime間の公開仕様として
`../crates/adocweave-core/conformance/cases.json`に置きます。readerはこの固定pathを直接読み、
`sourceFile`と各`expected*File`をfixture rootである`fixtures/conformance/`を基準に解決します。
readerのpathを再掲する台帳は置きません。

各caseには互換性分類、差分理由および仕様versionへの影響判断を記録します。native、WASMおよびLSPは
このmanifestまたは参照先の同じソースを使用し、別内容の複製fixtureを作りません。個別のfixtureは、
他のcaseの入力や期待出力へ依存せず、そのfixtureだけで一つの動作を検証できる内容にします。

利用側へ公開するcaseは、同じmanifestの任意項目`publicContract`で選択します。`publicContract`は、
利用側が依存できる投影のJSON pointer、HTML断片および診断codeを意味上のassertionとして記録します。
公開caseの入力AsciiDocもmanifestへ直接記録し、比較用file全体のbyte列と実装詳細はリポジトリ内の回帰検査に
限定します。Manifest内の公開caseは、リポジトリのrootのlink:../LICENSE-MIT[MIT License]または
link:../LICENSE-APACHE[Apache License 2.0]の条件で再利用できます。

manifestの`schemaVersion`は形式の非互換変更、`outputContractVersion`は`publicContract`の非互換変更で
更新します。公開仕様を変更するときは、manifest内の入力と`publicContract`およびRelease Notesを同じ変更で
更新します。
公開仕様に含まれない空白、属性順または未選択の投影fieldだけを変更する場合は`outputContractVersion`を
更新しません。

`syntax-support.json`は、対応表、互換性評価、文法および対応するfixtureの同期を検査するための
manifestである。人向けの仕様は`docs/`に記載し、このファイルへ説明文を重複させない。

`html/validation.json`はHTML5標準適合性検査の対象、固定validator設定およびnegative fixtureを管理します。
断片出力は`html/validation-template.html`の一意なmarkerへ挿入し、完全HTML文書として検査します。
検査時に生成する文書は`target/html5/`へ出力し、fixtureディレクトリへ書き戻しません。
